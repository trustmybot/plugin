# Benchmark Measurement Harness

Tools for measuring token burn, cache health, Claude Code subagent behaviour, and Codex Agent materialization latency.

**Dependencies:** the legacy transcript tools use `bash` and `python3` (stdlib only); the Codex materialization harness uses Node.js 22 or newer. `jq` is not required. `selftest.sh` runs each available toolchain independently and prints a warning for a missing optional runtime.

## Tools

### replay-session.sh

Parse a raw CC session JSONL file and emit per-turn metrics.

```
bash tests/benchmarks/replay-session.sh <session.jsonl> [--jsonl | --table]
```

**Output fields per turn:**

| Field | Description |
|---|---|
| `turn_index` | 1-based assistant-turn counter |
| `timestamp` | ISO-8601 timestamp of the assistant message |
| `input_tokens` | Tokens charged to the input budget this turn |
| `output_tokens` | Tokens generated by the model this turn |
| `cache_read_tokens` | Tokens served from cache (`cache_read_input_tokens`) |
| `cache_creation_tokens` | Tokens written to cache (`cache_creation_input_tokens`) |
| `hook_injected_bytes` | Total bytes of `<system-reminder>` text blocks in the preceding user message (proxy for UserPromptSubmit hook injection size) |
| `tool_calls` | Array of tool names called in this assistant turn |

Default output is JSONL (one object per turn). Pass `--table` for a human-readable ASCII table.

### tokens-per-turn.sh

Compute aggregate token statistics over a replay-session output.

```
bash tests/benchmarks/replay-session.sh session.jsonl > replay.jsonl
bash tests/benchmarks/tokens-per-turn.sh replay.jsonl
```

Output: `avg=N p50=N p95=N (over M turns)`

Tokens counted: `input_tokens + output_tokens` per turn. Cache tokens are excluded — they represent context re-read, not new model computation, so they belong in a separate cache-hit analysis.

### cache-stability.sh

Compare two replay-session outputs of the same session run at different times to assess cache prefix stability.

```
bash tests/benchmarks/cache-stability.sh replay-run1.jsonl replay-run2.jsonl
```

**Output columns:**

| Column | Description |
|---|---|
| `CACHE_RD_A` / `CACHE_RD_B` | Cache-read tokens in each run |
| `SHARED_PFX` | `min(cache_read_A, cache_read_B)` — lower bound on tokens served from a stable prefix |
| `DRIFT` | `abs(cache_creation_A - cache_creation_B)` — how many tokens were re-written to cache (breakpoint drift) |

A healthy, stable session has high `SHARED_PFX` and low `DRIFT`. High `DRIFT` signals that hook injections or system-reminder content changed between runs, breaking the cache prefix.

### spawn-reads.sh

Count subagent spawns (TaskCreate tool calls) and Read tool calls in a raw session JSONL, and compute mean reads per spawn.

```
bash tests/benchmarks/spawn-reads.sh session.jsonl
```

Output: `spawns=N reads=M mean_reads_per_spawn=X.XX`

High reads-per-spawn is a signal that subagents are doing expensive cold-start file exploration rather than relying on the world model.

### codex-agent-materialization.mjs

Measure `agent_materialization_get` against a copied installed plugin artifact and three disposable Git projects: `absent`, `current`, and `conflict`.

```bash
node tests/benchmarks/codex-agent-materialization.mjs \
  --installed-plugin-root /absolute/path/to/fixed-sha-installed-artifact \
  --output-dir /absolute/path/to/new-evidence-directory
```

The copied artifact must contain `.tmb-artifact-provenance.json` with exactly one `source_sha` field containing the 40-character lowercase commit SHA used to build it. The harness records that value as `plugin_sha`, records its own checkout separately as `harness_source_sha`, and hashes the complete artifact including the provenance file.

The harness starts one fresh MCP process per state, takes one cold sample, discards 10 warm-up calls, and records 100 warm samples. It verifies every response matches the intended state, then writes one JSONL sample file and one JSON summary. The summary uses nearest-rank p50 and p95 values and reports `pass` when every warm p95 is at or below 100 ms. A slower result reports `investigate` but still exits zero so machine-specific latency remains an advisory signal; protocol, fixture, or output failures exit non-zero.

The output directory must not exist and its canonical parent must be outside the installed artifact; symlinked-parent escapes are rejected. Benchmark Git commands discard inherited `GIT_*` overrides, disable hooks and fsmonitor, and ignore global/system Git configuration. The harness leaves the disposable projects and evidence in place for inspection.

## Session JSONL Format

CC session files live at `~/.claude/projects/<project-slug>/<session-id>.jsonl`. Each line is a JSON object. Relevant event types for these tools:

**`system`** — session metadata, informational messages. Fields: `uuid`, `timestamp`, `sessionId`.

**`user`** — a human or tool-result turn. Fields: `uuid`, `parentUuid`, `timestamp`, `message.role`, `message.content[]`. Content items are either `{type:"text", text:"..."}` or `{type:"tool_result", tool_use_id:"...", content:[...]}`. Hook-injected context from UserPromptSubmit hooks appears as `type:"text"` items containing `<system-reminder>...</system-reminder>` blocks.

**`assistant`** — a model response. Fields: `uuid`, `parentUuid`, `timestamp`, `message.role`, `message.content[]`, `message.usage`. Usage shape:
```json
{
  "input_tokens": 210,
  "output_tokens": 62,
  "cache_read_input_tokens": 5015,
  "cache_creation_input_tokens": 0,
  "cache_creation": {
    "ephemeral_1h_input_tokens": 0,
    "ephemeral_5m_input_tokens": 0
  }
}
```
Content items with `type:"tool_use"` carry `name` (the tool called) and `id`.

**`queue-operation`** — task notifications (subagent completion). Not used by these tools directly.

Other types (`last-prompt`, `permission-mode`, `file-history-snapshot`, `ai-title`, `attachment`) are structural metadata; the measurement tools skip them.

## Fixtures

`fixtures/sessions/` contains two synthesized minimal fixtures. They are hand-built with shape-accurate field names from the actual CC transcript format — no real user content.

| Fixture | Description |
|---|---|
| `bro-5turn.jsonl` | 5-turn bro session: task_list, task_brief, task_update_status calls with realistic usage fields and hook-injected system-reminders |
| `bro-with-spawn.jsonl` | Session with two TaskCreate subagent spawns (swe + pr-reviewer) |

## Acceptance Criteria (token-burn issues)

A token-burn issue is considered resolved when:

1. `replay-session.sh` on a representative session shows `cache_read_tokens` increasing monotonically across turns (cache prefix is stable).
2. `tokens-per-turn.sh` p95 falls within the target bound for the session type (set per issue).
3. `cache-stability.sh` between two identical runs shows `DRIFT < 500` tokens per turn (hook injection is deterministic and not re-creating the cache prefix).
4. `spawn-reads.sh` shows `mean_reads_per_spawn <= 3` for a mature bro session (subagents lean on world model, not cold-start reads).

# All benchmark selftests (fast, deterministic — no live services)
