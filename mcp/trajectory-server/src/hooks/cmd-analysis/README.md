# src/hooks/cmd-analysis

The TypeScript write-path analyzer (GH 1692): `tmb_cmd_write_paths` of `scripts/hooks/lib/cmd-analysis.sh` rebuilt on a tree-sitter-bash parse. Given a Bash command, it lists every path the command may write. Where it cannot name a path it prints an `UNRESOLVED:` line, so a gate can deny rather than allow. `cmd-analysis.sh` is frozen: the TS matches it line for line, except on the recorded cases where it is stricter.

## API

`index.ts` is the only entry point.

| Export | What it does |
|---|---|
| `writePaths(command, { cwd, raw, root, env })` | Resolves to the lines `tmb_cmd_write_paths "$command" "$cwd" [raw] "$root"` prints: absolute paths, `UNRESOLVED:<reason>:<text>` lines and, with `raw`, paths as written. `root` is the run root that a lister-bound loop variable or find / fd placeholder must stay under. `env` supplies `HOME`, `TMPDIR`, `CLAUDE_PROJECT_DIR` and `TMB_MODEL_CACHE_DIR` / `HF_HOME` (default `process.env`). A blank command resolves to `[]` without loading a parser. |
| `pathCanonical(path)` | `tmb_path_canonical`: follows symlinks in the existing prefix (at most 40 hops) and keeps the missing tail. A relative path comes back unchanged. |
| `payloadCwd(json, env)` | `tmb_payload_cwd`: the hook payload's `.cwd` when it is a non-empty string, else `env.PWD`. |
| `ANALYSIS_WORK_CAP` | The work units an analysis may spend: characters read, scanned, printed or held in tracked variables, and syntax nodes walked. |
| `isCapLine(line)` | Whether a `writePaths` line is the cap line (see `$(computed)` below). |
| `CAP_REASON` | The deny text of a gate that acts on the cap line itself: no-source-edit-from-main and swe-boundary. |
| `bashParserLoads()` | How many times this process has loaded the bash grammar: 0 after import, 1 after any number of commands. |
| `programParserLoads(name)` | The same count for a program grammar, `'python'` or `'javascript'`: 0 until the first program in that language, then 1. |
| `cmdStatements(command, cwd, env)` | `tmb_cmd_statements`: resolves to `{ ok: true, statements }`, one `Statement` `{ dir, stmt }` per executable statement, `bash -c` / `eval` bodies included (to depth 3). A `dir` of `@` becomes `cwdState(cwd)` and `@/x` becomes `<cwd>/x`; encoded bytes show as `_`. When the command or a body in it does not parse, it resolves to `{ ok: false }` (the `GitStatements` type), never a partial list. |
| `cwdState(cwd, env)` | `tmb_cwd_state`: resolves to `-` when `cwd` is no dir, `?` when it is a checkout with linked worktrees, else `cwd`. |
| `gitSubcommand(stmt)` | `tmb_git_subcommand`: the words from git's subcommand on, past `-C` / `-c` / `--git-dir` / `--work-tree` / `--namespace` and their values; `""` when `stmt` is no git command. |
| `stmtRepoRoot(dir, cwd, env)` | `tmb_stmt_repo_root`: resolves to the main checkout of the repo a statement's dir is in, `""` when none. |
| `denyAmbiguousGitTarget(stmt, unresolved)` | `tmb_deny_ambiguous_git_target`: the PreToolUse deny JSON line, with both of the .sh's messages verbatim (no directory named, or one the guard cannot resolve). |
| `ghMutation(stmt)` | `tmb_gh_mutation`: the forge write one statement makes, `<group> <action>` for a `gh` / `glab` write subcommand or `POST` / `PATCH` / `PUT` / `DELETE` for a writing `gh api`, including one a `git rebase --exec`, `bisect run` or `submodule foreach` runs; `""` for none or for a reader command (`echo`, `grep`, `cat`, …). |
| `ghMutationFrom(words)` | `tmb_gh_mutation_from`: the same verdict for the words of one `gh` / `glab` call, the tool word first. The `gh api` verb is upper-cased with `toUpperCase`, so a non-ASCII spelling (`poſt`) reads as `POST` in every locale; that is TS-only. |
| `isPromptSurfacePath(path, root, env)` | `tmb_is_prompt_surface_path`: resolves to true for a `CLAUDE.md` / `CODEX.md` / `CURSOR.md` / `GEMINI.md` anywhere, or a `.md` under `agents/`, `skills/`, `commands/`, `templates/` or `rules/` (or `.claude/agents|skills|commands|rules/`) of `root`, the path's own `surfaceRoot` when `root` is `""`. |
| `surfaceRoot(abs, env)` | `_tmb_surface_root`: resolves to the enclosing `.claude/worktrees/<name>`, else the main git root of the nearest existing ancestor. |
| `WRITE_SHAPES` | The write shapes the Bash rules judge, in the .sh's order. |
| `writeShapes()` | `tmb_cmd_write_shapes`: `WRITE_SHAPES` comma-joined, as quoted in swe-boundary's deny message. |
| `stripLiterals(command)` | `tmb_cmd_strip_literals` in its plain mode: the text it prints, trailing newline included. Heredoc bodies and comments are dropped, quotes removed, a quoted blank or operator shows as `_`, a substitution inside double quotes stays `$(...)`, and a line that ends inside a quote joins the next with `_`. git-guards matches a switch-then-merge needle against it. |

## Module map

| File | Role |
|---|---|
| `index.ts` | The public API above. |
| `parser.ts` | Loads the bash grammar, and the python and javascript grammars for inline programs, lazily, once per process (see Cold start). |
| `encode.ts` | The `keep` skeleton of `tmb_cmd_strip_literals`: heredoc bodies and comments dropped, quotes removed, quoted blanks and operators turned into reversible control bytes; `decode` maps them back. A quoted `(` / `)` inside a substitution gets its own bytes (`SUB_PO` / `SUB_PC`), so a held-program check is not fooled by `"$(cat ')')"`. A substitution's frame starts at its real `$(` or backtick, not at the blanks tree-sitter-bash folds into the opener after a preceding expansion (`"$(cat a) $(cat b)"`). Each heredoc gets bash's delimiter, its start word with quotes and backslashes removed; `encode` is not ok when the `heredoc_end` is not exactly that delimiter, or when a body line before it already is one (leading tabs stripped for `<<-`), so a heredoc tree-sitter-bash reads past its end never drops the statements after it (GH 1927). |
| `git.ts` | `cmdStatements`, `cwdState`, `gitSubcommand`, `stmtRepoRoot` and `denyAmbiguousGitTarget`: the git-target helpers of `cmd-analysis.sh` that git-push-guard and git-guards use, on the `encode.ts` skeleton and `statements.ts`. |
| `commit-message.ts` | `gitCommitMessage`: `tmb_git_commit_message` of `cmd-analysis.sh`, the first `git commit` statement of a command's skeleton and the message its argv carries, which commit-msg-lint uses. |
| `forge.ts` | `ghMutation` and `ghMutationFrom`: the forge-write classifier of `cmd-analysis.sh` (`tmb_gh_mutation`, `_tmb_gh_mutation_in`, `tmb_gh_mutation_from`) that swe-boundary uses, over the words of a `cmdStatements` statement. |
| `surface.ts` | `isPromptSurfacePath`, `surfaceRoot`, `WRITE_SHAPES` and `writeShapes`: the prompt-surface predicate and write-shape list of `cmd-analysis.sh` that swe-boundary uses. |
| `harness-turn.ts` | `isHarnessTurn`: `tmb_is_harness_turn` of `cmd-analysis.sh`, whether a UserPromptSubmit prompt came from the harness (a task or system notification, a subagent hand-back, an agent or cross-session message) rather than the Human. |
| `strip-literals.ts` | `stripLiterals`: the plain-mode awk scanner of `tmb_cmd_strip_literals`, ported state for state with no parser. |
| `statements.ts` | `_tmb_cmd_statements_enc`: one record per executable statement, with its effective dir (cd / pushd / popd / git -C / subshells), assignments and loop sources. In `assign` mode a loop's records sit between a `{` (`LOOP_OPEN`) and a `}` (`LOOP_CLOSE`) record: from the `while` / `until` keyword, since the condition runs on every pass, or from the `do` or `{` that ends a `for` / `select` header (also after `coproc`, and inside the header's own statement when that word comes right after NAME, as in `for i do …; done`), to the `done` or `}` that closes it (GH 1944). The frames must balance: a `do` no header waits for, a `done` or `}` that does not close the innermost frame, or a frame still open at the end appends a last `!` (`UNBALANCED`) record. A quoted or escaped word (`"done"`, `\done`, `d''one`, `$'done'`, `"}"`) is never one of these reserved words (POSIX 2.4): `encode.ts` puts a `QM` (`\x17`) mark before each opening quote and unquoted backslash, and `statements.ts` notes which words hold one, then drops the marks; a literal `\x17` in the command encodes as `$()`. A loop body's `cd` / `pushd` / `popd` crosses the back-edge (GH 1977): a dir token may list, each after an `ALT` (`\x13`), the other dirs the loop can bring its statement to; the frames are re-encoded until the dirs each one ends a pass in stop growing, and after a frame's `}` the dir is its entry dirs plus those. A frame still growing after `MAX_GROWTH` runs, or a frame edge that would leave more than `MAX_DIRS` dirs, leaves the dir `-` alone, so a `cd` that keeps drifting fails closed in bounded time. |
| `unwrap.ts` | Skips `VAR=value` words and the wrappers `sudo`, `env`, `command`, `nohup`, `time`, `exec`, plus `timeout` (and its duration), `stdbuf` and `nice` and their Homebrew coreutils names `gtimeout`, `gstdbuf` and `gnice`, each with its own options. These last six are TS-only. `command` with an option word holding `v` or `V` (`-v`, `-V`, `-pv`) before any `--` or operand is a lookup that runs nothing: the TS stops at that option word instead of skipping to the looked-up name, so `command -v bash` is not judged as `bash` reading stdin, while its own redirects still are (GH 1872). |
| `targets.ts` | The paths one statement writes as written: redirects, `tee`, `cp` / `mv` / `rm` / `touch` / `sed -i` and the rest, the sources `mv` removes, and the git tree commands. |
| `programs.ts` | Interpreter programs (`python -c`, `node -e`, `perl -e`, `ruby -e`, heredocs, here-strings, stdin programs): their write-call targets, held programs and the `$(computed)` and `$(unproven)` fail-closed markers. |
| `prove.ts` | The allowlist (GH 1739): a program is proven only when every call in it is a write `prog-calls.ts` judges or sits in a closed safe set. Python and node programs are walked on a tree-sitter parse; perl and ruby one-liners are lexed against an identifier allowlist; perl's `select` is allowed only as the 4-argument sleep `select(undef,undef,undef,<number or $scalar>)` (GH 1887). |
| `prog-calls.ts` | The `_tmb_cmd_prog_calls` awk scanner ported state for state; emits the `W` / `T` / `F` / `S` / `R` / `U` / `H` / `C` / `Q` / `A` lines `programs.ts` reads. A python or node write target that is one bare name, a python `write_text` / `write_bytes` receiver that is one bare name, or a `sys.argv[<n>]` / `process.argv[<n>]` target prints `F<TAB><name>` where the awk prints `F`. |
| `lister.ts` | The path-listing model: binds a loop variable or a find / fd placeholder to what its lister may list when that stays inside the run root. |
| `path.ts` | `pathCanonical` and `payloadCwd`. |
| `write-paths.ts` | `tmb_cmd_write_paths` itself: walks the statements, expands variables, recurses into `bash -c` / `eval` / `watch` bodies and sh programs on stdin (to depth 3), judges what find / fd / xargs run, and prints the lines. A `bash -c` statement's own redirects and write commands (`bash -c 'ls' > /etc/out`) are judged before its body; that is TS-only. `node --test` / `--run` / `--watch` and `python3 -m<module>` are not stdin programs. `eval` (or `builtin eval`) with a non-literal argument and a statement whose command word is an expansion (`$CMD`) print `$(unproven)`; that is TS-only. At a loop's `{` record it first applies the loop body's variable effects (assignments, `read` / `printf -v` / declaration builtins) over and over until the values stop changing, so an assignment later in the body reaches a use earlier in it on the next pass; a name still gaining values after 8 passes is unresolved. Variable values are a union in first-seen order, printed once each. A level with an `UNBALANCED` record, and every level it runs, resolves no variable at all: each use prints `UNRESOLVED:`, so a loop shape the tracker misreads fails closed instead of resolving from the wrong frame. `cmd-analysis.sh` follows the same loop-body and balance rules (GH 1944). |

## UNRESOLVED reasons

Every line that is not a path is `UNRESOLVED:<reason>:<text>`. Any of them means "this command writes somewhere the analyzer cannot name".

| Reason | Meaning |
|---|---|
| `$(parse)` | tree-sitter-bash could not parse the command, or misread a heredoc so that its end is not the line bash ends it at, as with `cat <<E"M"` or a body line of `$` (GH 1927). The `<text>` is the first 80 characters of the command and it is the only line printed, so a parse error never yields a partial list. A process call's shell command that does not parse prints the line beside the program's other lines; it keeps its reason (TS-only), where the .sh strips the prefix and judges the text as a path. |
| `$(computed)` | TS-only. The command writes, but the target is computed where neither analyzer can see it: a program piped or redirected into an interpreter (an info option such as `--version` exempts it only among the interpreter's own options, so `python3 - --version` still fails closed; `perl -c` runs `BEGIN` blocks and is not one, `ruby -c` is), a program held in a variable or in substitutions nested to any depth (`"$(cat $(echo x))"`, a quoted paren inside included), a write call with a computed target (concatenation, f-string, `%` / `.format`, `os.path.join` / `path.join` with a non-literal part, a variable, a loop over `listdir` / `glob` / `readdirSync`, a `sys.argv[n]` / `process.argv[n]`), printed beside any literal paths the program also names. An argv target never resolves to an operand, since the program can rebind, mutate or shadow argv (`sys.argv[1] = …`, `process.argv.splice(…)`, `const process = …`): `python3 -c … foo` prints the operands, as the .sh does, and the line; `python3 - foo <<EOF` prints only the line, since the .sh prints no stdin program's operands. A python or node target name the program binds exactly once, first, at top level, to one plain string literal (python also `Path` / `pathlib.Path` / `PurePath` of one) resolves to that literal and adds no line, when every other use is a whole call argument or (python) the receiver of a method call `p.<ident>(`. A rebound, augmented, loop / branch / with / for-bound or non-literal name does not, nor does a name that takes an attribute store (`p._str = …`) or a non-call attribute access (`p.name`). No name resolves in a program that reaches its namespace dynamically: `import` then `*` across blanks or backslash-newlines, `exec(`, `eval(`, `compile(`, `globals(`, `locals(`, `vars(`, `setattr(`, `delattr(`, `__dict__`, `__builtins__`, `__import__` or `importlib`. The marker also covers a shell body that find / fd / xargs run on a target it cannot bind, and nesting deeper than 3 levels. A process call's command keeps the line with its reason. The `<text>` is the interpreter name or the program or body text, at most 80 characters. The cap line (GH 2090) `UNRESOLVED:$(computed):analysis cap reached (<N> work units): split this command into smaller ones` is printed alone, with no partial paths, when the analysis passes `ANALYSIS_WORK_CAP`, overflows the stack or the longest string, or the command is itself longer than the cap (then before parsing). The count is deterministic and shared with the commands a program runs, so a command gets the same verdict on any machine; the .sh has no cap. |
| `$(unproven)` | TS-only (GH 1739). An inline program makes a call that is neither a write the scanner judges nor in the closed safe set of `prove.ts`: an unlisted call (a safe module allows only its listed names, so a module it imports, such as `os.path.os` or `json.codecs`, is unlisted), a callable held in a name (`m = shutil.move`), dynamic attribute access, an attribute or `process.argv` / `env` store, or a perl / ruby word off the allowlist. It is also printed for a stdin program whose text the shell fills in (a held part, an expanding heredoc or here-string), an `eval` with a non-literal argument, and a command word that is an expansion. Printed beside the program's other lines; the `<text>` is the program (prefixed by the interpreter for a stdin program) or the statement, at most 80 characters. |
| `$(proc)` | An interpreter program's process call (`os.system`, `subprocess`, `child_process`, …) runs a command whose target cannot be named. |
| `$(alias-write)` | An interpreter program holds or aliases a write callable (`w = open`, `from os import remove as r`), so its calls cannot be traced. |
| `$()` | The target contains a command substitution or backticks. |
| `PWD` | The statement's dir is unknown (after `cd "$X"` with an unknown `$X`), so the target is shown as `$PWD/<path>`. |
| a variable name | `$NAME` or `${NAME}` has no known value: not assigned in the command and not one of the allowlisted env variables. |
| a `${…}` text | A positional parameter, or a `${…}` expansion the analyzer does not model. |

A gate should treat every `UNRESOLVED:` line as a write it cannot place.

## Corpus and divergences

`src/test/cmd-analysis-diff.suite.ts` runs every row of `tests/fixtures/cmd-analysis/write-paths.jsonl` (`{cmd, cwd?, raw?, root?, layout?}`, with `$TMP` standing for the test's temp dir) through a bash process that sources `cmd-analysis.sh` and through `writePaths`, the rows split across `cmd-analysis-diff.shard-<k>of<n>.test.ts` with one bash process each, under a fixed `HOME` / `TMPDIR` / `CLAUDE_PROJECT_DIR` / `TMB_MODEL_CACHE_DIR` and `LC_ALL=C`.

- Each row must print the same lines in both, unless its `cmd` is in `tests/fixtures/cmd-analysis/divergences.jsonl`.
- A divergence `{cmd, sh, ts, reason}` must still differ exactly as recorded, and its `reason` explains why the TS is right. Divergences only ever make the TS stricter: it prints an `UNRESOLVED:` line, or more paths, where the .sh prints fewer or none.
- A change that alters a row's TS output either keeps it equal to the .sh, or records the row as a divergence with the new output and a reason.
- Read-only programs within the safe set (for example `python3 -c "print(open('README.md').read())"`) belong in the corpus too, and must stay `[]` in both. A read-only program outside it prints `$(unproven)` and is a recorded divergence.
- `src/test/cmd-analysis-unproven.test.ts` runs `tests/fixtures/cmd-analysis/unproven-probes.jsonl` with cwd and root `/w`: a `fail_closed` row prints an `UNRESOLVED:` line or a path outside `/w`, an `empty` row prints `[]`, a `resolves` row prints exactly its `paths`.
- A `layout: "repo-worktree-symlink"` row also checks `pathCanonical` against `tmb_path_canonical` on each absolute line.

## Cold start

A hook runs as a short-lived process, so the analyzer keeps its cold start small:

- Importing `index.ts` loads no parser. The first non-blank command loads only the bash grammar (`loadParser('bash')` from `../../parsing/loader.js`), once per process. `src/test/cmd-analysis-lazy.test.ts` checks this through `bashParserLoads()`.
- The python and javascript grammars (`tree-sitter-python.wasm` is copied into `dist/parsing/` by the build) load only when a program in that language is analyzed, once per process. The first such program marks its grammar wanted and stays unproven for that pass; `writePaths` loads the grammar and analyzes the command again. A plain shell command never loads them; `programParserLoads()` counts the loads.
- Before that load, `parser.ts` sets the V8 flags `--no-wasm-dynamic-tiering` and `--no-wasm-tier-up`, so the process does not compile optimized wasm code it will not run long enough to use.
- A failed load is not cached, so the next command tries again.
