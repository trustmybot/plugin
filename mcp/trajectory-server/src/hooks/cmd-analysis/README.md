# src/hooks/cmd-analysis

The TypeScript write-path analyzer (GH 1692): `tmb_cmd_write_paths` of the retired shell lib `cmd-analysis.sh` rebuilt on a tree-sitter-bash parse. Given a Bash command, it lists every path the command may write. Where it cannot name a path it prints an `UNRESOLVED:` line, so a gate can deny rather than allow. `cmd-analysis.sh` is retired: every hook runs on this port, which matched it line for line, except on the recorded cases where it is stricter, and the one recorded exception below (GH 1723).

## API

`index.ts` is the only entry point.

| Export | What it does |
|---|---|
| `writePaths(command, { cwd, raw, root, env, treeWrites, claudeDir, gitMoves })` | Resolves to the lines `tmb_cmd_write_paths "$command" "$cwd" [raw] "$root"` prints: absolute paths, `UNRESOLVED:<reason>:<text>` lines and, with `raw`, paths as written. `root` is the run root that a lister-bound loop variable or find / fd placeholder must stay under. `env` supplies `HOME`, `TMPDIR`, `CLAUDE_PROJECT_DIR` and `TMB_MODEL_CACHE_DIR` / `HF_HOME` (default `process.env`). With `treeWrites` (TS-only, prompt-write-approval, GH 2981) it lists only the dirs a statement fills with a whole tree, the arguments of a `mv`, `cp`, `rsync`, tar, `unzip`, `git mv`, `git checkout` or `git restore` brace-expanded as bash passes them (`braceWords`, a word that may leave its stem standing as `claudeDir`, `<root>/.claude` by default; no other command's words are expanded): a recursive `cp`'s and an `rsync`'s destination, where each source of a `mv` / `git mv` lands (`<dest>/<source basename>`, or the destination itself under `-T`), a tar extract's `-C` dirs or its own dir, an unzip's `-d` dirs or its own dir (none in a list, test or print mode such as `-l`, `-Z`, `-t` or `-p`; GH 2987), each operand of `git checkout` / `git restore` read as a pathspec (a glob cut to its leading literal dir; a `restore --staged` without `--worktree` none), and the interpreter targets; redirects and other writes are left out. A pathspec named from the repository top (`:/…`, `:(top)…` or any long magic carrying `top`), an exclusion and `--pathspec-from-file` (both read as the whole tree) resolve against the top: the `--work-tree` dir, else the nearest dir holding a `.git` above the statement's dir (`gitWorkTreeTop`), else `root`. Under `--git-dir`, or when `env` or the command sets `GIT_DIR`, `GIT_WORK_TREE` or `GIT_COMMON_DIR`, the top cannot be told and the line is `root` (or `/`), so a gate on it fails closed. With `gitMoves` (TS-only, prompt-write-approval, GH 2987) it also prints a `GIT-MOVE:` line (`GIT_MOVE_PREFIX` and JSON, read back by `parseGitMoveLine` as a `GitMove`) for each git statement its statement walk reaches, however it is run (a wrapper, find / fd / xargs, `watch`, a shell body, an interpreter's process call), that may rewrite its work tree or move a ref, and for each shell text naming git that it cannot read. A blank command resolves to `[]` without loading a parser. |

TS-only (GH 2987). |
| `REFS_MAY_MOVE` | The `unresolvable` `TreeChange` a gate gives a move beside another ref-moving git statement in the same work tree. TS-only (GH 2987). |
| `gitWorkTreeTop(dir)` | The nearest dir at or above `dir` holding a `.git`, as git finds its work tree with no `GIT_DIR`; null when none. A pure path check. |
| `pathCanonical(path)` | `tmb_path_canonical`: follows symlinks in the existing prefix (at most 40 hops) and keeps the missing tail. A relative path comes back unchanged. |
| `payloadCwd(json, env)` | `tmb_payload_cwd`: the hook payload's `.cwd` when it is a non-empty string, else `env.PWD`. |
| `braceExpand(word)` | The words bash brace-expands `word` to (comma lists, nested, and `{x..y[..n]}` sequences), or null past `BRACE_LIMIT` words. TS-only (prompt-write-approval, GH 2981). |

| `braceWords(words, unresolvable)` | A word list expanded. A word past the limit stands as its first word, the glob `<stem>.claude*`, its shapes (its words with each numeric sequence cut to its first and last number) and its last word; one whose shapes may lie outside its stem (a `..` segment, a `/` or `~` root, or a `$` or backtick after the stem) stands as its first word, `unresolvable` after its option prefix, and its last word, so a gate on `unresolvable` fails closed (GH 2994). |

| `cmdStatements(command, cwd, env)` | `tmb_cmd_statements`: resolves to `{ ok: true, statements }`, one `Statement` `{ dir, stmt }` per executable statement, `bash -c` / `eval` bodies included (to depth 3). The code a statement runs later is listed after it in `-`: a `trap` action, each `alias` value, a `mapfile` / `readarray -C` or `compgen` / `complete -C` callback, a `compgen` / `complete -W` word list's expansions, and the expansions of a `PS4` value (assigned, given to a wrapper such as `env PS4=… bash -x`, or through `export` / `declare` / `typeset` / `local` / `readonly`) holding `$` or a backtick. A statement is `opaque: true` when it runs code the listing cannot read: a shell's `-c` string, an `eval` argument or a deferred code word that is not literal (judged from `src` when the decoded word holds `$`, a backtick or a pattern char), a code runner an unquoted `$( )` cut, a shell that reads its code from stdin (`-s`, or no operand), a `${…@P}` prompt expansion, a `PS4` value that expands as it is assigned (`PS4=$X`, `export PS4="$X"`: `set -x` expands the result again), a command word that is an expansion (`$G push`), any `PS4` but a literal assignment's name (bare, before a command, behind `env` or a declaration builtin that is no nameref), a git argument's plain text or a quoted-delimiter heredoc body (`${PS4:=…}`, `printf -v PS4`, `read P\S4`, `declare -n p=PS4`, `export PS4`), a `${!name=…}` indirect assignment, a variable name a builtin takes from an expansion (`declare "$X=…"`, `export "$X=…"`, `printf -v "$X"`, `read "$X"`, `mapfile "$X"`, `declare -n p=$X`), code past depth 3, or deferred code that does not parse; the code it can read is still listed. When the command or a body in it does not parse, it resolves to `{ ok: false }` (the `GitStatements` type), never a partial list. |

A `cwd` inside a linked worktree (`git rev-parse --git-dir` differs from `--git-common-dir`) counts as that one checkout and resolves to `cwd` (GH 2510); with `unresolved: true` (git-guards, for a dir behind a variable that may name any checkout) it stays `?`. |

| `gitSubcommandOf(statement)` | git's subcommand in a statement (a `Statement` or its `stmt` string) and the words after it, as `gitSubcommand` gives them, or `undefined` when it is unknown (GH 2634): the subcommand word, or a git option word before it that is no option's argument, holds `$`, a backtick, a brace or glob character, or is a redirect. The argument of `-C`, `-c`, `--git-dir`, `--work-tree` or `--namespace` (or the `=value` of the last three) may hold an expansion, which cannot move the subcommand, and is unknown only as a brace or glob pattern or a redirect. ## Module map

| File | Role |
|---|---|
| `index.ts` | The public API above. |
| `brace.ts` | `braceExpand`, `braceEdge` and `braceWords`: bash brace expansion of a word, a `{` with no comma or sequence, an unclosed one and a `${…}` left literal; quoting is not seen, so a quoted brace expands too (fail-closed for the gate). TS-only (GH 2981). |
| `parser.ts` | Loads the bash grammar, and the python and javascript grammars for inline programs, lazily, once per process (see Cold start). |
| `encode.ts` | The `keep` skeleton of `tmb_cmd_strip_literals`: heredoc bodies and comments dropped, quotes removed, quoted blanks and operators turned into reversible control bytes; `decode` maps them back. A quoted `(` / `)` inside a substitution gets its own bytes (`SUB_PO` / `SUB_PC`), so a held-program check is not fooled by `"$(cat ')')"`. A substitution's frame starts at its real `$(` or backtick, not at the blanks tree-sitter-bash folds into the opener after a preceding expansion (`"$(cat a) $(cat b)"`). Each heredoc gets bash's delimiter, its start word with quotes and backslashes removed; `encode` is not ok when the `heredoc_end` is not exactly that delimiter, or when a body line before it already is one (leading tabs stripped for `<<-`; with an unquoted delimiter, body lines first joined across each unescaped backslash-newline, so `EO\` then `F` is a delimiter line, F753-1), so a heredoc tree-sitter-bash reads past its end never drops the statements after it (GH 1927). With `marks` on, each `$` bash keeps literal (inside `'…'` or `$'…'`, or after a backslash, unquoted or inside `"…"`) is `DOLLAR` (`\x19`), so `write-paths.ts` never expands it and judges `'$HOME/x'` or `\$PWD` as the path bash writes; `decode` maps it back to `$`, `decodeKeepDollar` keeps it until the path is printed, and a literal `\x19` in the command encodes as `$()`. An unescaped `$` inside `"…"` and an unquoted `$` still expand, and without `marks` the skeleton is unchanged (GH 2443). A backslash-newline is dropped unquoted and inside `"…"`, as bash joins the lines, and stays inside `'…'`, `$'…'` and heredoc bodies (an unquoted-delimiter body still joins it when finding the delimiter); `held` and `spliced` read the words tree-sitter-bash splits there as the one word bash reads, and such a word holding a `$` or backtick is held and never spliced (GH 2646, GH 1978). A `$'…'` body is decoded as bash decodes it (`ansiCChars`, GH 2640); an escape whose result is unknown (a NUL, no hex digit, a `\x` or octal byte above 0x7F, which bash writes as a raw byte, an invalid code point, `\c` before `\`, `?` or nothing) and a control char other than tab and newline encode as `$()`, so the word reads as computed and is held. With `shownControls` (the commit-message reader), a control char reads as U+FFFD instead, and each run of adjacent `\x` / octal byte escapes that is valid UTF-8 reads as its chars, as bash in a UTF-8 locale writes them; an invalid run stays `$()` (GH 2765). With `heredocCode` (the git listing), `bodyCodes` reads each outermost `$( )` of an unquoted-delimiter heredoc body from the parse tree's `command_substitution` nodes (a `<<-` body reparsed with its leading tabs stripped, since tree-sitter-bash gives its body no children) and each backtick from the text, since tree-sitter-bash misses those; each one's code is encoded on its own and framed by `QO` … `QC` after the heredoc's delimiter; code that does not parse, or an unclosed one, makes the command not ok (GH 2635). A body `$(( ))` that tree-sitter-bash reads as `$( )` around one subshell but bash reads as arithmetic made of arithmetic characters alone (`$((W=0))`) runs no command, so it adds no code; `$((a);(b))` and `$((a) )` are still `$( )` (GH 2876), and so is one holding a quote, `;`, `&`, `|`, newline, `$` or backtick, since zsh ignores quoted parens and runs `$((echo ")";cmd))` as a command (F823-1). |
| `git-word.ts` | `gitWord` (GH 2797): where git sits in a statement's words, the first word by its basename or the command a chain of wrappers runs (`env`, `command`, `builtin`, `exec`, `nice`, `nohup`, `time`, `sudo`, `doas`, `xargs`, `timeout`, `stdbuf`, `ionice`, `chrt`, `taskset`, `setsid`, and `gnice` / `gtimeout` / `gstdbuf`), each read by an allowlist of its options, which of them take a value, and its operand (`timeout`'s duration, `chrt`'s priority, `taskset`'s mask) or `NAME=value` words. `env -C` / `--chdir` take a dir value only within the words `unwrap.ts` strips, as the listing moves the statement into that dir there; anywhere else (`/usr/bin/env`, env behind `setsid`, `xargs` or another wrapper `unwrap.ts` does not strip) they are unknown. An option the table does not know (`sudo -D` among them), a `--chdir=` word, or a skipped word that is not literal (`NOT_LITERAL`) makes the place unsure: git is the first later word whose basename is git. `command -v` / `-V` runs nothing. `statements.ts` uses it for git's `-C` dir, kept empty words and `cut`. |
| `git.ts` | `cmdStatements`, `cwdState`, `gitSubcommand`, `gitSubcommandOf`, `gitSubcommandUnknown`, `unquotedCommand`, `prefilterPasses`, `gitBesideExpansion`, `ambiguousSubcommandReason`, `stmtRepoRoot` and `denyAmbiguousGitTarget`: the git-target helpers of `cmd-analysis.sh` that git-push-guard and git-guards use, on the `encode.ts` skeleton and `statements.ts`. |
| `git-moves.ts` | The `GIT-MOVE:` line format and `gitStatementRead`: what one git statement's words change in its work tree and where they point git, each subcommand's words read as git's parse-options reads them, a long option by a unique prefix too. Pure reads of one statement; `write-paths.ts` calls it from its statement walk. TS-only, prompt-write-approval (GH 2987). |
| `commit-message.ts` | `gitCommitMessage`: `tmb_git_commit_message` of `cmd-analysis.sh`, the first `git commit` statement of a command's skeleton and the message its argv carries, which commit-msg-lint uses. |
| `forge.ts` | `ghMutation` and `ghMutationFrom`: the forge-write classifier of `cmd-analysis.sh` (`tmb_gh_mutation`, `_tmb_gh_mutation_in`, `tmb_gh_mutation_from`) that swe-boundary uses, over the words of a `cmdStatements` statement. |
| `surface.ts` | `isPromptSurfacePath`, `surfaceRoot`, `WRITE_SHAPES` and `writeShapes`: the prompt-surface predicate and write-shape list of `cmd-analysis.sh` that swe-boundary uses. |
| `harness-turn.ts` | `isHarnessTurn`: `tmb_is_harness_turn` of `cmd-analysis.sh`, whether a UserPromptSubmit prompt came from the harness (a task or system notification, a subagent hand-back, an agent or cross-session message) rather than the Human. |
| `strip-literals.ts` | `stripLiterals`: the plain-mode awk scanner of `tmb_cmd_strip_literals`, ported state for state with no parser. |
| `statements.ts` | `_tmb_cmd_statements_enc`: one record per executable statement, with its effective dir (cd / pushd / popd / git -C / subshells), assignments and loop sources. With `frame` (by default the `assign` flag; `git.ts` sets it without `assign`, GH 2065) a loop's records sit between a `{` (`LOOP_OPEN`) and a `}` (`LOOP_CLOSE`) record: from the `while` / `until` keyword, since the condition runs on every pass, or from the `do` or `{` that ends a `for` / `select` header (also after `coproc`, and inside the header's own statement when that word comes right after NAME, as in `for i do …; done`), to the `done` or `}` that closes it (GH 1944). The frames must balance: a `do` no header waits for, a `done` or `}` that does not close the innermost frame, or a frame still open at the end appends, in `assign` mode, a last `!` (`UNBALANCED`) record. A quoted or escaped word (`"done"`, `\done`, `d''one`, `$'done'`, `"}"`) is never one of these reserved words (POSIX 2.4): `encode.ts` puts a `QM` (`\x17`) mark before each opening quote and unquoted backslash, and `statements.ts` notes which words hold one, then drops the marks; a literal `\x17` in the command encodes as `$()`. A loop body's `cd` / `pushd` / `popd` crosses the back-edge (GH 1977): a dir token may list, each after an `ALT` (`\x13`), the other dirs the loop can bring its statement to; the frames are re-encoded until the dirs each one ends a pass in stop growing, and after a frame's `}` the dir is its entry dirs plus those. A frame still growing after `MAX_GROWTH` runs, or a frame edge that would leave more than `MAX_DIRS` dirs, leaves the dir `-` alone, so a `cd` that keeps drifting fails closed in bounded time. With `frame` `'calls'` (what `git.ts` passes; `'escaped'` inside an `eval` body) a function body gets a frame of its own (`Frames.fnames` maps each name to its frames): each call adds its dirs to the frame's entry dirs, and a `{ }` body that moves the dir leaves its end dirs (and `return` dirs) as the dir after the call. A call the scan cannot pin (see `cmdStatements`) loses the frame to `-`, and an assignment inside a body leaves the variable unresolved (GH 2630). A `VAR=<literal>` survives a redirect whose target is a plain word or an fd duplication (`2>&1`, `>out.log`, `&>/dev/null`, `1>&-`), so `W=<dir>; git -C $W merge x 2>&1` resolves to `<dir>`; a target with `$`, a backtick, a glob, a brace or a `(` keeps the variable unresolved. That is TS-only: `cmd-analysis.sh` drops the variable at any redirect (GH 2404). |
| `unwrap.ts` | Skips `VAR=value` words and the wrappers `sudo`, `env`, `command`, `nohup`, `time`, `exec`, plus `builtin`, `timeout` (and its duration), `stdbuf` and `nice` and their Homebrew coreutils names `gtimeout`, `gstdbuf` and `gnice`, each with its own options. These last seven are TS-only (`builtin`: GH 2635). `command` with an option word holding `v` or `V` (`-v`, `-V`, `-pv`) before any `--` or operand is a lookup that runs nothing: the TS stops at that option word instead of skipping to the looked-up name, so `command -v bash` is not judged as `bash` reading stdin, while its own redirects still are (GH 1872). |
| `targets.ts` | The paths one statement writes as written: redirects, `tee`, `cp` / `mv` / `rm` / `touch` / `sed -i` and the rest, the sources `mv` removes, and the git tree commands. A symbolic `ln` that is the last statement of a top-level command, with nothing that may run alongside or after it (`&`, a pipe `|` / `|&`, `trap`, `coproc`, `setsid`, a process substitution, a detached or scheduled launcher such as `tmux`, `screen`, `at`, `batch`, `systemd-run`), writes only its link paths: the last operand, each `-t` / `--target-directory` value, or `./<basename TARGET>` for one operand; a hard link, an earlier statement, a nested body, or an option word after an operand (BSD `ln` reads it as one) keeps TARGET; that is TS-only (GH 1789). A tar extract (`-x` cluster, `--extract`, `--get`, or a bundled first word holding `x`) with no `-C` / `--directory` writes its own dir; that is TS-only (GH 2981). It also holds the `treeWrites` targets (see `writePaths`). |
| `programs.ts` | Interpreter programs (`python -c`, `node -e`, `perl -e`, `ruby -e`, heredocs, here-strings, stdin programs): their write-call targets, held programs and the `$(computed)` and `$(unproven)` fail-closed markers. |
| `prove.ts` | The allowlist (GH 1739): a program is proven only when every call in it is a write `prog-calls.ts` judges or sits in a closed safe set. Python and node programs are walked on a tree-sitter parse; perl and ruby one-liners are lexed against an identifier allowlist; perl's `select` is allowed only as the 4-argument sleep `select(undef,undef,undef,<number or $scalar>)` (GH 1887), and a perl `open` passes as safe rather than judged only as a 2-argument read of a plain path literal (`open(F, "a.md")`, `open(my $f, "<a.md")`): a mode prefix, a pipe, `-`, an interpolation or an escape in the string leaves it unproven (GH 2024). A string where a safe call takes a callback (`re.sub`'s `repl`) and a `.replace(a, b)` on the result of a str-returning method call (`open(p).read().replace(…)`) are proven. A call inside a python f-string interpolation leaves the program unproven, since `prog-calls.ts` cannot see it (GH 2463). A judged write call with a `*` or `**` argument marks the proof blind, since the scanner names no target for it (GH 1723). A process global (`os.environ`, `sys.argv`, a `sys` stream, `process.env` / `argv` / `stdout` / `stderr` / `versions`, or a name aliasing one) is proven only as the direct base of an attribute or subscript, an alias to a plain name, a loop iterable, a spread or splat, a comparison operand, the whole right side of a destructuring declaration or unpacking statement when it is `os.environ`, `sys.argv`, `sys.stdin`, `process.env` or `process.argv` itself (`PY_UNPACKED`, `JS_UNPACKED`), or an argument to a closed set of calls that keep nothing (`PY_SINKS`, a string literal's `join`, `JS_SINKS`, `console.*`); anywhere else it could reach a name the proof takes for a local, so the program is unproven, as is any node `this` (GH 2490). |
| `prog-calls.ts` | The `_tmb_cmd_prog_calls` awk scanner ported state for state; emits the `W` / `T` / `F` / `S` / `R` / `U` / `H` / `C` / `Q` / `A` lines `programs.ts` reads. A python or node write target that is one bare name, a python `write_text` / `write_bytes` receiver that is one bare name, or a `sys.argv[<n>]` / `process.argv[<n>]` target prints `F<TAB><name>` where the awk prints `F`. |
| `lister.ts` | The path-listing model: binds a loop variable or a find / fd placeholder to what its lister may list when that stays inside the run root. |
| `path.ts` | `pathCanonical`, `payloadCwd` and `gitWorkTreeTop` (the nearest dir holding a `.git`, as git finds its work tree with no `GIT_DIR`; TS-only, GH 2981). |
| `write-paths.ts` | `tmb_cmd_write_paths` itself: walks the statements, expands variables, recurses into `bash -c` / `eval` / `watch` bodies and sh programs on stdin (to depth 3), judges what find / fd / xargs run, and prints the lines. With `gitMoves` each statement it judges is also read by `git-moves.ts`, with the runners around it (watch, find / fd / xargs, a loop) that may start it more than once (GH 2987). A `bash -c` statement's own redirects and write commands (`bash -c 'ls' > /etc/out`) are judged before its body; that is TS-only. `node --test` / `--run` / `--watch` and `python3 -m<module>` are not stdin programs. `eval` (or `builtin eval`) with a non-literal argument and a statement whose command word is an expansion (`$CMD`) print `$(unproven)`; that is TS-only. An `eval` whose arguments the shell fills in only from `$NAME` / `${NAME}` variables, each holding only literals the command tracks (from a `for` list or a plain assignment; no glob, brace, tab or newline, `IFS` never set, no `cd` / `pushd` / `popd` in the result), runs each combination of values (at most 16) as its own eval body instead, and a name an eval body sets is unresolved after it (GH 1913). At a loop's `{` record it first applies the loop body's variable effects (assignments, `read` / `printf -v` / declaration builtins) over and over until the values stop changing, so an assignment later in the body reaches a use earlier in it on the next pass; a name still gaining values after 8 passes is unresolved. Variable values are a union in first-seen order, printed once each. A level with an `UNBALANCED` record, and every level it runs, resolves no variable at all: each use prints `UNRESOLVED:`, so a loop shape the tracker misreads fails closed instead of resolving from the wrong frame. `cmd-analysis.sh` follows the same loop-body and balance rules (GH 1944). A substitution that `mktemp.ts` allowlists resolves to the path mktemp prints: its template (expanded like any word, relative to the cwd, last component `[A-Za-z0-9._-]*` ending in at least three `X`), or `<prefix or tmp>.XXXXXXXX` under the run env `TMPDIR`, which must be absolute and not set by the command; at most 16 values. `${NAME:-def}` / `${NAME:=def}` / `${NAME-def}` / `${NAME=def}` for `PWD`, `OLDPWD`, `HOME`, `TMPDIR`, `CLAUDE_PROJECT_DIR` and `TMB_MODEL_CACHE_DIR` take the run env value when bash would (colon forms: set and non-empty; plain forms: set), else the default. Both are TS-only (GH 1912). A `${NAME=def}` resolves only in a statement with no command substitution that names `NAME` nowhere else, and `NAME` is unresolved after it (GH 2440). |
| `mktemp.ts` | `mktempCall` and `MKTEMP_MARK` (GH 1912): the allowlisted mktemp shape, flags only `-d`, `-q` and `-t <prefix>` (prefix `[A-Za-z0-9._-]+`), at most one template operand and never both `-t` and an operand. `encode.ts` (with `marks` on, as write-paths calls it) puts `MKTEMP_MARK` (`\x18`) after the opener of a `$(…)` or backtick substitution whose whole text is that shape, so a single-quoted `'$(mktemp)'` never resolves to a mktemp path (it is the literal name `$(mktemp)`, GH 2443); a literal `\x18` in the command encodes as `$()`. |

## UNRESOLVED reasons

Every line that is not a path is `UNRESOLVED:<reason>:<text>`. Any of them means "this command writes somewhere the analyzer cannot name".

| Reason | Meaning |
|---|---|
| `$(parse)` | tree-sitter-bash could not parse the command, or misread a heredoc so that its end is not the line bash ends it at, as with `cat <<E"M"` or a body line of `$` (GH 1927). The `<text>` is the first 80 characters of the command and it is the only line printed, so a parse error never yields a partial list. A process call's shell command that does not parse prints the line beside the program's other lines; it keeps its reason (TS-only), where the .sh strips the prefix and judges the text as a path. |
| `$(computed)` | TS-only. The command writes, but the target is computed where neither analyzer can see it: a program piped or redirected into an interpreter (an info option such as `--version` exempts it only among the interpreter's own options, so `python3 - --version` still fails closed; `perl -c` runs `BEGIN` blocks and is not one, `ruby -c` is), a program held in a variable or in substitutions nested to any depth (`"$(cat $(echo x))"`, a quoted paren inside included), a write call with a computed target (concatenation, f-string, `%` / `.format`, `os.path.join` / `path.join` with a non-literal part, a variable, a loop over `listdir` / `glob` / `readdirSync`, a `sys.argv[n]` / `process.argv[n]`), printed beside any literal paths the program also names. An argv target never resolves to an operand, since the program can rebind, mutate or shadow argv (`sys.argv[1] = …`, `process.argv.splice(…)`, `const process = …`): `python3 -c … foo` prints the operands, as the .sh does, and the line; `python3 - foo <<EOF` prints only the line, since the .sh prints no stdin program's operands. A python or node target name the program binds exactly once, first, at top level, to one plain string literal (python also `Path` / `pathlib.Path` / `PurePath` of one) resolves to that literal and adds no line, when every other use is a whole call argument or (python) the receiver of a method call `p.<ident>(`. A rebound, augmented, loop / branch / with / for-bound or non-literal name does not, nor does a name that takes an attribute store (`p._str = …`) or a non-call attribute access (`p.name`). No name resolves in a program that reaches its namespace dynamically: `import` then `*` across blanks or backslash-newlines, `exec(`, `eval(`, `compile(`, `globals(`, `locals(`, `vars(`, `setattr(`, `delattr(`, `__dict__`, `__builtins__`, `__import__` or `importlib`. The marker also covers a shell body that find / fd / xargs run on a target it cannot bind, and nesting deeper than 3 levels. A process call's command keeps the line with its reason. The `<text>` is the interpreter name or the program or body text, at most 80 characters. The cap line (GH 2090) `UNRESOLVED:$(computed):analysis cap reached (<N> work units): split this command into smaller ones` is printed alone, with no partial paths, when the analysis passes `ANALYSIS_WORK_CAP`, overflows the stack or the longest string, or the command is itself longer than the cap (then before parsing). The count is deterministic and shared with the commands a program runs, so a command gets the same verdict on any machine; the .sh has no cap. |
| `$(unproven)` | TS-only (GH 1739). An inline program makes a call that is neither a write the scanner judges nor in the closed safe set of `prove.ts`: an unlisted call (a safe module allows only its listed names, so a module it imports, such as `os.path.os` or `json.codecs`, is unlisted), a callable held in a name (`m = shutil.move`), dynamic attribute access, an attribute or `process.argv` / `env` store, a process global that escapes into a container, argument, loop variable or return value (GH 2490), or a perl / ruby word off the allowlist. It is also printed for a stdin program whose text the shell fills in (a held part, an expanding heredoc or here-string), an `eval` with a non-literal argument (other than one filled in only from tracked literals, GH 1913), and a command word that is an expansion. Printed beside the program's other lines; the `<text>` is the program (prefixed by the interpreter for a stdin program) or the statement, at most 80 characters. |
| `$(proc)` | An interpreter program's process call (`os.system`, `subprocess`, `child_process`, …) runs a command whose target cannot be named. |
| `$(alias-write)` | An interpreter program holds or aliases a write callable (`w = open`, `from os import remove as r`), so its calls cannot be traced. |
| `$()` | The target contains a command substitution or backticks. |
| `PWD` | The statement's dir is unknown (after `cd "$X"` with an unknown `$X`), so the target is shown as `$PWD/<path>`. |
| a variable name | `$NAME` or `${NAME}` has no known value: not assigned in the command and not one of the allowlisted env variables. |
| a `${…}` text | A positional parameter, or a `${…}` expansion the analyzer does not model. |

A gate should treat every `UNRESOLVED:` line as a write it cannot place.

## Corpus and divergences

`src/test/cmd-analysis-diff.suite.ts` runs every row of `tests/fixtures/cmd-analysis/write-paths.jsonl` (`{cmd, cwd?, raw?, root?, layout?}`, with `$TMP` standing for the test's temp dir) through `writePaths`, under a fixed `HOME` / `TMPDIR` / `CLAUDE_PROJECT_DIR` / `TMB_MODEL_CACHE_DIR` and `LC_ALL=C`, and compares its lines with `tests/fixtures/cmd-analysis/expected.jsonl`, the frozen output of the retired `cmd-analysis.sh`, recorded once (one line `{cmd, cwd?, raw?, root?, lines, canonical?}` per row). The rows split across `cmd-analysis-diff.shard-<k>of<n>.test.ts`; shard 1 also runs the whole-corpus and fixture checks.

- Each row must print the same lines in both, unless its `cmd` is in `tests/fixtures/cmd-analysis/divergences.jsonl`.
- A divergence `{cmd, sh, ts, reason}` must still differ exactly as recorded, and its `reason` explains why the TS is right. Divergences only ever make the TS stricter: it prints an `UNRESOLVED:` line, or more paths, where the .sh prints fewer or none. The one exception is GH 1723: a python program that `prove.ts` proves, whose every write target is a literal or a name bound only to plain literals, prints just those targets, without the .sh's literal fallback (GH 1550) that adds every other path-like literal in the program. The rebinds that fallback guards against (cProfile, trace, pdb, gc, pickle, exec, globals) all sit outside the prover's allowlist. A proof marked blind (a write call with a `*` or `**` argument) keeps the fallback.
- A change that alters a row's TS output either keeps it equal to the .sh, or records the row as a divergence with the new output and a reason.
- Read-only programs within the safe set (for example `python3 -c "print(open('README.md').read())"`) belong in the corpus too, and must stay `[]` in both. A read-only program outside it prints `$(unproven)` and is a recorded divergence.
- `src/test/cmd-analysis-unproven.test.ts` runs `tests/fixtures/cmd-analysis/unproven-probes.jsonl` with cwd and root `/w`: a `fail_closed` row prints an `UNRESOLVED:` line or a path outside `/w`, an `empty` row prints `[]`, a `resolves` row prints exactly its `paths`.
- A `layout: "repo-worktree-symlink"` row also checks `pathCanonical` against `tmb_path_canonical` on each absolute line.

## Cold start

A hook runs as a short-lived process, so the analyzer keeps its cold start small:

- Importing `index.ts` loads no parser. The first non-blank command loads only the bash grammar (`loadParser('bash')` from `../../parsing/loader.js`), once per process. `src/test/cmd-analysis-lazy.test.ts` checks this through `bashParserLoads()`.
- The python and javascript grammars (`tree-sitter-python.wasm` is copied into `dist/parsing/` by the build) load only when a program in that language is analyzed, once per process. The first such program marks its grammar wanted and stays unproven for that pass; `writePaths` loads the grammar and analyzes the command again. A plain shell command never loads them; `programParserLoads()` counts the loads.
- Before that load, `parser.ts` sets the V8 flags `--no-wasm-dynamic-tiering` and `--no-wasm-tier-up`, so the process does not compile optimized wasm code it will not run long enough to use.
- A failed load is not cached, so the next command tries again.
