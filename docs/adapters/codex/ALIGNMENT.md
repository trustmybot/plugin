# Codex workflow alignment

Codex should provide the same TMB user workflows as Claude Code through the shared core and a thin host adapter. This program covers planning, execution, review, delivery, recovery, consultants, extensions, and the dashboard.

Parent: [GH 2155](https://github.com/trustmybot/plugin/issues/2155). Baseline issue: [GH 2156](https://github.com/trustmybot/plugin/issues/2156). Milestone: [Codex adapter](https://github.com/trustmybot/plugin/milestone/30).

The source baseline is `dev` commit [`9cc886e81bab51eb26ee83807f85e45caecd7c27`](https://github.com/trustmybot/plugin/tree/9cc886e81bab51eb26ee83807f85e45caecd7c27), inspected on 2026-10-29. It includes the Human-only rework hard stop in [PR 2154](https://github.com/trustmybot/plugin/pull/2154). Implementation claims below refer to this tree. Test references identify existing coverage; they do not claim that a test or live-host session passed during this inventory.

[PARITY.md](PARITY.md) remains the declaration of what Codex currently provides. This plan adds no tools, activates no Hooks, changes no support claim, and grants no workflow authority to the two standalone Agents. The [Adapter Contract](../ADAPTER_CONTRACT.md) governs every delivery unit.

## Current baseline and target

The Codex [manifest](../../../.codex-plugin/plugin.json) selects two explicit Skills, an empty command surface, and an [empty Hook manifest](../../../hooks/codex/hooks.json). Its [registry](../../../mcp/trajectory-server/src/codex-tools.ts) exposes 15 tools: project-local initialization, inventory and scanning, two world-model reads, label taxonomy, local planning Issues and discussions, and the two Agent materialization operations. The wrappers inject Bro arguments and keep remote Issue synchronization off.

The shared [tool registry](../../../mcp/trajectory-server/src/tools/index.ts) already contains most of the domain behavior needed for alignment. Its handlers, schema, migrations, and workflow rules stay single-source. Host paths, event payloads, Agent configuration, and tool grammar need adaptation before more handlers can be exposed.

For this program, a capability is complete when the Codex entry point reaches the shared behavior, its failure and recovery paths work, the declared enforcement tier matches the implementation, and the applicable journey passes on a named native host build. A backend test, a generated Agent file, or a matching plugin version does not satisfy that definition.

- Use [PR 1183](https://github.com/trustmybot/plugin/pull/1183) as a source of implementation and regression cases. B1, B2, B3, D0, and E0 re-evaluate the relevant pieces against their current base. ### Rework hard stop in the baseline

[PR 2154](https://github.com/trustmybot/plugin/pull/2154) supersedes the earlier rule that a Bro decision could restart a task after repeated failure. [Shared constants](../../../mcp/trajectory-server/src/task-rework.ts) and the [rework gate](../../../mcp/trajectory-server/src/hooks/rework-limit.ts) now deny another SWE spawn or resume when any limit is reached:

| Limit | Count and reset rule |
|---|---|
| 2 task review FAILs | Count FAIL verdicts after the task's latest pass and after its latest applicable Human waiver. |
| 6 task SWE runs | Count runs after the applicable Human waiver; exclude `swept_orphan` rows and `stop_cause='budget'` handbacks. |
| 4 Issue review FAILs | Count FAIL verdicts across the Issue's tasks after the applicable Human waiver. A new task under that Issue does not discard the accumulated FAILs. |

The gate reads the latest discussion with `author='human'` and `kind='decision'` on that task, also recognizing Issue-level rows with `task_id IS NULL`. The current [waiver capture Hook](../../../mcp/trajectory-server/src/hooks/rework-waiver-capture.ts) writes only task-specific waivers from the Human's own `waive task <N>` prompt. That waiver resets all three count windows for the named task, including the Issue FAIL count used to judge it; it does not waive sibling tasks. The Issue-level reader has fixture coverage but no corresponding user-facing capture operation in this baseline. [Discussion writes](../../../mcp/trajectory-server/src/tools/discussions.ts) reject `author='human'` from every MCP caller. Agent decisions, dashboard comments, remote comments, retry, and task splitting do not supply a Human waiver.

D0 must establish a native trusted Human-input source before Codex can write such waivers. D2 must test the same limits for both fresh spawns and resumed Agents, including sibling-task FAILs, budget handbacks, fake approval text, and DB-read failures. A native `waive task <N>` journey must show that the named task can proceed while an unwaived sibling remains blocked; Issue-wide capture remains outside the implemented baseline. If a supported host cannot supply that source, the operation stays unavailable and the adapter declaration names the missing enforcement. A prompt instruction to behave as the Human is never a substitute.
