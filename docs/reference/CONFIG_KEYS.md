# plugin_config keys

`plugin_config` is the trajectory DB's key → JSON-value store for workspace-global settings. bro reads and writes it with `config_get` / `config_set` / `config_list`; `/onboard` writes its answers there; hooks only read it. A new key needs no migration, and every key the code depends on is listed here.

## Reading the config

The schema-seeded keys are present in every initialised DB, and seeding never overwrites a user's choice. The label-taxonomy keys fall back to a generic default when unset or malformed, so a label-less project can still create issues. The other keys may be absent until the operation that writes them runs; readers treat absent as the documented default.

## Branch policy is per repo, not here

The branching model (`branching_model`), PR target (`pr_target`) and protected branches (`protected_branches`) are per-repo settings, not `plugin_config` keys. `/onboard` writes them for each repo, and an unset value means the repo is not onboarded (run `/onboard`), never a silent global default. [Multi-repo workspaces](../architecture/GIT.md#multi-repo-workspaces) explains how an operation finds its repo in a single- or multi-repo workspace.

The branching model sets the defaults `/onboard` writes, and never overrides an explicit value:

| Branching model | PR target default | Protected branches default |
|---|---|---|
| `github-flow` | `main` | `["main"]` |
| `gitflow` | `dev` | `["main", "dev"]` |
| `custom` | (caller required) | (caller required) |
