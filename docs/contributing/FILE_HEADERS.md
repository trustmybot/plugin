# File headers — one line saying what the file is for

A new `*.ts`, `*.tsx` or `*.sh` source file opens with a one-line header comment that says what the file is for. The world model reads that line as the file's purpose (`extractPurpose` in `mcp/trajectory-server/src/file-purpose.ts`), so it is what bro sees when it looks for where something lives.

```ts
// Ranks cheatcode hits by embedding similarity and recency.
```

```bash
#!/usr/bin/env bash
# Blocks a git push from a swe worktree until the pr-reviewer gate passes.
```

## What the header is not

- **Not a changelog line.** "Added in v1.2 for GH 1234" or "Fix the race" ages the day it lands; the commit and `changelog.d/` carry history.
- **Not a banner.** A license block, `===` rule or author name is not a purpose; write the sentence a reader needs to know what the file does.
- **Not a restatement of the name.** `// utils` says nothing `utils.ts` doesn't.

## Where it applies

Files added under `src/`, `mcp/*/src/`, `dashboard/src/`, `scripts/` and `skills/*/scripts/`. Tests (`/test/`, `.test.`, `.spec.`), `fixtures/`, `dist/`, `.d.ts` files and generated files (`@generated` or `generated by` in the head) are exempt. Existing files are not checked.

`tests/l1-lint/purpose-header.test.mjs` enforces it against the files a branch adds since its merge base with the PR target.
