# scripts/maintenance

Operational and one-off scripts that keep a TMB install healthy: version bumps and the standalone scan invokers fired by hooks. These are not part of the per-turn hot path — they run on demand (a person, a release flow) or as the body a hook shells out to.

## Files

| File | Purpose |
|---|---|
| `bump-version.ts` | Atomic plugin-version bump — updates the four files that must stay in sync (the Claude plugin manifest, two package manifests, and the `bun.lock` workspace version) and assembles `## Unreleased` plus the `changelog.d/` fragments into the release's `CHANGELOG.md` section (deleting the fragments), or fails leaving every file unchanged. Operates on the checkout holding the script, whatever the cwd. `--dry-run` prints the section; `--date` sets its date; `--version-only` updates the four version files and leaves `CHANGELOG.md` and `changelog.d/` alone (CI dev builds) and ignores `--impact-db`. `--impact-db <path>` (opt-in) closes the section with `### Measured impact`: each fragment ending with a `Metric:` line maps to the PR whose commit added it (subject ending `(#N)`; a fragment with none is skipped with a warning), the built `mcp/trajectory-server/dist/change-impact/cli.js --source plugin_version --id <N>` measures it against that trajectory DB, and each declared metric gets one bullet, `- #<PR> \`<metric>\`, expected <lower\|higher>: <as declared \| moved the wrong way \| did not move \| not enough data>` plus the median ratio and its 95% CI when there is enough data; an unknown change reads not enough data, and a missing CLI or any other CLI failure refuses the bump with every file unchanged. `release.ts` carries the section into the GitHub release notes. Idempotent. |
| `lib/measured-impact.ts` | The pure renderer of `bump-version.ts --impact-db`'s `### Measured impact` bullets from the change-impact CLI's `declared` outcomes, sorted by PR then metric. |
| `dev-build-version.ts` | Prints the dev-build version `X.Y.Z-dev.<n>[.gh<PR>]` for a commit (`--next X.Y.Z [--pr N] [--ref REF]`): `n` is the first-parent commit count since the highest stable tag, reachable or not, and `--next` must be above that tag. Operates on the cwd's repo. Run by `.github/workflows/dev-build.yml`. |
| `lib/changelog-fragments.ts` | Fragment listing, parsing and validation shared by `bump-version.ts` and `tests/l1-lint/changelog-current.test.mjs` (its `list` / `validate` CLI). |
| `run-scan.mjs` | Standalone scan invoker that the trajectory server's connect-time catch-up (`mcp/trajectory-server/src/startup-catchup.ts`) spawns with source `startup_catchup`, which on a warm DB brings each known repo's world model to its target commit by the incremental reindex (GH 2584); a manual run defaults to `bro_auto_initial`. In hook mode (`run-scan.mjs <project-root> hook <repo> [--fetch]`), spawned detached by the `ref-move-reindex` PostToolUse hook, it runs no `scan_run`: it reindexes only `<repo>` with trigger `hook`, first fetching `origin/<target branch>` with `--fetch`, and exits when another process holds the scan lock. Reuses the same `scan_run` logic as the MCP tool through the bundled `mcp/trajectory-server/dist/run-scan.js` (web-tree-sitter inlined, so it runs without devDependencies, GH 1878); silent on a scan failure. Opens only the DB named by `TRAJECTORY_DB_PATH` (the caller passes it; never discovered) and exits 2 without it; a DB that fails to open, such as an older schema it may not migrate, exits 1 with the error. Scans the project root given as its argument, else `CLAUDE_PROJECT_DIR`, never the working directory; with neither it exits 2. |
| `runtime-payload.ts` | Prunes a checkout to the plugin's runtime payload (`node --experimental-strip-types scripts/maintenance/runtime-payload.ts [--root <dir>] [--check]`): every tracked path outside its allowlist leaves the index and the working tree, and it prints the kept/removed counts and the kept size; `--check` removes nothing and exits 1 listing the offenders. Run by `.github/workflows/dev-build.yml` before and after the build commit; tested by `tests/l3-integration/runtime-payload.test.mjs`. |
| `payload-parity.ts` | `node --experimental-strip-types scripts/maintenance/payload-parity.ts --ref <ref> [--root <dir>]`: checks that HEAD's tree holds every generated path (`GENERATED_PATHS`, exported: `mcp/trajectory-server/dist/`, `dashboard/dist/`, `scripts/hooks/lib/audit-events.txt`, `scripts/hooks/lib/data-contracts.json`) that `<ref>` holds (GH 2054). Exits 1 listing the missing paths, or when HEAD holds no generated file; 2 on bad usage or a git error. Run by `.github/workflows/dev-build.yml`'s `dry_run` dispatch against `origin/dev-build`; tested by `tests/l3-integration/payload-parity.test.mjs`. |
| `labels.mjs` | Keeps the repo's GitHub issue labels in line with `.github/labels.json` (TMB development only): `--sync` creates or updates labels and only reports extras, `--doc` rewrites the canonical tables in `docs/contributing/LABELS.md`, `--check` reports a stale doc offline, `--check-live` diffs against GitHub, `--triage <issue>` applies an issue form's Area answer when the issue has no area; on a CLI-filed report (`tmb-report` marker) it also adds `Bug` when the issue has no type and the Impact answer's priority when it has no priority, then toggles `needs-triage`. Run by `label-sync.yml` and `issue-triage.yml`; tested by `tests/l1-lint/labels.test.mjs`. |
| `gen-enums-doc.mjs` | Generates what derives from `mcp/trajectory-server/src/audit-events.ts` (read through its compiled `dist/`): `--txt` writes `scripts/hooks/lib/audit-events.txt` (run by `npm run build`), `--doc` rewrites the `audit.event_type` table in `docs/contributing/ENUMS.md` between its generated markers, `--check` only reports which is stale (`tests/l1-lint/enums-doc-fresh.test.mjs`). |
| `gen-erd-doc.mjs` | Regenerates the schema-derived part of `docs/architecture/ERD.md` between its `erd:generated` markers — mermaid erDiagram, per-table column tables, foreign keys with their `ON DELETE` action, FTS5 search indexes with their shadow tables, the index list, the eval-mode tables — from `mcp/trajectory-server/src/schema.sql` and `schema-eval.sql`, and keeps the doc's `schema_version` token equal to `TARGET_SCHEMA_VERSION` in `db.ts`. `--check` writes nothing and exits 1 when the doc is stale (`tests/l1-lint/erd-doc-fresh.test.mjs`). |
| `gen-config-keys-doc.mjs` | Regenerates the key table in `docs/architecture/CONFIG_KEYS.md` from the `plugin_config` keys the server and scripts read and write (plus the `schema.sql` seed for defaults); each key's type, setter and effect come from its `KEYS` entry in the script, and a key without an entry (or an unused entry) fails. `--check` reports staleness (`tests/l1-lint/config-keys-doc-fresh.test.mjs`). |
| `effort-ab-report.ts` | `node scripts/maintenance/effort-ab-report.ts [--db <path>] [--label <name>]`: the swe effort A/B report (GH 1745) — for each arm (`high`, `medium`) of the tasks enrolled under the label (default `plugin_config.swe_effort_ab`'s), the task count and the median and mean of wall-clock, swe tool calls, swe cache-read tokens, review FAILs and time to merge (task `created_at` to the issue's `issue_auto_closed_on_merge` row). Opens the DB read-only (default: the one the server resolves) and reads it through `dist/effort-ab-report.js`, so build the server first. Exits 2 on bad usage or a missing DB. Each arm also shows the `suggested_tier` counts and each task's tier from its newest `effort_inputs_recorded` row (GH 1904; `null` when none). |
| `reviewer-eval.ts` | `node scripts/maintenance/reviewer-eval.ts [--db <path>] [--repo <dir>] [--repo-name <name>] [--base <ref>] [--json]`: the code-reviewer eval (GH 1955), to rerun whenever the code-reviewer's prompt, tools, model or effort changes. Prints `key=value` lines: the first-pass rate (tasks whose lowest-`attempt_n` `validation_attempts` row passed), the mean `attempt_n` of the first pass, the `wontfix` share of `review_findings`, escaped bugs from an SZZ trace (for each `Bug` issue created since the first review, its fix commits on `--base`, default `origin/dev`, that name `GH <n>`: the code lines each fix removes or changes, skipping docs, tests, `dist/` and changelog fragments, are blamed on `<fix>^`, and the `GH <n>` in each blamed subject maps to those issues' passed tasks whose `files[]` cover the blamed path and whose `completed_at` is at or before the blamed commit's committer date; bugs and traced tasks are limited to the repo `--repo-name` names, default the basename of the directory holding `--repo`'s git common dir, so a worktree resolves to its main checkout), known-clean tasks (passed first time and not traced), finding severity counts when the DB has the column, and one line per reviewer arm (the `model` and `effort` of the task's first code-reviewer `agent_runs` row). `--json` prints one JSON object instead. Opens the DB read-only (default: the one the server resolves) and reads it through `dist/reviewer-eval.js`, so build the server first; git runs in `--repo` (default: the cwd). Exits 2 on bad usage, a missing DB or a git failure. |
| `effort-inputs.ts` | `node scripts/maintenance/effort-inputs.ts --tasks <id,…> [--db <path>] [--repo <name>]`: the world-model effort inputs and suggested tier (GH 1904) of existing tasks, computed as at their creation through `dist/effort-inputs.js`, so the effort A/B can score tasks enrolled before `effort_inputs_recorded` rows existed. Prints one JSON line per task (`task_id`, `inputs`, `suggested_tier`, `reason`, `effort`; `error` for an unknown id). `--repo` picks the world model (default: each task's repo). Opens the DB read-only (default: the one the server resolves) and writes nothing; build the server first. Exits 2 on bad usage or a missing DB. |
| `wm-caller-recall.ts` | `node scripts/maintenance/wm-caller-recall.ts [--db <path>] [--repo <name>] [--repo-path <dir>] [--sample <n>] [--seed <n>] [--json]`: the world model's caller recall (GH 1988) — samples `--sample` (default 100) non-test TS/TSX function, method and class symbols of `--repo` (default `plugin`) with `--seed` (default 1988), takes each one's value references from the TypeScript language service (`findReferences`, one service per `tsconfig.json`), maps each to its innermost enclosing indexed symbol and compares that set with the symbol's world-model callers. Prints recall, precision and the misses by class (`unresolved`, `wrong_target`, `caller_not_indexed`, `no_edge`, plus `false_edge` extras) with up to 5 examples each as markdown, or the full per-symbol report with `--json`. Opens the DB read-only (default: the one the server resolves) and never writes the repo (default `--repo-path`: the repos row's path); reads through `dist/caller-recall.js`, so build the server first. Exits 2 on bad usage or a missing DB or checkout. |
| `stale-docs-eval.ts` | `node scripts/maintenance/stale-docs-eval.ts`: the replay eval of `cli.js stale-docs` (GH 1955) — runs the built check with `--head` on four past diffs whose code-reviewer findings were stale docs or comments, counts a finding as caught when a flag names its path and a line in its target range, and prints each finding caught or missed and each replay's flag count. Exits 0 only when at least 4 of the 8 findings are caught and the two ordinary replays (tasks 114 and 142) print at most 100 flags each, else 1; the two 380-file rename replays (tasks 180 and 182) report their flag counts uncapped; exits 2 when a case commit is missing from the local object store or the check fails to run. Build the server first. |
| `emit-data-contracts.mjs` | Regenerates `scripts/hooks/lib/data-contracts.json` (the SessionStart banner's copy of the contracts) from the built server; `npm run build` in `mcp/trajectory-server/` runs it. `--check` exits 1 when the committed file is stale. |

Three Human-run maintenance tools moved out of this folder into the trajectory server's CLI (GH 1692), run as `node --experimental-sqlite mcp/trajectory-server/dist/cli.js <subcommand>` from the plugin root or its cache copy (the bundle needs no `node_modules`): `heal-mcp-cache` (interactive remediation for the Claude Code plugin MCP-config cache bug, refuses to run inside Claude Code), `trajectory-doctor` (checks a trajectory DB against its data contracts on a query-only connection; the L5/L6 runners call it on the run's DB) and `backfill-agent-runs` (recovers `agent_runs` rows from transcripts still on disk; dry run by default). Their flags and exit codes are in each source's header under `mcp/trajectory-server/src/cli/`.

## How it fits

`bump-version.ts` backs the release/version-sync flow; the two `run-scan*.mjs` invokers let hooks refresh the world model without duplicating the MCP tool's scan logic; `emit-data-contracts.mjs` and `cli.js trajectory-doctor` carry the trajectory DB data contracts to the terminal, the test runners and the SessionStart hook. Scripts that call into the server (the `run-scan*.mjs` invokers, like the `cli.js` `backfill-agent-runs` and `trajectory-doctor` subcommands) resolve and check the DB path before importing any tool module (the invokers import `dist/run-scan.js` only then), so a missing DB exits 2 and creates nothing. None of them migrates: only the trajectory-server upgrades an older-schema DB, and any other opener throws on one and changes nothing (`docs/architecture/MEMORY.md#where-the-trajectory-db-lives`).
