# scripts/maintenance

Operational and one-off scripts that keep a TMB install healthy: version bumps, cache remediation, stale-worktree cleanup, and the standalone scan invokers fired by hooks. These are not part of the per-turn hot path — they run on demand (a person, a release flow) or as the body a hook shells out to.

## Files

| File | Purpose |
|---|---|
| `bump-version.sh` | Atomic plugin-version bump — updates the five files that must stay in sync (the Claude and Codex manifests, two package manifests, and the `bun.lock` workspace version) and assembles `## Unreleased` plus the `changelog.d/` fragments into the release's `CHANGELOG.md` section (deleting the fragments), or fails leaving every file unchanged. Operates on the checkout holding the script, whatever the cwd. `--dry-run` prints the section; `--date` sets its date; `--version-only` updates the five version files and leaves `CHANGELOG.md` and `changelog.d/` alone (CI dev builds). Idempotent. |
| `dev-build-version.sh` | Prints the dev-build version `X.Y.Z-dev.<n>[.gh<PR>]` for a commit (`--next X.Y.Z [--pr N] [--ref REF]`): `n` is the first-parent commit count since the highest stable tag, reachable or not, and `--next` must be above that tag. Operates on the cwd's repo. Run by `.github/workflows/dev-build.yml`. |
| `install-merge-driver.sh` | Writes the `tmb-regen` merge driver (keep ours for a generated artefact, name it on stderr) into one repo's `.git/config` — never the global config. With no argument it targets the main checkout of the repo holding the script, never the cwd. Run by the WorktreeCreate hook; idempotent. |
| `regen-generated.sh` | Rebuilds every generated artefact — `npm run build`, `gen-enums-doc.mjs --doc`, `emit-data-contracts.mjs`, and `gen-erd-doc.mjs` / `gen-config-keys-doc.mjs` when present. Run it after a rebase or merge; `--check` lists the stale files, puts the checked-out content back, and exits 1. |
| `lib/changelog-fragments.sh` | Fragment listing, parsing and validation shared by `bump-version.sh` and `tests/l1-lint/changelog-current.sh`. |
| `heal-mcp-cache.sh` | Interactive remediation for the Claude Code plugin MCP-config cache bug — clears stale `disabledMcpServers` entries and other recovery steps for the one installed channel (auto-detected, or `--channel stable|rc|dev` when several are installed). Refuses to run inside Claude Code; run it from a terminal. |
| `cleanup-stale-worktrees.sh` | One-time cleanup of repo-rooted SWE worktrees left over before worktrees moved to workspace-rooted paths. Idempotent. |
| `backfill-agent-runs.sh` | Recovers `agent_runs` rows from the Claude Code transcripts still on disk by calling the server's `agent_runs_backfill` tool as bro. Dry run by default (`--apply` writes; `--since`, `--transcripts-dir`); reads transcripts only and writes nothing but the project's trajectory DB. Idempotent. |
| `run-scan.mjs` | Standalone scan invoker used by the `post-task-close-rescan.sh` hook to re-run the scan against the current commit after an atomic close. Reuses the same `scan_run` logic as the MCP tool; silent on a scan failure. Opens only the DB named by `TRAJECTORY_DB_PATH` (the hook passes it; never discovered) and exits 2 without it; a DB that fails to open, such as an older schema it may not migrate, exits 1 with the error. Scans the project root given as its argument, else `CLAUDE_PROJECT_DIR`, never the working directory; with neither it exits 2. |
| `labels.mjs` | Keeps the repo's GitHub issue labels in line with `.github/labels.json` (TMB development only): `--sync` creates or updates labels and only reports extras, `--doc` rewrites the canonical tables in `docs/contributing/LABELS.md`, `--check` reports a stale doc offline, `--check-live` diffs against GitHub, `--triage <issue>` applies an issue form's Area answer and toggles `needs-triage`. Run by `label-sync.yml` and `issue-triage.yml`; tested by `tests/l1-lint/labels.test.mjs`. |
| `gen-enums-doc.mjs` | Generates what derives from `mcp/trajectory-server/src/audit-events.ts` (read through its compiled `dist/`): `--txt` writes `scripts/hooks/lib/audit-events.txt` (run by `npm run build`), `--doc` rewrites the `audit.event_type` table in `docs/contributing/ENUMS.md` between its generated markers, `--check` only reports which is stale (`tests/l1-lint/enums-doc-fresh.sh`). |
| `gen-erd-doc.mjs` | Regenerates the schema-derived part of `docs/architecture/ERD.md` between its `erd:generated` markers — mermaid erDiagram, per-table column tables, foreign keys with their `ON DELETE` action, FTS5 search indexes with their shadow tables, the index list, the eval-mode tables — from `mcp/trajectory-server/src/schema.sql` and `schema-eval.sql`, and keeps the doc's `schema_version` token equal to `TARGET_SCHEMA_VERSION` in `db.ts`. `--check` writes nothing and exits 1 when the doc is stale (`tests/l1-lint/erd-doc-fresh.sh`). |
| `gen-config-keys-doc.mjs` | Regenerates the key table in `docs/reference/CONFIG_KEYS.md` from the `plugin_config` keys the server and scripts read and write (plus the `schema.sql` seed for defaults); each key's type, setter and effect come from its `KEYS` entry in the script, and a key without an entry (or an unused entry) fails. `--check` reports staleness (`tests/l1-lint/config-keys-doc-fresh.sh`). |
| `run-scan-initial.mjs` | Mirror of `run-scan.mjs` for the cold-world-model SessionStart prescan, tagged with a distinct audit source; takes `TRAJECTORY_DB_PATH` and the project root the same way. Silent on a scan failure. |
| `trajectory-doctor.sh` | Checks a trajectory DB against its data contracts (`--db <path>`, `--ids a,b`, `--record`) on a query-only connection from `dist/` — no schema applied, no migration; prints the JSON report. Exits 1 when an error-severity contract fails or cannot run, 2 when the DB schema is older than the contracts need (start the trajectory server to migrate) or on a usage/DB error. `--record` writes the `trajectory_doctor_run` row through the `trajectory_doctor` tool handler, only on a DB at the server's schema version. The L5/L6 runners call it on the run's DB. |
| `emit-data-contracts.mjs` | Regenerates `scripts/hooks/lib/data-contracts.json` (the SessionStart banner's copy of the contracts) from the built server; `npm run build` in `mcp/trajectory-server/` runs it. `--check` exits 1 when the committed file is stale. |

## How it fits

`bump-version.sh` backs the release/version-sync flow; `install-merge-driver.sh` and `regen-generated.sh` keep rebases across the generated artefacts conflict-free (`docs/contributing/CHANGELOG_AND_REBASES.md`); `heal-mcp-cache.sh` and `cleanup-stale-worktrees.sh` are recovery tooling, as is `backfill-agent-runs.sh` for metering lost before v1.0.3; the two `run-scan*.mjs` invokers let hooks refresh the world model without duplicating the MCP tool's scan logic; `trajectory-doctor.sh` and `emit-data-contracts.mjs` carry the trajectory DB data contracts to the terminal, the test runners and the SessionStart hook. Scripts that call into the server (`backfill-agent-runs.sh`, `trajectory-doctor.sh`, `run-scan.mjs`) import `db.js`, resolve and check the DB path, and only then import a tool module, so a missing DB exits 2 and creates nothing. None of them migrates: only the trajectory-server upgrades an older-schema DB, and any other opener throws on one and changes nothing (`docs/reference/TRAJECTORY_DB_LOCATION.md`).
