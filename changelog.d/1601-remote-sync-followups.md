### Fixed
- **Issue sync names the real reason it skipped, and a renamed remote keeps its sync choice** (GH 1601): when the remote you asked for was not the one chosen at onboard, `issue_create` told you to fix remote URLs and `issue_update` said the issue had no remote link; both now report `not_synced` with a hint to re-run `/onboard` to change the Remote choice. Closing an issue whose repo cannot be resolved now reports `repo_unresolved` instead of `not_synced`. Renaming a git remote (same URL, new name) no longer switches its sync on or off on the next scan, and `scan_run` returns a `no_sync_remote` warning for a repo whose remotes all have sync off while issue sync is on.
