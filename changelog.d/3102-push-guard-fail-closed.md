### Fixed
- **The push gate judges what a push actually sends** (GH 3102): `git-push-guard` read the commits from the checkout's HEAD, so `git -C <repo> push origin <feature>` from a checkout on dev shipped an unreviewed feature; it now reads each push's refspecs (a branch, `HEAD`, a full ref, `+<src>:<dst>`, `--all`) and denies a refspec it cannot resolve. A task whose `commit_sha` was stored short (7+ hex) now matches the pushed commit, in the review check and the rebase check alike, and forced pushes (`--force`, `--force-with-lease`, `-f`) are judged like any push instead of skipped.
