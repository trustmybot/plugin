### Added
- **Release notes can say whether each change moved the metric it declared** (GH 2600): `bump-version.ts --impact-db <trajectory DB>` adds a `### Measured impact` section at the end of the release's CHANGELOG section, which the GitHub release notes carry. Each fragment that ends with a `Metric:` line is traced to the PR whose squash commit added it, and the change-impact CLI measures that PR. Each declared metric gets one bullet, for example ``- #<PR> `swe_rework_ratio`, expected lower: as declared (median ratio 0.80, 95% CI 0.65–0.95)``. The outcome reads as declared, moved the wrong way, did not move, or not enough data, and there is no ratio when there is not enough data. A fragment with no PR commit is skipped with a warning. If the CLI is missing or fails, the bump stops and changes no file. Without the flag the output is unchanged, and `--version-only` ignores it.
