### Fixed
- **The push gate denies a git command whose subcommand it cannot read** (GH 2634): `p=push; git $p origin dev`, `git "$@"`, `g() { git "$@"; }; g push`, `git ${p}sh`, `git $(echo push)` and `git -C . $p` read as "not a push", so a push from `.claude/worktrees/` went through. A git command now counts as no push only when its subcommand and every git option before it are written literally; an expansion, a brace or glob pattern, or a redirect there is denied as an ambiguous subcommand. An expansion in the argument of `-C`, `-c`, `--git-dir`, `--work-tree` or `--namespace` cannot move the subcommand, so `git -C "$W" status` and `git -C $(pwd) log` still pass while `git -C $W push` is judged as a push, and a command that names git next to an expansion, or spells `push` with quotes or a backslash (`git pu''sh`), is no longer skipped by the gate's quick text check.
