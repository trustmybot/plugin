### Fixed
- **Closing an issue's last task leaves the issue open until its commits merge** (GH 3234): `bro_atomic_close` and `task_recover` with `close_issue_if_last_task` closed the issue at task close, so an integrate that then failed to carry the review (exit 5) left a closed issue whose task `task_reopen` refused and whose `task_retry` landed under a closed issue. They now leave the issue open and return `issue_close_deferred: 'merge'` (or `issue_left_open` while work remains); the issue closes at merge (an in-session merge of the PR that names it) or through `issue_close`. They no longer return `remote`. When an issue was closed anyway, `task_reopen`, `task_retry` and a code-reviewer FAIL reopen it in the same transaction, write one `issue_reopened` audit row naming the cause and return `issue_reopened: true`; the remote twin is left as it is. A FAIL no longer reports `reopen_skipped: {reason: 'issue_closed'}`.
