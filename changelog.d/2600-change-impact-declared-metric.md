### Added
- **A change can declare the agent metric it means to move, and change impact says whether it did** (GH 2600): a `changelog.d/` fragment may end with `Metric: <metric id> lower|higher`. The fragment check accepts that line only as the entry's last line, in exactly that shape, with an id from the change-impact metric registry, and `bump-version` leaves it out of `CHANGELOG.md`. On dev builds, `change_impact` (the MCP tool, its CLI and the dashboard) gives each merged change a `declared` list with one `{metric, direction, outcome}` per declared line, read from git history so it still works after a release deletes the fragments. The outcome is `as_declared`, `wrong_way`, `not_moved` or `not_enough_data`, and the dashboard's Change impact table shows it as a badge, with `wrong_way` and `not_moved` marked for attention.
