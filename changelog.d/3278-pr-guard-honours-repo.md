### Fixed
- **`gh pr create --repo` and `glab mr create -R` are judged by the PR target of the repo they name** (GH 3278): the git guard applied the PR target of whatever repo the shell sat in, so a PR for one repo could be blocked by another repo's target and no base passed from every directory. A create naming `-R`/`--repo` now uses the policy of the registered repo whose `origin` remote that value names (`OWNER/REPO` matches any host; `HOST/OWNER/REPO` or a URL must match the host too), and gets no verdict when no registered repo matches. A value the shell fills in (`"$R"`, `$(gh repo view …)`) keeps the policy of the repo the shell sits in. Every PR or MR deny now names the repo whose policy it applied.
