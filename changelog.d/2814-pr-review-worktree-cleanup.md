### Fixed
- `pr_monitor_worktree` checks each call out into its own directory, `<repo>/.claude/worktrees/pr-review-<sha>-<suffix>`, created atomically with a unique suffix, so two overlapping calls on one commit (from one server or several) no longer delete each other's checkout (GH 2814). When `git worktree add` fails or times out, the call removes its own worktree, prunes git's record of it and deletes its directory if still left, then returns the `worktree add failed` error. A leftover `pr-review-*` directory from an earlier run no longer blocks a call and is left alone. The delete only ever touches a `pr-review-<sha>-<suffix>` entry directly inside `<repo>/.claude/worktrees/`, and a `worktrees` directory that resolves outside the repo is refused.
