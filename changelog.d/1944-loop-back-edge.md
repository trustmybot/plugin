### Security
- **A loop that reassigns a variable after using it as a write target is now judged on every value the variable takes** (GH 1944): the containment guard read a loop body once, top to bottom, so in `x=/w/a; while :; do echo > $x; x=/etc/p; done` it saw only `/w/a` and allowed a write that the second pass sends outside the project. Both write-path analyzers (the TypeScript one and `cmd-analysis.sh`) now run each `while`, `until`, `for` and `select` body over its own assignments until the variable values stop changing, so a later assignment in the body reaches an earlier use, nested loops included, and a `for` / `select` body written in braces (`for i in 1 2; { …; }`) or a loop run by `coproc` counts as a loop too. A value that keeps growing (`x=$x/a`) or that the analyzer cannot name (`read -r x`, `printf -v x`) makes the target unresolved, and the command is denied. A loop that keeps every target inside the project, such as `for f in a b; do x=$PWD/$f; echo > $x; done`, is allowed as before.
