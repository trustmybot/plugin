### Added
- **The world model knows what each file is for** (GH 1352): the kuzu graph gains `File` nodes (`path`, `repo`, `dir`, `purpose`, `purpose_source`, `content_md5`, `size_bytes`, `last_commit_sha`, `updated_at`) hung off their directory by `HAS_FILE` edges; an existing graph gains the tables on open and the next `/scan` fills them. `scan_run` gives each tracked file a one-line purpose read from its first 4 KB — a Python docstring, a leading comment block (`//`, `/* */`, `#`, `--`) or JSDoc `@file`, a markdown frontmatter `description` or H1 plus first sentence, a manifest `description` — and re-extracts only when the file's `content_md5` changed, so unchanged files keep their row and a purpose an swe wrote (`purpose_source='swe'`) survives edits; deleted files drop out. Structural directory summaries now read `<dir>/ — N files; name: purpose; …`. `world_model_get(path=<dir>)` lists that directory's `files` with purposes, the root call adds `coverage` (files, with purpose, by source), and `world_model_search` matches file purposes and paths too, tagging each hit `kind: 'dir'` or `'file'`.
