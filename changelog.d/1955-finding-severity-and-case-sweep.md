### Changed
- **Review findings carry a severity and a bug class, so only blocking ones cost a rework round** (GH 1955): each finding a code-reviewer records can now say whether it is `blocking` (the default), a `nit` or `pre_existing`, and name the bug class it belongs to. A `fail` verdict needs at least one blocking finding, and a `pass` can now carry nit and pre-existing findings, which stay on record without blocking the close. The close gate probes only blocking findings, and `task_brief` shows the swe only the open blocking ones, each with its severity and class; a `task_retry` carries only those over. The swe's completion report takes an optional `case_sweep`: each bug class it swept before close and the cases it checked. Schema v57 adds the two columns, and existing findings read as blocking; existing DBs upgrade on the next session start.
