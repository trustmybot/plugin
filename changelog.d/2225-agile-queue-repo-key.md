### Changed
- **One set of agile tasks awaiting review, kept apart per repo** (GH 2225): `review_queue`, `review_batch_handoff`, `review_batch_record`, `review_waive_record` and the feature-branch merge gate now read the same set of agile tasks awaiting review, and each repo keeps its own. A task counts when it is closed and queued but not yet batch-reviewed, waived or passed on its own, or when `cli.js feature-merge` folded it onto a feature branch and it was later reopened for rework. A reopened task keeps the merge gate shut. The waiver skips it, and the hand-off and the batch verdict refuse it, until it closes and is queued again. `review_queue` drops `grace_hours` and its old 30-day window, so it lists every task awaiting review, and a task with its own review pass leaves the list. Two repos can now use the same feature-branch name without mixing their tasks: groups never span repos, `review_waive_record` takes an optional `repo` (it is refused with `mixed_repos` when the branch's tasks span repos and none is named), and the merge gate judges only the repo the command runs in. A task with no repo on record counts for its issue's repo, in the queue and on a feature branch alike.
- **`review_batch_record` refuses a verdict after the feature branch moved** (GH 2225): unless the branch's current tip in the hand-off's repo is still the handed-off `head_sha`, it is refused with `head_moved` and writes nothing. A task that already has its own review pass at its current commit is refused with `already_passed`.
