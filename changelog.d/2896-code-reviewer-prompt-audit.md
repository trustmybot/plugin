### Changed
- **code-reviewer's prompt states its verdicts and keeps each rule in one place** (GH 2896): the agent file now names the three verdicts, `pass`, `fail` and `escalate`, with when to use each, and says `feedback` is a one-paragraph summary of the verdict and why. The MCP self-test paragraph is gone, since `validation_record` already refuses a code-reviewer call without `mcp_available`. A sibling the swe's case sweep missed now fails the review only when it breaks function; a gap in the sweep list alone is a nit. The agent description no longer claims code-reviewer is read-only on files; it says code-reviewer has no Edit or Write tool, which is what is enforced.
- **code-reviewer follows one review workflow** (GH 2896): it reads the brief and spec, reads the branch diff, then asks the world model for the callers, importers, table readers and tests of each changed symbol the target branch already has, and reads only the code those point to, with Grep as the fallback; a skipped walk or a world-model miss goes in `wm_feedback`.
