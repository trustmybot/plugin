### Changed
- **The bug report form asks for what makes a bug reproducible, and CLI-filed reports get labelled** (GH 2034): the GitHub bug form now has 12 fields: a one-line summary, expected vs actual, numbered repro steps with a worked example, an optional repro script, how often, the exact error, area, impact, environment, `trajectory_doctor` output, workaround, and two required checks (searched existing issues, no secrets in the report). The separate version field is gone because the environment block carries it. A report bro files from the CLI cannot set labels, so the triage workflow now adds `Bug` and the priority for its Impact answer when the issue has none, and never replaces a label already there.
