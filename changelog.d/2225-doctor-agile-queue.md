### Changed
- **`trajectory_doctor` counts agile tasks' pending reviews as a queue, not an error** (GH 2225): a task closed under `workflow_mode` `agile` has its code review queued until release, so `closed_tasks_reviewed` no longer counts it; a task stamped `truest`, or with no mode, is checked as before. The new warn-level `agile_review_queued` contract counts the agile tasks closed in the last 30 days and more than `TMB_REVIEW_GRACE_HOURS` (default 24) ago that have no passing review, bro-written waiver or allowed bypass, so its observed value is the size of the review backlog. Both contracts need schema v66 and are skipped on an older DB until the trajectory server migrates it.
