### Fixed
- **The world model now matches the commit a task branches from** (GH 2584): it used to index the main checkout's working tree, so a task brief could carry line ranges from a checkout many commits behind the swe worktree. Each repo is now indexed from git objects at its target commit (`origin/<target branch>`, else `HEAD`), and `repos.indexed_commit` records that commit. Every world-model read, every task spawn (`task_provision`, `task_reopen`, `task_retry`) and the startup catch-up compare it with the target and re-parse only the files the commit range changes, in one DB transaction. A NULL or unreachable stamp, an extractor or schema change, a mismatch row or `/scan` rebuilds the repo in full. A read that finds another session reindexing answers at once with `stale: true` on the files the range changes. Each reindex writes one `wm_reindex` audit row.
