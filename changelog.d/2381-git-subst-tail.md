### Fixed
- **The git guards no longer read the words after a substitution as a command** (GH 2381): in `echo $(true) cd /w/ok; git commit -m a`, the words after `$(…)` or a backtick are arguments of echo, yet the git guards followed the cd and judged the commit in `/w/ok` instead of the repo the shell runs it in, and `echo $(true) git commit -m 'ok'; git commit -m 'bad'` had the commit-message lint read `ok`. Those words are now no statement of their own for the git guards or the commit-message lint. A git command inside a substitution (`echo $(git push)`) or after `;`, `&&`, `||`, `|` or a newline is still checked.
