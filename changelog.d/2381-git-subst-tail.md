### Fixed
- **A `cd` after a substitution no longer moves the repo the git guards judge** (GH 2381): in `echo $(true) cd /w/ok; git commit -m a`, the words after `$(…)` or a backtick are arguments of echo, yet the git guards followed the cd and judged the commit in `/w/ok` instead of the repo the shell runs it in, and `echo $(true) git commit -m 'ok'; git commit -m 'bad'` had the commit-message lint read `ok`. A `cd`, `pushd` or `popd` in those words now changes no dir, and the commit-message lint reads the first commit that is not in them, falling back to one that is (`xargs $(true) git commit -m …`). The git guards still check those words as a command, since a command like `xargs` runs them: `xargs $(true) gh pr merge 1` is still caught, and `echo $(true) git push origin main` is still checked as a push.
