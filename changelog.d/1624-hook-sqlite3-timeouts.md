### Fixed
- **Hooks no longer fail with "database is locked" while another session writes, and the session-start scan stops warning about your other sessions** (GH 1624): several hooks and skill scripts called the `sqlite3` CLI with its default busy timeout of zero, so a read or write that landed while a second session's trajectory server was writing failed at once, and the hook quietly let a call through or blocked it. Every call now waits for the lock: reads go through the shared read helpers, the pr-reviewer validation fallback writes through the shared write helper, and a new lint fails any `sqlite3` call without a timeout. The SessionStart orphan scan no longer reports a live sibling session's server as a `lock-conflict` (SQLite WAL lets sessions share the DB), and it only flags servers whose Claude Code session is gone. It now also recognises Claude Code launched as `node .../claude`, from the native installer's `claude/versions/<v>` binary, from the npm package's `cli.js`, or from the desktop app. The sqlite3 fallback that writes when the server is down now allows consultants on audit and discussion entries, matching the server, and a lint fails if the two role lists drift apart.
