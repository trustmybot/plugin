### Fixed
- **Text in a heredoc or a quoted argument no longer trips the git and forge guards** (GH 1281): the statement splitter shared by every Bash guard drops heredoc bodies in every form (`<<EOF`, `<<-EOF`, `<<'EOF'`, `<<"EOF"`, several on one line, inside `$( )`) and treats `$'…'` as a quoted span, so a swe writing a test fixture that mentions `gh issue close`, or bro posting `gh issue comment --body "$(cat <<'EOF' … EOF)"` whose text says `cd x && git commit --amend`, is no longer denied. A `$( )` or backtick inside double quotes still runs, so its body is judged as statements of its own (`echo "$(gh pr merge 1)"` still denies) while the outer statement keeps the words after it. `tmb_gh_mutation` judges gh/glab at command position only — argv0 or the end of a wrapper chain (`timeout`, `xargs`, `sudo -u x`, `stdbuf`, …) — never an operand of a data command such as `echo`, `printf` or `grep`; every real gh/glab mutation, implied-POST `api` call and protected-branch git write still denies, and `cd X && git …` is judged against X.
