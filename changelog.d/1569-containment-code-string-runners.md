### Fixed
- **The containment guard judges the code a python program runs from a string, and denies exec / eval reached dynamically** (GH 1569): `cProfile.run('open("/etc/evil", "w")')` or a `cProfile.run` that rebinds a variable a later `open(p, 'w')` writes was allowed, as was `getattr(builtins, 'ex' + 'ec')(s)`. Module-level code-string runners (cProfile / profile `run` / `runctx`, pdb `run` / `runeval` / `runctx`, `timeit.timeit` / `repeat`, `compile`, under any import alias) are now scanned as the program's own code when every code string is a plain literal and are unresolvable otherwise; with any such call, a write through a variable is unresolvable too. `builtins` / `__builtins__` used as a value or by the literal name (`sys.modules.get('builtins')`, not a computed key), a builtin's `.__self__`, `__import__('builtins')`, and exec / eval / compile held in a variable or imported under another name are unresolvable. Profiler, tracer, debugger and Timer objects are always denied: any reference to `cProfile.Profile`, `profile.Profile`, `trace.Trace`, `pdb.Pdb`, `bdb.Bdb` or `timeit.Timer`, called, chained or not, is unresolvable, since the object reaches its runner in ways the guard cannot follow (`Profile().run(…)` returns the profiler, `type(t)` of a Timer is its class). So `with cProfile.Profile() as pr:` and `timeit.Timer('pass')` are now denied, as is a bare name passed to `timeit`. `dump_stats(path)` and the `filename` of `cProfile.run` / `runctx` count as writes. Use the module-level functions instead: `cProfile.run('main()')`, `timeit.timeit('sum(range(9))')` and a `timeit` lambda stay allowed; profile into a file with `cProfile.run('main()', 'out.prof')` and time a function with `timeit.timeit(lambda: f())`.
