### Fixed
- **Bro is metered per session instead of per task** (GH 1501): the `bro-turn-usage` Stop hook now keeps exactly one bro `agent_runs` row per Claude Code session (`task_id` NULL), rewritten with the session transcript's absolute main-loop sums on every Stop, with the first / last message as its window, the dominant model and the project as `root_dir`; a session with no real model or no output tokens (say, a lone API-error turn) gets no row. Before, it split each turn across per-task bro rows by time window, which left batch siblings and claimed rows closed with 0 tokens and no model. `task_provision`, `task_create_batch`, `task_reopen` and `task_retry` no longer open bro rows (they still accept `session_id`), `agent_runs_backfill` leaves bro rows alone, `task_stats` counts a task's swe and pr-reviewer runs only, and the `agent_runs_claimed` audit event is retired. The `populated_agent_runs_*` data contracts skip the per-task bro rows older versions left behind, and a new `bro_session_runs_metered` contract requires every session row to carry `session_id`, `model`, `tokens_out` and `usage_source`.
