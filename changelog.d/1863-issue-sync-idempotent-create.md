### Fixed
- **Retrying a lost issue create no longer opens a duplicate remote issue** (GH 1863): when `gh issue create` or `glab issue create` made the issue but TMB lost the result (a timeout, a non-zero exit with no output, no issue number in the output, or a failed read-back), every `issue_sync_retry` created another remote issue. Every remote issue body now ends with a hidden `<!-- tmb-issue:<id>:<created_at> -->` marker; the local description is unchanged. `issue_create` reports such a create as `outcome: 'unknown'`, and `issue_sync_retry` first looks for the marker on the remote (the newest 50 issues, then a search). It adopts a match, lowest number first, and reports any others as `duplicates`. If that lookup fails, it creates nothing and returns `lookup_failed`. Existing duplicates are left as they are.
