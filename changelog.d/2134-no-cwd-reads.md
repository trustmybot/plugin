### Fixed
- **Merge, attribution and verification hooks act on the right repo** (GH 2134): the attribution footer and the auto-close on merge called `gh` / `glab` in the hook's own directory, so a `cd <repo> && gh pr create` or `gh pr merge` from another directory read, edited or closed the same number in a different repo, or did nothing. The footer now targets the repo named by the URL in `gh` / `glab`'s own response, so no directory chooses it. The auto-close runs in the checkout of the `cd` leading the command's first non-blank line, else the session's directory, never a `git -C` target or a `cd` in a later line or heredoc body; a removed worktree resolves to its main checkout and a submodule stays on its own remote. Known limits of the auto-close: `cd /b && x && cd /a && gh pr merge` picks `/b`, a relative `cd ..` can resolve wrongly when the session's directory is already the post-`cd` one, and `gh pr merge -R other/repo` still reads the local repo. The verification gate asks `mise` for the toolchain of the task's worktree instead of the hook's directory. The other reviewed `no-cwd-reads` hits are recorded in the lint's allowlist, so that lint passes again.
