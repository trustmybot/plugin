### Fixed
- **Merge, attribution and verification hooks act on the right repo** (GH 2134): the attribution footer and the auto-close on merge called `gh` / `glab` in the hook's own directory, so a `cd <repo> && gh pr create` or `gh pr merge` from another directory read, edited or closed the same number in a different repo, or did nothing. They now run in the directory `gh` itself started in: the command's leading `cd` target, else the session's directory, never a `git -C` target. The auto-close uses that directory's checkout, so a removed worktree resolves to its main checkout and a submodule stays on its own remote. The verification gate asks `mise` for the toolchain of the task's worktree instead of the hook's directory. The other reviewed `no-cwd-reads` hits are recorded in the lint's allowlist, so that lint passes again.
