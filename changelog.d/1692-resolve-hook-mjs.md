### Changed
- **The headless shim's resolver is TypeScript, `resolve-hook.mjs`, not `resolve-hook.sh`** (GH 1692): `scripts/lib/resolve-hook.sh` is gone. `/onboard` now copies the bundled `mcp/trajectory-server/dist/resolve-hook.mjs` to `.claude/tmb/resolve-hook.mjs` and writes `node <project>/.claude/tmb/resolve-hook.mjs --marketplace <mp> --hook PreToolUse --shim --project <root>` entries, with the same flags, install lookup and `failing OPEN` warning as before. If a project uses headless enforcement, re-run `/onboard` (or turn headless enforcement on again) once: it replaces the `resolve-hook.sh` entries with `resolve-hook.mjs` ones and deletes the old `.claude/tmb/resolve-hook.sh`. Turning headless enforcement off removes both forms. With `node` off PATH the entry cannot start, which Claude Code treats as a non-blocking error, so the call goes ahead as before.
