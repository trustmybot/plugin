### Fixed
- **`cli.js integrate` rebases onto origin's latest base, not a stale local copy** (GH 2198): integrate compared the task commit against the local `<base>` as given, so a local `dev` behind origin passed the ancestor check and exit 0 printed an unrebased SHA. When the base names a branch and an `origin` remote exists, integrate now runs `git fetch origin <base>` first and rebases onto `origin/<base>` (falling back to the local branch); `origin/dev` and `dev` behave the same, and its messages name the ref it used. A failed or timed-out fetch exits 4 with nothing rebased or recorded. Repos with no `origin`, and SHA or tag bases, work as before.
