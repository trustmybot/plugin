### Fixed
- **`W=<path>; git -C $W commit` keeps its dir past a quoted message and a data heredoc** (GH 1911): the git guards treated `W` as unknown after a statement such as `git -C $W commit -m "a (b)"` or `git -C $W commit -F - <<EOM`, then denied with `ambiguous_git_target` in a repo with worktrees. Quoted or escaped `( ) < >` and backticks now count as data. A heredoc counts as data when its delimiter is quoted, or when its body has no backtick and no `$` other than a plain `$NAME` or `${NAME}`. The bash and TS analyzers apply the same rule. A quoted `$( )`, `$(( ))`, `${W:=…}` or backtick, and a heredoc body that can expand, still make `W` unknown.
