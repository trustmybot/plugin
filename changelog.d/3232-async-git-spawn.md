### Changed
- **A slow git fetch or worktree step no longer freezes every other lane** (GH 3232): the MCP server serves every lane from one process, and its long-running git calls (the base fetch and worktree add/remove of `task_provision`, `task_reopen` and `task_retry`, the world-model fetch after a forge merge and its origin check, the checkout-lag count on every world-model read, and the `/onboard` git and CLI probes) used to block that process until git exited. They now run without blocking it, so other tool calls keep answering while one waits on git. `/onboard` finds `gh` and `glab` on `PATH` without starting a shell. Results are unchanged, except that a base fetch that times out now reports how long it ran instead of a raw `ETIMEDOUT`.
