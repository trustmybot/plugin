### Fixed
- **Test runs never spawn the real `claude` CLI, and L4 flows get a 30 s per-test timeout** (GH 1309): `scripts/scan.sh` ran `claude plugin list --json` on every scan, so the `scan_run` unit tests reached the live CLI and `tests/run-all.sh` had to keep its `claude` stub non-recording. Under `TMB_FORBID_LIVE_SYNC=1` scan.sh no longer spawns `claude`: it reads the plugin list from the file `TMB_SCAN_PLUGIN_JSON` names, else records the plugin inventory as unavailable. Its JSON gains `plugin_inventory: {status, note}` (`cli`, `fixture`, `unavailable` or `skipped`), which `scan_run` returns and, when unavailable, appends to the `deep_scan_completed` summary. The `scan_run` unit tests run against a two-plugin fixture with their own trajectory DB, and one asserts that without a fixture no `claude` process starts. `tests/run-all.sh` now stubs `claude` like `gh`/`glab` (every call recorded, a recorded call fails the step), exports an empty plugin-list fixture for L2 and L4, and runs every L4 flow with `bun test --timeout 30000` (flow-10 failed once on bun's 5 s default during a loaded full run). The `no-tmp-writes.sh` self-test stubs `claude` the same way.
