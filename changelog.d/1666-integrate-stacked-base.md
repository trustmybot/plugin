### Fixed
- **integrate.sh rebases a branch stacked on a squash-merged parent instead of reporting patch drift** (GH 1666): when a task's branch was cut from another branch that was later squash-merged into the base, `integrate.sh` compared patch-ids over a range that still held the parent's original commit, which the rebase had dropped as already applied, and exited 2 although the task's own change was intact. Both sides now list the commits a rebase picks, skipping those already in the base, so the stacked branch integrates and verifies normally. A task whose change is already in the base still exits 2, now with a message saying so.
