### Changed
- **bro drives agile mode with `cli.js feature-branch`** (GH 2225): bro reads each task's mode from its repo's `effective_mode` in `repos_list`, and for a task in an exempt repo makes no review hand-off and spawns no code-reviewer. bro now cuts, syncs, drops and cleans up a milestone feature branch with `feature-branch cut`, `sync`, `drop` and `cleanup` in place of raw git, and checks for a remote before every push, keeping the branch local when the repo has none. A sync conflict goes to the Human: bro reads what each side changed, then asks the Human how to resolve each path. The prompts now say that a closed agile task still queued can be handed to code-reviewer on request, that a failed lint or suite at the batch hand-off becomes a fix task, that a failed group is handed off again once its fix lands, that a waiver covers only the closed tasks of one named repo queued when it is recorded, and that a docs or prompts task bro writes itself gets the doc-review self-check and is queued with no code-reviewer pass. Dropping a feature branch deletes it only when the Human says so, and cleanup runs once the milestone PR has merged.
