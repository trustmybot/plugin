### Fixed
- **Inline programs can no longer write the environment after passing it around** (GH 2490): the containment guard proved `python3 -c` and `node -e` programs that put `os.environ`, `sys.argv`, a standard stream, `process.env` or `process.argv` into a container, a function argument, a loop variable or a return value and wrote through the name that received it (`e=[os.environ][0]`, `e,f=os.environ,1`, `f(os.environ)`, `for e in [os.environ]`, `const [e]=[process.env]`, `[process.env].forEach(e=>…)`, `const o={e:process.env}`, `JSON.stringify(process.env,(k,v)=>…)`), and wrote through `(os.environ).update(…)`, `(process.argv).push(…)` and `const g=this`. Such a value is now proven only as the base of an attribute or subscript, an alias to a plain name, a loop iterable, a spread, a comparison operand, the whole right side of a destructuring or unpacking of `os.environ`, `sys.argv`, `sys.stdin`, `process.env` or `process.argv`, or an argument to a closed set of calls that keep nothing (`print`, `len`, `dict`, `json.dumps`, a string's `join`, `console.log`, `JSON.stringify`, `Object.keys` and the like); every other use is unproven, and so is `this` in a node program. `print(os.environ)`, `for k in os.environ`, `"HOME" in os.environ`, `_,*a=sys.argv`, `" ".join(sys.argv)`, `console.log(process.env)`, `{...process.env}`, `const {HOME}=process.env` and `const [,,...args]=process.argv` still prove.
