### Fixed
- **`issue_adopt_remote` works on a repo-less issue in a multi-repo workspace** (GH 1368): with the issue's repo NULL and several repos registered, adoption spawned `gh issue view` with no cwd and no `--repo` and reported `remote_verify_failed`. It now takes an optional `repo` (a `repos` row name; an unknown name returns `repo_not_found`), verifies against that repo's path and remote, and backfills the issue's null repo on success; without it, the call returns `repo_unresolved: issue <id> has no repo and the workspace has N repos — pass repo` before spawning anything. A single-repo workspace still resolves without the argument.
