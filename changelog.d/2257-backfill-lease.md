### Fixed
- **Several sessions on one project embed its history once, not once each** (GH 2257): every trajectory-server re-embedded the same rows at boot, so 4 sessions on one DB ran 4 identical backfills at about 65% CPU each. The boot backfill now holds a lease, the lock dir `<db>.backfill.lock`, whose holder refreshes it every 60 s; a server that finds it held skips its boot backfill and logs `embeddings_backfill_skipped` with `reason: 'lease_held'` to `mcp-server.log`. A lease left by a crashed server goes stale after 5 min and the next boot takes it over. Each backfill also re-checks every batch of 50 rows and skips the rows another server embedded meanwhile.
