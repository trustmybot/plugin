### Fixed
- **A symbolic link created inside the worktree is no longer denied because its target is outside** (GH 1789): the containment guard judged `ln -s TARGET LINK` by TARGET, so `ln -s <main checkout>/node_modules node_modules` in a worktree was denied although it only creates `node_modules` there. A symbolic `ln` is now judged by the link it creates: the last operand, the `-t` / `--target-directory` directory, or `./<name of TARGET>` for a single operand, under any `cd` before it. TARGET is still judged, fail-closed, when another statement follows the `ln` in the same Bash command (`ln -s /out link && echo x > link/f`), when something may run after it (a background job, a `trap`, a process substitution), inside a `bash -c` / `eval` body, for a hard link (no `-s`), and when an option word comes after an operand (BSD `ln` reads it as an operand). A write through a link that already exists still resolves to its outside target and is denied, from Bash and from Write / Edit.
