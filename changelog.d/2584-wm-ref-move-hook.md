### Added
- **The world model catches up when a Bash command moves the target branch** (GH 2584): after `git fetch`, `git pull`, `git push`, `gh pr merge` or `glab mr merge`, a new PostToolUse hook checks each repo the command touched. When the repo's indexed commit is not `origin/<target branch>` (else `HEAD`), it starts the reindex in a detached background process and returns at once, so the next world-model read finds the index current. A PR merged through `gh` or `glab` moves only the remote, so its reindex first fetches the target branch (5 s cap). The fetch is skipped when swe or code-reviewer ran the merge. Words inside a heredoc or a quoted string never trigger it. A failed command, or a repo another session is reindexing, is left for the next read. The reindex is recorded with trigger `hook` in its `wm_reindex` audit row and in `wm_freshness`. `TMB_SKIP_AUTO_RESCAN=1` turns the hook off.
