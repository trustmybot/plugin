### Changed
- **code-reviewer's review skill puts the fail bar first and no longer contradicts it** (GH 2897): the `tmb_review` skill now leads with the records, the fail bar, grading and the three verdicts (`pass`, `fail`, `escalate`, each with when to use it, plus what `feedback` holds), then the review questions, with worktree, re-review and row-writing mechanics last. The lines that called a missing run, a weak test record, a `not_met` criterion or a missing `Populated:` sample an automatic fail now each make a finding that the fail bar grades, with the probe to record named. Rules the server enforces are gone from the skill: the spawn preflight refuses a commit with no passing verification run, and `validation_record` refuses a pass without probes. The skill spells verdicts one way, states each rule once, gives three example `probe_cmd`s, and says the fallback is for when the MCP server is down. Its description and tool list now match how code-reviewer loads and uses it.
- **`validation_record` refuses a pass without a passing verification run** (GH 2897): a `pass` now needs the task's newest verification run at its commit to have exited 0 without timing out, in the MCP tool and the fallback CLI alike, so the rule holds even when the code-reviewer preflight is bypassed. The refusal, `verification_run_required`, names what it found: no commit, no run, a run at another commit, a timed-out run or a failed one. `fail` and `escalate` need no run.
- **code-reviewer judges whether the diff breaks other behaviour, not whether it meets its spec** (GH 2897): the agent file and `tmb_review` skill now follow the quality-layer split, where swe owns functionality through its recorded checks and criterion report and bro owns intent and design. The reviewer no longer re-asks whether the diff does what the spec says, records no finding for fit, design, placement or complexity, and passes when every criterion's record proves it.
