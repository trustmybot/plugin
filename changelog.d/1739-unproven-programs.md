### Security
- **Inline programs the guard cannot prove are denied** (GH 1739): the containment guard used to allow a `python3 -c`, `node -e`, `perl -e` or `ruby -e` program (or one on stdin) unless it spotted a write call it knew, so an unknown writer or a write callable held in a name slipped through. It now allows such a program only when every call is a write it can place or sits in a small read-only safe set (printing, reading files, string and JSON helpers, and the like). Anything else is denied as unproven, as is a stdin program whose text the shell fills in, an `eval` of a non-literal, and a command word that is a variable. Some harmless one-liners outside the safe set are now denied; use Edit or Write, a plain read-only one-liner, or a script file instead.
