### Fixed
- **`issue_adopt_remote` reports the real reason it refuses** (GH 2772): adopting a GitHub or GitLab iid onto an issue already linked to a different iid ran `gh`/`glab issue view` first, so a transient CLI failure surfaced as `remote_verify_failed ... (not_found_or_error)` for an issue that exists. The link conflict is now checked before any CLI call and returns `already_linked`. When verification does fail, the reason carries the CLI's first stderr line (`not_found_or_error: HTTP 401: Bad credentials`), so an auth or network error no longer reads as a missing issue.
