### Fixed
- **Codex project tools no longer fail with a false `project_state_not_ignored` on a busy machine** (GH 1523): every Codex tool call re-checks the project with three local `git` commands, and any command still running after 5 seconds was killed and read as "the project does not ignore `.tmb/`", so `project_inventory` (and any other tool) could fail on a correct project when the machine was loaded, as in the full test suite under the close gate. Each `git` check now gets 60 seconds, and one that runs past that is stopped and reported as the new error code `project_validation_timeout`, naming the command and the limit, instead of a false verdict about the project; the existing guards (no prompts, hooks, fsmonitor or global config) stay. The local-only scan test now asserts that `project_inventory` succeeded before reading its data, so a failure names the tool's error.
