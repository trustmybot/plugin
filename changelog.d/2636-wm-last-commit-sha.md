### Fixed
- **The world model's last commit per file now matches git log after a merge** (GH 2636): when a merge brought in a side-branch commit that touched a file without changing its content, for example by adding a byte-identical copy, an incremental reindex kept the file's older `last_commit_sha` while a clean rebuild names the side commit, and an ordinary scan never corrected it because the content hash had not changed. An incremental reindex now gives each path the range's git log names whichever of the range's commit and the stored one `git log` lists first, the commit a clean rebuild names whichever branch's commit is newer by date, and a scan writes a new commit sha onto a row whose content is unchanged.
