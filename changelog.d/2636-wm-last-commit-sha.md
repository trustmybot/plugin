### Fixed
- **The world model's last commit per file now matches git log after a merge** (GH 2636): when a merge brought in a side-branch commit that touched a file without changing its content, for example by adding a byte-identical copy, an incremental reindex kept the file's older `last_commit_sha` while a clean rebuild names the side commit, and an ordinary scan never corrected it because the content hash had not changed. An incremental reindex now takes `last_commit_sha` from the range's git log for every path it names, and a scan writes a new commit sha onto a row whose content is unchanged.
