### Changed
- **`/onboard` no longer asks about headless enforcement** (GH 1574): the round that offered to gate non-interactive `claude -p` runs is gone, so a new project answers one question fewer. `onboard_get_questions(round='headless')` now fails with `unknown round 'headless'`; the `headless_enforcement` setting, the shim it writes and a stored `yes` all stay as they were.
- **Headless enforcement is offered when you ask for it** (GH 1574): mentioning `claude -p`, headless or CI runs on an onboarded project makes bro ask one consent question naming `.claude/settings.local.json` and the number of entries it adds; on Yes, `onboard_apply(headless_enforcement='yes')` turns it on without re-running `/onboard`. Set `TMB_DISABLE_HEADLESS_HINT=1` to silence the prompt.
- **The Bash sandbox question says exactly what it writes** (GH 1574): it names `.claude/settings.local.json` in this project and every key it sets (`sandbox.enabled`, `sandbox.filesystem.allowWrite`, `sandbox.network.allowedDomains`, `sandbox.enableWeakerNetworkIsolation` on macOS, `env.npm_config_cache`, `env.BUN_INSTALL_CACHE_DIR`), and the Yes and No answers are described in plain words.
- **`.claude/settings.local.json` stays out of your commits** (GH 1574): when the sandbox or the headless shim creates that file in a git work tree that does not already ignore it, TMB adds `.claude/settings.local.json` to the project's `.gitignore`. A file that already existed, a path git already ignores, or a project outside git leaves `.gitignore` untouched; the sandbox result reports `gitignore_appended`.
