### Added
- **The world model remembers how things work, and says when that memory goes stale** (GH 1680): bro and consultants can now save a concept with `world_model_concept_upsert`: a named flow, subsystem or invariant written as ordered steps, each pinned to a function, hook or file and saying how it hands off to the next. A concept is saved only when every step points at code that exists and every claim about it (for example "A calls B" or "only these files write this table") holds. After each `/scan`, a step whose code changed is marked `suspect` and one whose code is gone `broken`, and the concept says which step it was. `world_model_concepts` finds concepts by name, description or step text; when none match, it returns a chain walked from the best-matching function through what it calls, labelled `derived, unverified`. `world_model_concept_get` shows one concept's steps in order. The index also gains the hooks in `hooks/hooks.json` in the order Claude Code runs them, fuller doc comments, and calls that resolve once their target is added, moved to another file or re-created under a new kind, without re-parsing the caller. ADR 0002 records the design. Schema v45 adds the concept tables; the first `/scan` after upgrading re-parses every file.
