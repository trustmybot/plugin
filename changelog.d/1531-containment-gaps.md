### Security
- **The containment guard catches more writes and no longer reads file content as write targets** (GH 1531): `git bisect`, `submodule update`, `sparse-checkout`, `read-tree -u`, `checkout-index`, `mergetool` and `init <dir>` now count as writes, as do the `-o` / `--output` of `git format-patch` and `git archive`. In inline python / node / perl / ruby programs, `os.truncate`, `zipfile.ZipFile(p, 'w'|'a'|'x')` and process calls (`subprocess.run` / `call` / `check_call` / `Popen`, `os.system`, `execSync`, `spawnSync`, `system`, backticks) are write calls, recognised under import aliases too. A process call is judged as the shell command it runs, its `cwd=` a leading `cd`, so `subprocess.run(['rm', '-rf', '..'])` and `os.system('cd .. && …')` are judged where they land; an argument that is not a literal, or a process function the program reaches some other way (`f = subprocess.run`, `getattr(os, …)`), fails closed. A write target that leaves the root with `..` and comes back in (`cd .. && rm -rf <worktree-name>`) is denied. Each wrapper (`sudo`, `env`, `time`, `exec`) skips its options by its own table, so `sudo -S rm /etc/x` is judged on `/etc/x` and `sudo -C 5` takes an fd number. Text a program writes (`write()`, `write_text()`, `writeFileSync` data, …) is content: a file whose text mentions other paths is judged, and scope-noted, on its own path only; a write path the scan cannot resolve still fails closed.
