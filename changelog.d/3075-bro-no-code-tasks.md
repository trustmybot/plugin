### Added
- **bro edits docs and prompts itself, in a no-code task's worktree** (GH 3075): `task_provision` takes an optional `task.no_code_class` (`docs` or `prompts`), stored on the task and kept by `task_retry`. bro may Write or Edit a repo file only inside the worktree of a running task that has a class, and only on a path that `.config/tmb/path-classes.json` classes as docs or prompts. The classes are read at the task's base commit, so the task cannot widen its own limits. Code paths, tasks without a class, and edits in the main checkout are refused, and the refusal names swe. This includes Markdown and docs files in the main checkout, which bro could edit before. The path is resolved first, so a `..` path out of a worktree is judged where it lands. Scratch writes keep their rules everywhere. Files outside every registered repo (such as auto-memory) and files git ignores keep their rules too, except under `.claude/worktrees/` inside a git repo: there bro's write is refused unless it is proven to sit in the worktree of a running no-code task, which includes refusing it when the trajectory DB cannot be read or cannot show which task owns the worktree. When bro closes such a task, the same checks run as when swe closes a task: its verification commands and close lints, recorded for the commit. Every path the task itself changes, measured from where it branches off its PR target (so dev commits merged into the branch do not count), must also be docs or prompts; a code or mixed change is refused, with its code paths listed. swe, consultants, and closes of tasks without a class behave as before.
