### Changed
- **`TMB_DISABLE_PREPUSH_INSTALL=1` is never silent and fails safe** (GH 3281): with the switch set, session start prints one notice that names it and `cli.js prepush-uninstall`, and removes TMB's pre-push hook from every repo it would install in, so no live hook remains. The command-text push judge stays on. Only you can set the switch: an agent's command that names it, or an agent's edit that writes it into the session's environment file, a `.claude` settings file or a shell profile, is denied. Reading it with a plain `grep`, `rg`, `git grep`, `cat`, `printenv` or `echo` still works.
- **The hook-skip guard denies fewer forms, and each deny shows the fix** (GH 3281): a double-quoted `-C`, `--git-dir` or `--work-tree` value now passes on any git command, a push included (`git -C "$WT" push`). So does a `git config` write with a literal key and double-quoted values (`git config user.name "$NAME"`). An unquoted expansion in a git global option's value still denies on every git command, because bash may split it into another subcommand, and the deny prints your command with that expansion double-quoted (`git -C "$WT" status`). A push with any other expansion still denies. A `git config` read with a variable now allows only `--global`, `--local`, `--system`, `--worktree`, a literal `--type=<t>`, or `-f`/`--file` with a literal or double-quoted path before its read form (`git config --type=bool --get "$K"`, `git config -f "$F" --list`); any other option or variable there denies, since it could turn the read into a write. Each deny the guard makes because it cannot read a command literally is recorded as a `prepush_observed` row with its masked command form.
