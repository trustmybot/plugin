### Changed
- **Dev merges no longer wait on the release gate** (GH 1604): CONTRIBUTING drops the feature-branch and post-merge `dev` dispatches of release-gate. CI-affecting PRs to `dev` are validated by the local sweep, pr-reviewer and any PR checks; release-gate runs only when cutting an rc, and `main` still needs a green rc gate.
- **release-gate is rc/main-only in CI** (GH 1604): a new `ref-guard` job refuses `workflow_dispatch` from any ref other than `rc` or `main`, so the heavy jobs never run on a feature branch or `dev`. The pre-tag dispatch now runs from `rc` (`gh workflow run release-gate.yml --ref rc`) after fast-forwarding it to the candidate, and the rc tag push inherits that same-SHA verdict.
- **Dev builds announce themselves on their PR** (GH 1604): `dev-build.yml` comments the stamped version, the dev-build commit and the upgrade commands (`claude plugin marketplace update trustmybot-dev`, `claude plugin update tmb@trustmybot-dev`) on the PR that produced the build; a failed comment only warns. CONTRIBUTING documents the upgrade under Dev builds.
