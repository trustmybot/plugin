### Fixed
- **A session opened in a subdirectory of a TMB workspace uses the workspace's trajectory DB** (GH 1553): the server and the hooks now share one rule. They walk up from `CLAUDE_PROJECT_DIR` (else the cwd) toward `/`, stopping before `$HOME` unless the session starts there. The nearest DB whose state dir holds a `standalone` file wins; otherwise the outermost DB wins. A fresh DB is created only when none resolves, so `<ws>/a/b/.claude/tmb/` is no longer created next to `<ws>/.claude/tmb/`. The project root is the dir that holds the resolved DB, and a relative `repos.path` now resolves against it on both sides. A new `trajectory_doctor` contract, `no_other_trajectory_dbs`, lists every other trajectory DB under the project with its issue and task counts. `/onboard` opens with a Round 0 when the session is nested below the workspace: keep the workspace DB, make this directory its own standalone project, or cancel; empty stray DBs can be removed, but never a standalone project or one reached through a symlinked directory. In a nested session the containment guard still lets bro write Claude Code's auto-memory, which Claude Code names after the session directory. Two new audit events record these choices: `stray_db_removed` and `project_made_standalone`.
