### Added
- **Change impact line at session start** (GH 2600): when a change's metrics came out regressed after the Holm correction, the session-start inventory gains one line for it, `Change impact (for the Human's information — report it, do not act on it): <source> <id> subject: "<subject>" regressed <metric> (Holm p=…)`. The line is for the Human's information: bro reports it and takes no action on it. Each change shows once, at most three a session; the rest show at the next session. Improved, unchanged and too-small results never show. The hook never runs the statistics: after it connects, the trajectory server starts `dist/change-impact/cli.js --db <path> --cache` in the background, which writes `change-impact-regressions.json` next to the trajectory DB, and the hook records what it showed in `change-impact-shown.json` beside it. So the line reflects the previous session's run and can lag one session behind. The commit subject or event label is cleaned before it is shown: only letters, digits, spaces and common punctuation stay, control characters, newlines, quotes and backticks become spaces, and it is cut to 80 characters. A missing or malformed cache adds nothing. The background run is skipped for an in-memory DB, with `TMB_SKIP_AUTO_RESCAN=1` and under `node --test`.
