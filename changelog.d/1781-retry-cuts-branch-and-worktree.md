### Fixed
- **A retried task is ready for swe as soon as `task_retry` returns** (GH 1781): `task_retry` used to insert the new task without creating its branch or worktree, so the swe spawn gate refused it until someone ran git by hand. It now cuts the branch the way `task_provision` does: from the failed task's parent branch, else the repo's target branch, else its default branch. It then adds the worktree and returns `git_setup`, `base_ref` and `worktree_path`. If the base can't be resolved, or `new_branch_id` already exists and has diverged from the base, the retry is refused and no task is created. `task_reopen` now also creates a branch that exists neither locally nor on origin, cutting it from the task's base instead of failing in `git worktree add`, and reports this as `branch_created`.
