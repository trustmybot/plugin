### Fixed
- **Review verdicts are never overwritten, and the newest verdict gates the push** (GH 2412): a code-reviewer spawned with an `attempt_n` that already had a row used to replace it, so a later pass could erase an earlier fail and its open findings. `validation_record` and `cli.js validation-record-fallback` now only append: a reused `attempt_n` is stored as the task's highest attempt + 1, the earlier row and its findings stay as they were, and the result and return line name the stored attempt. An honor-system call (`mcp_available: false`) no longer fails with `verified_verdict_exists`, since it can no longer overwrite anything. The push gate, the close paths and worktree cleanup count a task as reviewed only when its newest verdict is a pass: an older pass under a newer fail or escalate no longer lets the task through.
