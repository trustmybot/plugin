### Fixed
- **commit-msg-lint, clean-merged-branch and remote-id-guard read a keyword or `#N` however bash spells it** (GH 2787, GH 2143): a `commit`, `merge` or `#N` written in `$'…'` escapes or split by a line continuation slipped past them, since each read the raw command text. They now read it as bash does, so `git $'\x63ommit' -m 'bad'` is linted, `gh pr $'\x6derge' 5` cleans up its branch and `--body $'Closes \x2310'` is checked. remote-id-guard also judges a bare `#N` against the repo the `gh`/`glab` command targets: `--repo`/`-R` names it, else the dir it runs in. A `#N` in a PR for another registered repo is no longer mapped to this repo's local issue, and a `--repo` that names no registered repo is let through.
