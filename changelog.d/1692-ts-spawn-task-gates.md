### Changed
- **The task-DB Agent-spawn gates have TypeScript versions, checked against the bash ones** (GH 1692): `require-task-spec`, `require-spawn-effort` and `require-feature-branch-active` now also live in `mcp/trajectory-server/src/hooks/` and are listed in `dist/hooks-gates.txt`. `agent-spawn-dispatch.sh` still runs the .sh versions, so nothing changes at runtime yet. `tmb_effort_defaults` is ported as `effortDefaults` in `src/hooks/lib/effort.ts`. A corpus in `tests/fixtures/hook-corpus/` runs each payload through both versions in the C and `en_US.UTF-8` locales against real git repos, worktrees and trajectory DBs. Both versions give the same exit code, stdout and stderr, byte for byte. The corpus has 25 payloads for `require-task-spec`, 19 for `require-spawn-effort` and 15 for `require-feature-branch-active`, and it covers the allow path and every deny branch. The three l3 suites pass against both versions; `TMB_HOOK_TEST_IMPL=ts` picks the TypeScript one.

  The TypeScript gates differ from the .sh only where the .sh skips its check because a CLI tool is missing (decision 703). Each difference has a unit test in `src/test/hooks-spawn-gates.test.ts` and a corpus payload marked divergent:
  - **They run without jq.** With no jq on PATH, `require-task-spec` and `require-feature-branch-active` allowed every spawn, and `require-spawn-effort` denied every swe and code-reviewer spawn with "jq not found". The TypeScript gates read the payload with Node and decide as usual.
  - **They run without the `sqlite3` CLI.** With no `sqlite3` on PATH, all three .sh gates allowed every spawn. The TypeScript gates read the trajectory DB through `node:sqlite` and still deny a missing task row, a mismatched effort or a missing branch.
