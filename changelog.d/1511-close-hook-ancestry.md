### Fixed
- **A SWE that stops without committing no longer auto-completes its task when the local parent branch is stale** (GH 1511): `swe-atomic-close` counted any difference between the worktree HEAD and `refs/heads/<parent>` as commits, so a worktree provisioned from `origin/<parent>` while the local `<parent>` lagged behind auto-completed at its base sha on the first SubagentStop. Commits are now counted by ancestry: the worktree has commits only when its HEAD is neither equal to nor an ancestor of any parent tip that exists, local or origin; the same rule covers the local feature ref, the empty-`parent_branch_id` base and the no-worktree checkout. Every auto-complete now writes one `swe_atomic_close_auto_completed` audit row carrying `task_id`, `commit_sha`, `parent_tip_local` and `parent_tip_origin`, so a wrong auto-complete is visible.
