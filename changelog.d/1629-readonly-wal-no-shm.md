### Fixed
- **bro's read-only fallback reads the trajectory DB after a clean shutdown or a copy** (GH 1629): when the trajectory server was down, `bro-sqlite-readonly.sh` opened the DB with `sqlite3 -readonly`, which cannot open a WAL database whose `-shm` file is missing, so reads came back empty. It now reads such a DB from a private `VACUUM INTO` snapshot in a scratch directory that is removed on exit, so rows still in the `-wal` come back and the DB and its `-wal` are left untouched. A snapshot that fails prints the sqlite error and exits non-zero instead of returning an empty result.
