### Changed
- **Long output of bro's routine reads is trimmed** (GH 2193): a new PostToolUse Bash hook, `bash-output-trim`, cuts the stdout of bro's main-thread read commands when it is longer than 4000 characters. It keeps about 2400 characters from the start and 800 from the end, and puts one line between them saying how much was cut and how to get the rest. A read is a chain of `cd`, `NAME=value` and read pipelines joined by `&&`, `;` or newlines. The pipelines start with `git log`/`status`/`diff`/`show`/`grep` and the other git read verbs, `gh {pr,issue,run} {view,list,checks,diff}` (including `--json`/`-q` output), `sqlite3 -readonly` SELECT queries, `rg`, `ls`, `echo` or `cat`. They pipe only into filters such as `head`, `grep`, `sort`, `jq` and print-only `sed -n`. Commands with a substitution, a file redirect, a heredoc or a write (`sed -i`, `sort -o`, `git diff --output`) are never touched, and neither are subagent calls or calls with stderr.
