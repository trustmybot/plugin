### Fixed
- **`cheatcode_install` can now grant an already-registered cheatcode to a new agent** (GH 2121): when the cheatcode was already registered (for example a plugin found by reconcile), passing a target used to return an idempotent no-op and drop the target, so a plugin like typescript-lsp could never be granted to swe as `LSP`. Now a target with no attachment yet goes through the same approval and project-containment checks, materializes the project's `.claude/agents/<target>.md` (or `.claude/CLAUDE.md` for bro), records the attachment and an audit row, and returns `attached: true` with `materialized`. With no target, or a target already attached, the call is still a no-op, and the registered row itself is left unchanged.
