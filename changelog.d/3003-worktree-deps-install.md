### Fixed
- **A task that adds a dependency now verifies against it** (GH 3003): `cli.js integrate`, `pr_monitor_worktree` and the task environment gate now run the install per installed lockfile root whose manifests differ. Each dir holding a lockfile that the main checkout installed (it has a `node_modules` there) is an install root for the package dirs nearest beneath it, so a lockfile dir main never installed, such as a test fixture, never gets an install; when its lockfile or any `package.json` in that group differs from the main checkout's, the lockfile's frozen install (`bun install --frozen-lockfile`, `npm ci`, `pnpm install --frozen-lockfile` or `yarn install --frozen-lockfile`) runs in that root instead of linking the main checkout's `node_modules`, which lacked the new package. Every other package dir, such as a nested app with its own lockfile that the change left alone, still links the main install. A failed install stops `cli.js integrate` with exit 1 and the branch unmoved, and makes `pr_monitor_worktree` return `passed: false` naming the root, the command and its output; the environment gate goes on to its setup stage.
