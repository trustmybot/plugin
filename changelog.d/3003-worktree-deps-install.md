### Fixed
- **A task that adds a dependency now verifies against it** (GH 3003): when a worktree's lockfile or any `package.json` differs from the main checkout's, `cli.js integrate`, `pr_monitor_worktree` and the task environment gate run the lockfile's frozen install (`bun install --frozen-lockfile`, `npm ci`, `pnpm install --frozen-lockfile` or `yarn install --frozen-lockfile`) in the worktree instead of linking the main checkout's `node_modules`, which lacked the new package. A failed install stops `cli.js integrate` with exit 1 and the branch unmoved, and makes `pr_monitor_worktree` return `passed: false` with the command and its output; the environment gate goes on to its setup stage. With matching manifests or no lockfile, the worktree links the main install as before.
