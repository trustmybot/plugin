### Fixed
- **What find -exec / -delete, fd -x and xargs run is judged by the Bash write guards** (GH 1338): `tmb_cmd_write_paths` modelled loops over find or fd output but not the commands find, fd and xargs run themselves, so `find / -exec rm {} \;`, `find . -delete`, `find … -print0 | xargs -0 rm` and `fd … -x rm` were allowed for any path by `containment-guard.sh` and `swe-boundary.sh`. The command of find `-exec` / `-execdir` / `-ok` / `-okdir`, fd `-x` / `-X` (`--exec`, `--exec-batch`) and xargs is now analysed as a statement of its own, with find's `{}` (fd's `{}`, `{.}`, `{//}`; xargs's `-I` string, else its appended argument) bound to the paths find or fd lists the way a loop variable is: each in-root start path and everything under it, plus the prompt-surface dirs a recursive listing reaches. `-delete` writes those paths and `-fprint` / `-fprint0` / `-fprintf` / `-fls` write their file; `-print`, `-ls` and `-printf` still write nothing. A start path outside the run root, behind a variable, or followed with `-L`, and xargs fed by anything but one find or fd, is unresolvable, denied with `write target "${find_path}" depends on a variable the guard cannot resolve in this command` (`${fd_path}`, `${xargs_arg}`). A non-`prompt_bearing` swe can no longer `find agents -name '*.md' -exec sed -i … {} \;`. find and loop sources share one option parser (`_tmb_cmd_lister_bind`), and it no longer reads `-executable` as `-exec`.
