### Fixed
- **A compacted bro session sees every open issue it owns, not just one** (GH 3020): after a compaction, bro's restored state now starts with each open issue the session's lane owns, one line each as `- #<id> <objective> (<n> live tasks)`. An open issue with no tasks yet is marked `unstarted`, and a count of the lane's closed issues follows. The list shows the 30 newest open issues, then `+N more`, and appears even when no single issue was recorded for the session. Before, the restore named one issue, so issues queued in the same session dropped out of view. A new advisory hook records lane membership each time `intent_start`, `issue_create`, `issue_adopt_remote` or `task_provision` succeeds; it never blocks, and `TMB_DISABLE_LANE_MEMBERSHIP_HOOK=1` turns it off. Upgrading to schema v73 adds the `lanes` and `lane_issues` tables and fills them from past sessions' compaction records and agent runs.
