### Fixed
- **git-push-guard sees a push split across a line continuation** (GH 2646): a backslash-newline (`git \` then `push origin dev` on the next line, or `git pu\` then `sh`, unquoted or inside double quotes) split the command in two for the analyzer, so the push read as an unknown command and was allowed from a worktree. The analyzer now joins the lines as bash does, and the gate's quick `push` check looks past the continuation too, so the worktree, swe and review denies fire again. Single-quoted text and quoted-delimiter heredoc bodies (`<<'EOF'`) keep the backslash-newline, as in bash. In an unquoted-delimiter heredoc (`<<EOF`, `<<-EOF`) bash joins body lines before it looks for the delimiter, so a body line like `EO\` then `F` ends the heredoc and the lines after it run as commands; the analyzer now finds that end the same way and fails closed when it disagrees with the parse, so git-push-guard denies the push hidden after it.
