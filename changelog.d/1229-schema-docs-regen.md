### Changed
- **The schema docs are generated from the schema, and the config keys have a home** (GH 1229): `docs/architecture/ERD.md` had drifted from `schema.sql` — eval-only tables drawn as production, the FTS search tables missing, wrong `cheatcodes.origin` values, stale columns and indexes, an old `schema_version`. Its diagram, per-table columns (type, NULL, default, PK/FK/CHECK), foreign keys with their `ON DELETE` action, FTS5 search indexes with their shadow tables, index list and eval-mode tables are now generated by `scripts/maintenance/gen-erd-doc.mjs`, and `tests/l1-lint/erd-doc-fresh.sh` fails when they drift. `docs/reference/CONFIG_KEYS.md` is generated by `scripts/maintenance/gen-config-keys-doc.mjs` from the `plugin_config` keys the code actually reads and writes (type, default, who sets it, effect); a key with no entry fails `config-keys-doc-fresh.sh`, and the links that pointed at a missing file resolve. `ENUMS.md` documents `cheatcodes.origin` as `builtin`/`marketplace`/`external` and both `cheatcodes.status` lifecycles; the server README, `src/tools/README.md` and `REFERENCE.md` list every tool family and all 73 tools, held there by `tool-families-documented.sh`; the `REFERENCE.md` hook table and `hooks/hooks.json` must agree both ways (`hooks-doc-fresh.sh`). `FLOWS.md`, `CONFIG_KEYS.md` and `ERD.md` describe a repo's remotes as its `repo_remotes` rows, and `RESPONSIBILITIES.md` describes what `bro_atomic_close` records. `tests/run-all.sh` runs every L1 lint and checks that none is left out. The sqlite3 fallback refuses an audit `event_type` outside `scripts/hooks/lib/audit-events.txt` (and refuses when the list is missing); the SessionStart banner reports `unchecked (schema vN < vM …)` instead of `healthy` whenever the DB's schema is older than the contracts need; `npm run build` regenerates `scripts/hooks/lib/data-contracts.json`.
