### Fixed
- **`issue_update_description` now updates the GitHub or GitLab issue body too** (GH 2067): it used to change only the local row, so the remote issue body went stale after every plan edit. When issue sync is on and the issue is linked, the new description (with the issue's sync marker kept at the end) is written to the remote with `gh issue edit --body-file -` or `glab issue update -d`. The result carries a `_sync` field like `issue_update`'s: `synced` with the backends, `sync_failed` with the reason, exit code and stderr when the remote edit fails (the local description is still saved), or `sync_skipped` with reason `no_remote_iid` for an issue with no remote link. Description edits from the dashboard are mirrored the same way.
