### Added
- **Agile mode closes a task without a per-task review** (GH 2225): with the project's workflow mode set to agile, closing a task no longer waits for a code-reviewer pass. The task closes, is queued for the later grouped review (it shows in the review queue and the doctor's agile backlog), and the close records that it was queued instead of recording a skipped review. The push guard lets such a task's commit, or a rebase of it, be pushed to a feature branch as a backup, but still blocks it from the repo's target branch. The exception needs a push that names the branch it pushes, as in `git push origin feat/x` or `git push origin HEAD:feat/x`; a push that names no branch (`git push`, `git push origin`), a matching or `--all`/`--mirror` push, `git push origin HEAD` from a detached HEAD, or a push that leaves the destination to the remote's configured push mapping does not get it. Under the default truest mode nothing changes.
