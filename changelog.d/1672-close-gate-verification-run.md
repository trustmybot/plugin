### Fixed
- **A task can no longer close without a verification run for its closing commit** (GH 1672): `bro_atomic_close` now refuses with `verification_run_missing` when the task has `verification[]` commands but no passing run of those commands is recorded for the closing commit, and no `verification_gate_waived` row exists for it. Before this, a task could close with no recorded run in two ways: the SubagentStop auto-complete, or a `task_update_spec` that changed `verification[]` after swe completed. The error explains how to fix it: resume swe to call `task_update_status(completed)` again so the gate runs and records the commands, or waive the gate with `waive_verification_gate_reason`. A passing run is still reused, but only for the same task, commit and `verification[]`. A run recorded before `verification[]` was amended no longer counts.
