### Added
- **swe can hand back a checkpoint, and each stop records why it ended early** (GH 1905): `task_update_status` takes an optional `checkpoint` (`done`, `left`, `files`, optional `commit_sha`) with `status='running'`. The server stamps it with the time and stores it on the task. A move to `completed` clears it. When a swe stops after writing a checkpoint in that run, the SubagentStop hook keeps the task `running` even if it has commits, and tells bro to resume. The next spawn reads the checkpoint from `task_brief`, which also returns `last_stop`: why the newest finished swe run stopped. That reason is stored on the run's `agent_runs` row as `stop_cause`: `budget` for a checkpoint handback, or `hook_block` when the run ended on a PreToolUse hook denial, whose text goes in `stop_detail`. A clean stop leaves both empty. The trajectory DB moves to schema v52 and migrates on the next session start.
