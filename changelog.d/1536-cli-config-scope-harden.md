### Fixed
- **The cli-config-scope lint now catches every way a script can call the `claude` CLI** (GH 1536): `tests/l1-lint/cli-config-scope.sh` flagged only a literal `claude plugin|mcp <subcommand>` written straight after the program. It now also catches the program given as a path, a variable or behind `command`/`exec`/`VAR=value`, global options before `plugin`/`mcp`, the `plugins` alias, and variable subcommands (in shell and in TS/JS argv arrays), which are flagged unless the call is pinned to project scope. The last scope flag decides, so `--scope project --scope user` fails and `-s project` passes. The subcommand list comes from the Claude Code 2.1.303 `--help`, aliases included (`plugin i`, `marketplace rm`, `marketplace update`, `configure`, `init|new`, `prune|autoremove`, `mcp add-from-claude-desktop`, `login`, `logout`, `reset-project-choices`), and subcommands with no scope option are flagged outright. Trailing comments are stripped only outside quotes. The lint now scans every tracked `*.sh`, `*.mjs`, `*.js` and `*.ts` outside test, `dist/` and `node_modules/` directories, including `skills/**/scripts` and the `scripts/maintenance/*.mjs` generators. No unpinned call exists in the tree today.
