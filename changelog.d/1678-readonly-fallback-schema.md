### Fixed
- **The read-only recovery fallback works again on current databases** (GH 1678): when the trajectory-server was down, `bro-sqlite-readonly.sh` `issue_get`, `issue_resume` and `config_get` exited 1 with no output because they queried columns the schema no longer has (`issues.remote_iid`, `plugin_config.updated_at`). Issue reads now return `gh_iid` and `gl_iid`, and any failed query prints `bro-sqlite-readonly: <subcommand> failed: <sqlite error>` to stderr instead of failing silently. A new test runs every subcommand against a freshly migrated database, so future schema drift fails CI.
