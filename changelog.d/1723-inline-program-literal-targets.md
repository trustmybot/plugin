### Fixed
- **A `~/` path passed to `replace` or `re.sub` in an inline python program is no longer read as a write target** (GH 1723): a program such as `p='docs/a.md'; s=open(p).read().replace('~/.jobduck','{{home}}'); open(p,'w').write(s)` was denied by the containment guard as writing "outside this run's root", because a write through a name counted every path-like string in the program as a target. Once the guard proves a python program, its targets are now only the paths it writes, so this edit is allowed. A `re.sub` with a string replacement and a two-argument `.replace` on the result of a call such as `open(p).read()` now pass that proof. A program the guard cannot prove is still judged the old way, a write call with a `*` or `**` argument still counts every path-like string, and a name bound to a path outside the root is still denied.
