### Fixed
- **swe's worktree comes from its task, not from the session's cwd** (GH 1550): Claude Code gives bro and every subagent one working directory, so hooks that read `$PWD` or the payload `cwd` resolved the wrong worktree or root when the repo lives outside the project, the project sits under `.claude/worktrees/<n>`, repos are nested, or `.claude/worktrees` appears twice in a path. The hooks now derive it from the swe's identity: `task_id` in its spawn transcript → `tasks.repo` → `repos.path` → `<repos.path>/.claude/worktrees/<branch slug>`. A swe with a missing piece is denied with a message that names the piece. The project root comes from `CLAUDE_PROJECT_DIR`. `scan.sh` finds repos in a session dir under `.claude/worktrees/<n>`. An interpreter program that writes through a variable bound once to a plain literal (`p = 'notes.txt'`) is judged by that literal, so its other text (`s.replace('x', '/user/own')`) is no longer read as a write target. A new lint, `tests/l1-lint/no-cwd-identity.sh`, keeps the cwd from coming back as identity.
