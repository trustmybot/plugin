### Fixed
- **swe's worktree comes from its task, not from the session's cwd** (GH 1550): Claude Code gives bro and every subagent one working directory, so hooks that read `$PWD` or the payload `cwd` resolved the wrong worktree or root when the repo lives outside the project, the project sits under `.claude/worktrees/<n>`, repos are nested, or `.claude/worktrees` appears twice in a path. The hooks now derive it from the swe's identity: `task_id` in its spawn transcript → `tasks.repo` → `repos.path` → `<repos.path>/.claude/worktrees/<branch slug>`. A swe with a missing piece is denied with a message that names the piece. The project root comes from `CLAUDE_PROJECT_DIR`. `scan.sh` finds repos in a session dir under `.claude/worktrees/<n>`. An interpreter program whose write calls name literal paths (`open('notes.txt', 'w')`) is judged by those paths, so its other text (`s.replace('x', '/user/own')`) is not a write target. A program that writes through a variable still counts every literal, since Python can rebind a variable unseen (`cProfile.run`, `trace`, `pdb`, `gc.get_objects`, pickle): inline the path or use the Edit tool. A lint, `tests/l1-lint/no-cwd-reads.sh` (GH 1553), keeps the cwd from coming back as identity.
