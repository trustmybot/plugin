### Fixed
- **Inline programs can no longer write the environment through a second name** (GH 2481): the containment guard proved `python3 -c` and `node -e` programs that bound `os.environ` or `process.env` to a name and wrote through it (`e=os.environ; e["HOME"]="/etc"`, `e.update(…)`, `del e[k]`, `e |= {…}`, `f=e; f[k]=v`, `const e=process.env; e.HOME=v`, `delete e.HOME`), and `let h; h=require("https"); h.get(…)`, though the same write spelled out was denied. A name assigned a reference (also through parentheses, `a=b=…`, `x or y`, `c ? x : y`, `||=` and default parameters) is now judged as the reference it holds, a `require` assigned later is judged as that module, and a name whose assignments disagree is unproven. Reads through such a name, like `e.get("HOME")`, `o=sys.stdout; o.write(…)` or `console.log(e.HOME)`, still prove.
