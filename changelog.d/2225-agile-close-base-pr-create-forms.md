### Fixed
- **Agile closes diff against the feature branch, and every way of opening a PR is gated** (GH 2225): in agile mode, `review_handoff` and `bro_atomic_close` now measure a task stacked on a feature branch against that branch instead of the repo's target branch, so the reported merge-base, extras and base move describe the task's own work on the feature branch; every other task is measured as before. The feature-branch merge gate and the PR-target rule in git-guards now recognise each way gh and glab open a pull or merge request, not only a literal `gh pr create` or `glab mr create`: `gh -R <repo> pr create`, `gh pr new`, `glab -R <repo> mr new`, `gh api` POSTs to `repos/<owner>/<repo>/pulls`, and `gh api graphql` calls to `createPullRequest`. The head and base come from `--head`/`-H`, `--source-branch`/`-s`, `--base`/`-B`, `head=`/`base=` fields, or the graphql `headRefName`/`baseRefName`. Read-only calls such as `gh pr view` or a GET of the pulls list are unaffected.
