### Fixed
- **bro hears about a swe run that outlives its task** (GH 2190): a swe run could keep going for hours after its task closed, for example stuck on an interactive `cp -i` prompt, and nothing said so because the overrun alert only watched `running` tasks. The `task-overrun-alert` hook now also tells bro, once per spawn, about any swe run in bro's session that started more than `TMB_TASK_OVERRUN_MIN` minutes (default 60) ago, has not stopped, and whose task is closed, missing or otherwise not `running`. bro can then check the run and stop it. A task reopened for rework or long after its close is now timed from the reopen, so the review wait and the closed time no longer trip the task alert at once, and each running stint can alert once.
