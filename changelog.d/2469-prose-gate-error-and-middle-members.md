### Fixed
- **A command tree-sitter cannot parse no longer writes prose into scratch** (GH 2469): the no-prose-in-scratch gate let `tr a b 2>/dev/null <<< "plan" | sort > $TMPDIR/x.txt` through, because a here-string after a stderr redirect does not parse and the gate allowed what it could not parse. It now fails closed: a prose file in a scratch zone that such a command names is denied, unless `bash -n` finds a syntax error, so the command never runs.
- **An authoring command in the middle of a pipe no longer slips prose into scratch** (GH 2470): the gate checked only the first and last commands of a pipe, so `find . | echo plan | sort > $TMPDIR/x.txt` passed. It now checks every piped command; a bare `cat` past the head of the pipe relays its input and stays allowed.
