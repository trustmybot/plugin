### Fixed
- **A Bash copy that names only a parent dir of your project's skills or agents needs the Human's approval too** (GH 2981): `cp -r x/skills .claude/`, `rsync -a src/ .claude/`, `tar -x -C .claude`, `git checkout <ref> -- .claude/skills` and a whole tree copied, moved, extracted or restored into the project root (`cp -r foo/.claude .`, `tar -xf a.tar`, `git checkout HEAD -- .`) could write skill and agent files without the Human's approval. Each is now blocked unless bro recorded the Human's Yes for that exact dir in the last 30 minutes with scope `full`; the deny names the dir to approve. Ordinary writes that name the root, such as `git commit`, `cp a.txt .` or `make -C .`, are not affected, and swe is still exempt. A `tar` extract with no `-C` now counts as a write to its own dir for every Bash write guard.
