### Fixed
- **A Bash copy that names only a parent dir of your project's skills or agents needs the Human's approval too** (GH 2981): `cp -r x/skills .claude/`, `rsync -a src/ .claude/`, `tar -x -C .claude`, `git checkout <ref> -- .claude/skills` and a whole tree copied, extracted or restored into the project root (`cp -r foo/.claude .`, `tar -xf a.tar`, `git checkout HEAD -- .`) could write skill and agent files without the Human's approval. Each is now blocked unless bro recorded the Human's Yes for that exact dir in the last 30 minutes with scope `full`; the deny names the dir to approve. A git pathspec named from the repository top (`:/.claude/skills`, `':(top).claude'`) is judged from that top, not from the dir the command runs in, and is blocked when git is pointed at another repository (`--git-dir`, `GIT_DIR`), where the top cannot be told. A `mv` into the root is blocked only when it moves a `.claude` dir there, including through a brace (`mv x/{.claude,a} .`) or a glob that can match it (`mv x/.c* .`); as in bash, `*`, `?` and `[...]` do not match a leading dot, so `mv build/* .` is not affected unless the command turns on `dotglob`. Ordinary writes that name the root, such as `git commit`, `cp a.txt .`, `mv src/ .` or `make -C .`, are not affected, and swe is still exempt. A `tar` extract with no `-C` now counts as a write to its own dir for every Bash write guard, and a Bash command that does not parse is now blocked by this gate too wherever the containment guard blocks it (a trajectory DB is present); with no trajectory DB, such a command is blocked only when its text may name `.claude` (any case or quoting, `$'…'` quoting, or a dot followed by a glob, brace or `$`). Commands that write nothing, such as `echo {1..5000}` or `jq` and `curl -d` with a quoted JSON argument, are never blocked for their braces.
