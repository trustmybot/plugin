### Changed
- **The headless shim runs the TypeScript router, not `dispatch.sh`** (GH 1692). Headless enforcement now writes one `.claude/settings.local.json` entry per PreToolUse group of `hooks/hooks.json`, `resolve-hook.sh --marketplace <mp> --hook PreToolUse --shim --project <root>`, with the group's matcher, `timeout` and `onFailure`. The resolver execs the active install's `node mcp/trajectory-server/dist/hooks.js PreToolUse --shim` (a router entry with a part adds `--part <part>`), so headless runs judge each call with the same gates, order and aggregation as interactive sessions.
  - Under `--shim` the router exits 0 with no output and runs no gate when `CLAUDE_PROJECT_DIR` is another project or the plugin's SessionStart marker exists for the session, as `dispatch.sh --shim` did; otherwise it decides as the plugin's own entry does.
  - The per-gate entries and their advisory-gate exclusion list are gone. Re-run `/onboard` (or turn headless enforcement on again) once to replace a project's old entries; `docs/reference/UPGRADE.md` walks through it.
  - With `node` off PATH, or an install without `dist/hooks.js`, the resolver prints a `failing OPEN` warning and allows the call. An old per-gate entry run by the new resolver does the same, naming the re-run.
