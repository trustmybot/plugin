### Fixed
- **Tasks whose `files[]` are prompt files are marked prompt-bearing on their own** (GH 2978): `prompt_bearing` was set only when bro passed it, so a task that edits a skill, agent, command, template, rule or `CLAUDE.md` file could be spawned without it and swe's edit was then denied. `task_provision`, `task_create_batch`, `task_update_spec`, `task_reopen` and `task_retry` now set it to 1 when any `files[]` entry is a prompt-surface file or a directory under one of those roots, and never lower it. Effort resolves as for an explicit `prompt_bearing: 1`, and the result carries `prompt_bearing_derived: true` when the files decided it.
