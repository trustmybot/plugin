### Fixed
- **The verification gate records only real commits, budgets commands apart from its record writes, and tells its own timeout from a command's exit 124** (GH 1310): when the worktree HEAD did not resolve the gate wrote a `verification_runs` row with `commit_sha='nohead'`; now it records and reuses nothing, still runs `verification[]`, and its decision says `(not recorded: worktree HEAD unresolvable)`. `verification_timeout_s` (and `TMB_VERIFICATION_TIMEOUT_S`) is clamped to 1–1800: 0 or a non-integer falls back to 900 s with a stderr warning naming the value instead of timing out at once. The budget and the cumulative time count command time only; each run-record write gets 3 s, the start and command writes at most 9 s together, and the finish write 3 attempts with backoff, so a contended DB no longer eats the command budget. `tests/l1-lint/hook-timeout-budget.sh` floors the gate's hooks.json timeout at cap + record writes (20 s) + 1 s dispatcher + 5 s (1826 s, under the unchanged 1830 s). When every finish attempt fails the decision stands and stderr says the record is unfinished; the new warn contract `no_unfinished_verification_runs` reports a run still unfinished 2 h after it started. `timed_out` is set only when the gate's timeout wrapper fired (a marker the wrapper writes) or the budget was spent before a command started; a command that itself exits 124 is recorded as `exit_code` 124, `timed_out` 0, and denied as a failing command. `verification_recorded_for_closed_tasks` counts only tasks closed at or after the first recorded verification run (the v36 migration keeps no applied-at timestamp) and is skipped as `no_v36_timestamp` while no run exists; a DB contract can now carry a `skip_when` SELECT whose non-zero result skips it without making the report unhealthy.
