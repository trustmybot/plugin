### Changed
- **SessionStart, UserPromptSubmit and WorktreeCreate now run their gates through the TypeScript router** (GH 1692). `hooks/hooks.json` holds three SessionStart registrations, three UserPromptSubmit and one WorktreeCreate, every one advisory.
  - The default groups now run one gate at a time in a fixed order, where the separate `dispatch.sh` entries ran in parallel, so a slow gate holds the ones after it. SessionStart default is `ensure-gitignore`, `mcp-health-check`, `deferred-tools-drift-warn`, `plugin-hooks-marker`, `ensure-mcp-deps-installed`, `substrate-preflight` and `orphan-scan`; UserPromptSubmit default is `rework-waiver-capture`, `activation-routine`, `session-log-capture`, `prompt-intent-hints` and `task-overrun-alert`. A gate left no group budget is skipped and logged.
  - `session-start-persona` and `session-start-prescan`, and `user-prompt-persona` and `roundtable-slash-detect`, keep registrations of their own (`node dist/hooks.js <Event> <part>`), which still run in parallel, so a big context is measured alone against Claude Code's 10,000-character cap. A group's `part` is a seventh column of `dist/hooks-router.txt` and a third segment of its `budgets.json` key.
  - On SessionStart and UserPromptSubmit a gate's plain stdout is context: a lone output passes through unchanged and several merge into one `additionalContext` in group order. Text shaped as JSON that fails to parse is still dropped and logged.
  - WorktreeCreate prints the gate's bare path and nothing else. On a gate failure, timeout, budget skip, unparseable payload or failed hop it prints no stdout, names the cause on stderr and exits non-zero, and `hook_call` records `failed`. A duplicate within the dedupe window replays the path.
  - Dedupe keys hold the part, and SessionStart keys on event and session as `dispatch.sh` does.
