### Fixed
- **The session-start inventory reads the world model as cold when it is empty, so the first-session scan runs again** (GH 1593): the inventory called the world model "warm" whenever an earlier scan had been recorded, even when the world-model tables held nothing. Every install upgraded past the move to SQLite showed "warm" over an empty map, and the automatic scan for a cold world model never fired. The inventory now reads warm only when the world model holds directories. A scan that refills an empty world model now reports `structural_change: true`, and `scan_run` with no world model to write returns a `world_model_unavailable` error instead of marking your repos as scanned.
