### Fixed
- **The git branch gates no longer let git through when it runs via `xargs` or behind `env $X`** (GH 2850, GH 2144, GH 2808): `echo name | xargs git checkout -b` and `echo name | xargs git -C <main> checkout` got past the new-branch rule and stay-on-base-guard, because xargs supplies the branch name from its input. `env $X git -C <main> checkout <task-branch>` got past stay-on-base-guard, no-worktree-branch-create and branch-up-to-date-with-remote, because the listing strips the `env` wrapper and those gates never read it. Now git-guards denies a checkout, switch or branch run through xargs, unless it is the literal `checkout -b <name>` / `switch -c <name>`, and no merge run that way counts as a fast-forward sync. stay-on-base-guard denies a checkout or switch run through xargs that creates no branch and restores no files. no-worktree-branch-create denies a `worktree add` run through xargs unless both of its bypass variables are set, and branch-up-to-date-with-remote denies one that creates no branch. Each of these denies cites `ambiguous_git_arguments` and applies where that gate already judges the literal form. All four gates treat `env $X git …` as an unknown subcommand, and their prefilters parse any command that names both `xargs` and `git`. Literal commands are judged as before.
