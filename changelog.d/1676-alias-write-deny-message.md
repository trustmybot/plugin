### Fixed
- **A write through an aliased or stored `open` now gets a deny message that names it** (GH 1676): an inline python program that holds `open` as a value (`o = open; o(...)`, `from builtins import open as o`, `writers = [open]`) is still denied, but the containment guard now says the target "is written through an aliased or stored write builtin the guard can't resolve; call open() (or the write method) directly with a literal path" instead of blaming a process call. A non-literal process call keeps its own process-call message, and which programs are denied is unchanged.
