### Fixed
- **Tasks stacked on unpushed local work keep it** (GH 1713): `task_provision` always cut a new branch from `origin/<base>`, so commits on a local `<base>` that were not pushed yet were missing from the task's branch. It now cuts from the local `<base>` when it is strictly ahead of `origin/<base>` (the `git pull --ff-only` rule), and from `origin/<base>` otherwise. The result names the ref it cut from in `base_ref`. When local and origin have diverged, the cut stays on origin and the result carries a `base_diverged` warning with both SHAs and the ahead/behind counts. The close-time scope gate measures from the same base, so the local base's own commits are not counted as the task's out-of-scope paths.
