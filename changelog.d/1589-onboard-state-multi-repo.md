### Fixed
- **`/onboard` shows each repo's own branching policy and remotes in a multi-repo workspace** (GH 1589): with several repos, `onboard_state_get` reported the alphabetically first repo's branching model, PR target, protected branches and remotes as the whole workspace's, so a gitflow repo could appear as GitHub Flow on `main`, and the final `/onboard` apply could return no remotes while the stored state still named some. With two or more repos, the state and the final apply now list every repo with its own policy and remotes under `repos`; a single-repo project sees the same shape as before, and the apply's remotes always match what the state then reports.
