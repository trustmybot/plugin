### Changed
- **A code-reviewer pass carries across a trivial `cli.js integrate` rebase** (GH 2082): since GH 2411 every exit-0 integrate left the rebased head unreviewed, so bro had to spawn code-reviewer again before the push, even though integrate had already proved the rebase trivial (the same `git patch-id --stable` list, and `verification[]` passing on the new SHA). Like Gerrit's `TRIVIAL_REBASE` copyCondition, which copies a vote onto a new patch set that only rebases the old one, integrate now writes the reviewed commit's review anchor into the `task_integrated` row as `review_anchor_at`, and `HAS_PASS_SQL` judges the pass against it. On exit 0 bro pushes the printed SHA, and a second integrate needs no new review. Only a `task_integrated` row from `hook:integrate` carries an anchor: older rows without `review_anchor_at`, any other new head, and a FAIL verdict recorded after the pass still need a fresh review.
