### Changed
- **The task-close hooks have TypeScript versions** (GH 1692): two hooks are ported from `scripts/hooks/<gate>.sh` to `mcp/trajectory-server/src/hooks/` and listed in `dist/hooks-gates.txt`, so `dispatch.sh` runs them through node (`TMB_HOOKS_IMPL=bash` still runs the .sh). Their policy, bypass variable, messages and DB writes are unchanged:
  - `swe-atomic-close` (SubagentStop) binds a swe or code-reviewer spawn to the `task_id=<N>` in its transcript and meters the run row: tokens, cache reads and writes, turns, the last message time and the model. For swe it then auto-completes a pending or running task that has commits, warns bro when it stopped without committing, hands a checkpoint back to resume from, and names a PreToolUse block that stopped the run. An unbound or unknown task writes one `agent_runs_capture_skipped` audit row.
  - `post-task-close-rescan` (PostToolUse on `bro_atomic_close`) starts `scripts/maintenance/run-scan.mjs` against the DB the hooks resolve. The scan runs as a detached, unref'd child with its stdio ignored, node's form of the .sh's `& disown`, so the hook returns without waiting for it. `TMB_SKIP_AUTO_RESCAN=1` still skips it.

  A 31-payload corpus in `tests/fixtures/hook-corpus/` runs each hook through both versions in the C and `en_US.UTF-8` locales, each payload against a freshly restored sandbox. Both versions exit the same way, print byte-identical stdout and stderr, and leave identical tasks, agent_runs, agent_run_tool_output and audit rows and log files behind. The swe-atomic-close payloads cover every decision-matrix row, a stale local parent branch, a run with no worktree, a resumed run, an unmeasured spawn, code-reviewer metering, an unbound spawn, an unknown task, a non-swe subagent and stdin that is not one JSON object. The rescan payloads cover a close in each channel, other tools, the bypass and malformed stdin; a fake scan that waits for a release file shows each hook returned before the scan finished.

  The `swe-atomic-close`, `swe-atomic-close-agent-runs` and `post-task-close-rescan` l3 suites pass against both versions; `TMB_HOOK_TEST_IMPL=ts` picks the TypeScript one.

  The TypeScript hooks differ from the .sh only where they no longer need a CLI tool (decision 703). Each difference has a payload in the corpus marked `corpus_divergent`:
  - **No jq needed.** Without jq, `swe-atomic-close.sh` exited without touching the task and `post-task-close-rescan.sh` started no scan. The TypeScript `swe-atomic-close` still meters and closes the run, and `post-task-close-rescan` still starts the scan.
  - **No `sqlite3` CLI needed.** `swe-atomic-close` reads and writes the trajectory DB through Node's built-in `node:sqlite`. Without `sqlite3`, the .sh logged its entry line and exited; the TypeScript hook binds the task and meters, closes or warns as usual.
