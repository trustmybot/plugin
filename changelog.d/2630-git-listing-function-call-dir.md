### Fixed
- **The git guards judge a git command in a shell function in every directory a call can run it in** (GH 2630): in `cd /tmp; f() { git push origin dev; }; cd .claude/worktrees/t; f` the push runs in the worktree, but the guards judged it in `/tmp` alone, and a `function f { … }` body was never split, so its push went unseen. A git statement in a function body is now checked in the directory it is defined in and in each directory a call starts it in, a `cd` in the body carries to the statements after the call, and a call whose directory can't be pinned (`eval`, `trap`, an alias, a function exported to a `bash -c`, a name held in a variable, recursion, a call before the definition) is denied as an unresolved directory.
