### Added
- **The close gate records each verification run and reuses a passing one; `task_brief` shows the record** (GH 1294): a task's `verification[]` ran three times (swe, the close gate, pr-reviewer) at 10–12 minutes each, and the results lived only in prose. Schema v36 adds `verification_runs` (`task_id` → `tasks` ON DELETE CASCADE, `commit_sha`, `source` `gate`|`manual`, `started_at`, `finished_at`, `exit_code`, `budget_s`, `timed_out`, `created_at`; indexed on `(task_id, commit_sha, finished_at)`) and `verification_run_commands` (`run_id` → `verification_runs` ON DELETE CASCADE, `ordinal`, `command`, `exit_code`, `elapsed_s`, `output_tail`). `swe-verification-gate.sh` writes them through the new `scripts/hooks/lib/verification-runs.sh` — the run row when it starts, a command row after each command, then the finish — so a killed run keeps a partial record. A passing run for the same task and worktree HEAD that finished within the hour is reused: the close is allowed without running anything, with `verification reused run #N (<finished_at>)`; this replaces the verdict file beside the run lock (concurrent closes still serialize on the lock). A failure deny names the command, its position, exit code, elapsed and cumulative time, with the forwarded FAIL lines and tail. `task_brief` adds `verification_run` (the latest run with its commands, null when none) next to the unchanged `verification` command list, and `validation_history` rows carry the latest run started by each attempt. A new warn contract, `verification_recorded_for_closed_tasks` (min_schema 36), flags tasks closed in the last 7 days with a non-empty `verification[]`, no waiver and no recorded run for their commit.
