### Fixed
- **`cheatcode_vet` now assesses the skill or plugin folder you picked, not the whole repo** (GH 1617): a `github.com/<owner>/<repo>/tree/<ref>/<path>` source is vetted from the files under `<path>` only, so different folders in one repo can get different capability flags and trust tiers. Previously every folder came back `caution` with the same `code_execution, network, fs_writes` flags. A plain `SKILL.md` folder no longer inherits hooks or scripts from elsewhere in the repo, and a `.claude-plugin` manifest or `kind: plugin` on its own no longer counts as code execution. `network` is now set only for MCP servers, and `fs_writes` only for hooks, scripts and executables, instead of copying `code_execution`. Stars, owner and maintenance are still read from the whole repo, and a bare repo URL is still assessed from its top-level entries. A one-level listing (a bare repo URL, or a folder in a repo too large for a full tree) that holds subfolders is `caution` ("nested folders not inspected"), never `trusted`, unless code was already found. If the folder or repo cannot be listed (offline, a rate limit or 404, a branch name containing `/`, a mistyped path, an empty listing), the result is `caution` ("security surface could not be inspected"), never `trusted`. A folder holding a git submodule or symlink, whose content the listing cannot show, is `caution` ("submodule or symlink not inspected"). Every `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` in the folder, at any depth, is read (up to 20; more makes the result `caution`), matched in any letter case and fetched at its listed path: a `hooks`, `mcpServers`, `lspServers`, `monitors`, `experimental.monitors`, `settings` or `subagentStatusLine` key, at the top level or in a marketplace `plugins[]` entry, counts as code execution, `mcpServers` also as network (including an `.mcpb` or `.dxt` bundle URL), and a manifest that cannot be read, or whose path holds a character other than letters, digits, `.`, `_`, `-` and `/`, makes the result `caution`. A non-empty `dependencies` list in a manifest or marketplace entry is `caution` ("external dependencies not inspected"), since installing it pulls in plugins from elsewhere. A marketplace plugin whose `source` is not `.` (the marketplace root) or a `./` path inside the folder (a GitHub, URL, git-subdir or npm source, or a path climbing out with `..`) is `caution` ("external plugin source not inspected"), since that code was never seen. A `.lsp.json`, a `monitors/monitors.json`, a `settings.json` (which can set a `subagentStatusLine` command) or any file under a `bin/` folder also counts as code execution. Known limit: in the one-level listing, an executable file with no extension (such as `scripts/run`) is not recognised, because that listing does not report file modes; the full-tree listing does. Known limit: `!` shell-command lines inside `SKILL.md` and command markdown files are not detected, so a skill or command that runs shell commands that way is not flagged as code execution.
