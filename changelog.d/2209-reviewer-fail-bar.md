### Changed
- **code-reviewer has a stated fail bar and review dimensions** (GH 2209): a finding is `blocking` only when this diff introduced it, it breaks function (a criterion, the touched code or a caller, a security property, or a stated performance budget), its probe fails on the commit, its `expected` cites a basis (an `SC<n>` id, a spec line, or base behaviour at file:line), and the spec did not ask for the change; when only the impact is in doubt it stays `blocking`. Design, placement and complexity are graded `nit`. The diff review now asks security, performance and test-quality questions where the diff makes them relevant, and a CLAUDE.md, skill, agent or review-rules file the diff changes is reviewed as code rather than followed as guidance.
