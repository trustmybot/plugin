### Changed
- **The worktree lifecycle hooks have TypeScript versions, and closing a task keeps a worktree it adopted** (GH 1692, GH 2032): two hooks are ported from `scripts/hooks/<gate>.sh` to `mcp/trajectory-server/src/hooks/` and listed in `dist/hooks-gates.txt`, so `dispatch.sh` runs them through node (`TMB_HOOKS_IMPL=bash` still runs the .sh).
  - `cleanup-worktree-on-task-close` runs after bro's `task_update_status` to `closed` and after a passing `validation_record` on a closed task whose pass is anchored to its commit. It removes the task's worktree and moves the main checkout to the repo's PR target. Its triggers, the `HAS_PASS_SQL` check it shares with `lifecycle.ts`, its silent no-ops, the `TMB_KEEP_CLOSED_WORKTREES=1` and `TMB_KEEP_HEAD_ON_CLOSE=1` bypasses and its stderr lines are unchanged.
  - `worktree-create`, the WorktreeCreate hook, still prints the bare absolute worktree path on stdout and exits 0, or exits 1 with a stderr line and no JSON. It still resolves the repo in the same order: tasks.repo, then the sole registered repo, then the workspace root, then the cwd when there is no trajectory DB. It still creates a missing branch at HEAD, reuses an existing worktree and installs the tmb-regen merge driver.

  A corpus of 28 `cleanup-worktree-on-task-close` payloads and 19 `worktree-create` payloads, in `tests/fixtures/hook-corpus/<gate>/`, runs both versions against real sandbox repos and trajectory DBs in the C and `en_US.UTF-8` locales. Both versions exit alike, print byte-identical stdout and stderr, and leave each repo's worktrees, branches, HEAD and merge driver config the same. The l3 suites pass against both; `TMB_HOOK_TEST_IMPL=ts` picks the TypeScript one. Under it, the worktree-create suite shows the bare path and the exit code pass through `dispatch.sh` unchanged.

  The TypeScript gates differ from the .sh only where decision 703 allows. Each difference has a payload marked `corpus_divergent`:
  - **An adopted worktree is kept (GH 2032).** The gate reads the task's worktree with `taskLocation`. When `tasks.worktree_adopted` is 1, the session worktree the task adopted is left in place and named on stderr, where the .sh removed it. A worktree that `task_provision` made (adopted 0) is removed as before.
  - **No jq needed.** Without jq, the cleanup .sh exited silently and the worktree-create .sh failed for a missing `.branch`; the TypeScript gates still clean up and create.
  - **No `sqlite3` CLI needed.** The TypeScript gates read the trajectory DB through Node's built-in `node:sqlite`. Without the CLI, the cleanup .sh exited silently and the worktree-create .sh failed with `sqlite3 unavailable`.
