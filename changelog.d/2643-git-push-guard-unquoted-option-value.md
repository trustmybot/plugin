### Fixed
- **git-push-guard denies an unquoted expansion in a git option's value** (GH 2643): `W='/x push'; git -C $W status` runs `git -C /x push status` after bash splits `$W`, but the guard read it as `status`. An unquoted `$` or backtick in the value of `-C`, `-c`, `--git-dir` and git's other value-taking options now leaves the subcommand unknown and the git guards deny it, unless the variable comes from a literal assignment in the same command whose value has no blank and no glob, brace or quote character (`W=/x; git -C $W status`), which bash keeps as one word. The double-quoted form (`git -C "$W" status`) is read as before. Quote such values to keep them allowed. When the dir behind such a value is unresolved in a repo with linked worktrees, git-guards names the ambiguous dir first.
