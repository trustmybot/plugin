### Fixed
- **swe and code-reviewer can no longer reach a git stash write through a subcommand the stash rule cannot read** (GH 2837): `swe-boundary` read git's subcommand as written, so `p=stash; git $p pop`, `git $(echo stash) pop` or `git -c alias.s=stash s pop` slipped past the GH 2786 stash rule. The rule is now an allowlist: it admits a git statement only when its subcommand reads literally from the statement's source and, for `git stash`, only a literal `list` or `show`. An expansion, quote or backslash in the subcommand, a path-qualified git, or a `-c` / `--config-env` option that may define an alias is denied with a message asking to spell the subcommand out; a quoted, escaped or computed stash verb is denied as a stash write.
