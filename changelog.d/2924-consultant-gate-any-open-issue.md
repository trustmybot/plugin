### Fixed
- **A consultant that wrote its analysis on any open issue can return** (GH 2924): the consultant persistence gate only counted a discussion row on the most recently updated open issue, so a consultant that wrote to the issue bro scoped it to was blocked whenever another open issue was updated later. The gate now lets the consultant stop once it has a row on any open issue written since its spawn started, read from the earliest timestamp in its own transcript; with no readable spawn start, a row on any open issue counts. When it blocks, the fix names the newest open issue by creation, the one `discussion_append` writes to by default.
