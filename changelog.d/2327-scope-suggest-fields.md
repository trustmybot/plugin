### Added
- **`scope_suggest` drafts a task's scope from the world model** (GH 2327): bro or a consultant passes an `objective` and optional `anchors` (symbol names or repo-relative file paths) and gets the files in scope ranked by score, each with `via` saying what put it there (`search`, `anchor`, `caller:<name>`, `import:<name>`), the `tests` that reach each anchor, the `runners` covering each in-scope directory nearest first, and a `draft {files, verification}` to edit into the spec. An anchor that matches nothing lands in `unresolved_anchors` instead of failing the call. The tool only reads.
- **`world_model_get` takes `fields`** (GH 2327): `fields: ['path', 'purpose']` keeps only those keys on each tree node and `files[]` entry, so a zoomed-in call costs fewer tokens. `path` always stays, and so do `children` and `files` on tree nodes. An unknown name is an error that lists the valid ones, and leaving `fields` out returns the same output as before.
