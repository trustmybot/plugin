### Fixed
- **An issue closes once its task commits reach the target branch, in local-only projects too** (GH 3234): with the task closed at bro's close step and the issue left open, nothing closed the issue when the work merged outside an in-session `gh pr merge`. Each TMB checkpoint that fetches a repo's target (startup catch-up, the ref-move hook, a world-model read by bro or a consultant, `task_provision`) now closes an open issue whose closed task commits are all in `origin/<target>` (the local target branch when there is no origin), by ancestry or patch equivalence, so merge-queue merges, web-UI squash merges and a local `git merge` all count. An issue with a live task or an unreviewed closed task stays open. Each close writes one `issue_closed_on_target_reach` audit row; the GitHub/GitLab close follows only when issue sync is on (`issue_close_remote_skipped` otherwise). Old open issues whose work already merged close on the first checkpoint. A `task_provision` whose own checkpoint closed the issue reopens it in the task's transaction (`issue_reopened` row, `issue_reopened: true`), so the new task never lands under a closed issue.
