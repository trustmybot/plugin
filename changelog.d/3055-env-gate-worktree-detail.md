### Fixed
- **A refused worktree stage now says why, and an empty leftover folder no longer blocks it** (GH 3055): when `task_provision`, `task_reopen` or `task_retry` failed at the environment gate's `worktree` stage, the detail showed git's first line (`Preparing worktree (checking out ...)`) and dropped the `fatal:` line that named the cause; it now shows git's `fatal:` or `error:` line. A folder left at the worktree path that git does not know as a worktree is removed first when it holds only empty directories (such as `.claude/.cc-writes/`), so the worktree is created there. A folder that holds any file is left as it is, and the refusal names it as occupied so you know what to clear.
