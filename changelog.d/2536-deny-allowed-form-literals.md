### Fixed
- **The ambiguous-target deny quotes the command as you wrote it** (GH 2536): when a git command names no directory in a repo with linked worktrees, the deny used to show the command with its quotes dropped and spaces turned into `_`, so `git commit -m 'fix: thing'` came out as `git commit -m fix:_thing`, and copying the allowed form broke the message. The deny now quotes the command as written, and its allowed form is `git -C <path>` plus the subcommand and its arguments exactly as typed (the command's own `-C` and `-c` options dropped), or `cd <path> && <command>` for a command that is not git. Which commands are allowed or denied is unchanged.
