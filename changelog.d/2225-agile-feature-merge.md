### Added
- **`cli.js feature-merge <task_id>` lands a closed agile task on its feature branch** (GH 2225): the feature branch is the task's `parent_branch_id`, and the command moves it without a PR and never pushes. When the feature tip is already under the task's commit, the branch fast-forwards to it. When the feature branch has moved on, the task is rebased onto it in a temporary worktree and its `verification[]` runs there, as `cli.js integrate` does. On a pass, the feature branch and the task branch move to the rebased commit, the task's `commit_sha` follows, and a fresh `review_queued` row keeps the task queued for the grouped review. Every successful run writes a `feature_branch_merged` audit row and prints only the new feature tip on stdout. A failed check exits 1 and a conflict or patch drift exits 2, both leaving the branches and the task unchanged. A task that is not closed in agile mode exits 3. Exit 4 covers the other refusals: no parent branch, a parent that is the repo's target or a protected branch, a missing feature branch, a feature branch checked out in a worktree, or a task with no `verification[]`.
