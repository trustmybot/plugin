### Changed
- **`orphan-scan` and `session-start-prescan` have TypeScript versions** (GH 1692). Both are ported from `scripts/hooks/<gate>.sh` to `mcp/trajectory-server/src/hooks/<gate>.ts` and listed in `dist/hooks-gates.txt`, so `dispatch.sh` runs them through node (`TMB_HOOKS_IMPL=bash` still runs the .sh). Both stay advisory and exit 0 silently on any failure; `orphan-scan` keeps its 4 s cap, and still only reports or, with `TMB_ORPHAN_SCAN_CLEAN=1`, cleans this project's stale DBs and dead-owner trajectory-servers plus cache versions no `installed_plugins.json` entry pins. Their output lines, their order and the no-jq Tooling line are byte-identical to the .sh.

  Two corpora run both versions in the C and `en_US.UTF-8` locales, each against a fresh copy of one sandbox with its own HOME and `ps`/`lsof` stubs, so no case reads the real `~/.claude` or signals a process. Both versions print byte-identical output and leave the sandbox alike.
  - `tests/fixtures/hook-corpus/orphan-scan/` (14 payloads): nothing to report, stale old-layout, 0-byte and legacy DBs, the live DB kept, dead-owner duplicates from the holders override and from lsof, a live owner not reported, unpinned cache versions, a version another project pins not reported, clean mode, and a corrupt live DB.
  - `tests/fixtures/hook-corpus/session-start-prescan/` (16 payloads): the cold-scan bypass, no jq, no DB, warm, empty and stale world models, version skew, git dirty counts, open issues and pending tasks, top-level dirs and stacks in locale order, several repos (relative, missing, a `|` in a name), duplicate enabled copies, pre-1.1.0 user hooks, a schema behind the contracts, and a corrupt DB.

  The `orphan-scan` and `session-start-prescan` l3 suites pass against both versions; `TMB_HOOK_TEST_IMPL=ts` picks the TypeScript one. `mcp/trajectory-server/src/test/hooks-session-scans.test.ts` shows that clean mode never lists or removes another project's DB, process or pinned cache version.

  The TypeScript versions differ from the .sh only where decision 703 allows; each has a `corpus_divergent` payload and a unit test in `hooks-session-scans.test.ts`:
  - **`orphan-scan` needs no jq.** Without jq the .sh stayed silent; the TypeScript gate still reports.
  - **`orphan-scan` reads schema versions through node:sqlite.** Without the `sqlite3` CLI the .sh warned that the live DB was unavailable and never called an older-schema DB stale; the TypeScript gate reads both and reports it.
  - **`session-start-prescan` reads the DB through node:sqlite.** Without the `sqlite3` CLI the .sh stayed silent; the TypeScript gate prints the inventory.
