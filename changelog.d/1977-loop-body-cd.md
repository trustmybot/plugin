### Fixed
- **A write that comes before a `cd` in a loop body is now judged in the directory the next pass runs it in** (GH 1977): the containment guard read a loop body once, top to bottom, so in `while :; do echo > f; cd /etc; done` it saw only `./f` and allowed a write that the second pass puts in `/etc`. Both write-path analyzers (the TypeScript one and `cmd-analysis.sh`) now carry a body's `cd`, `pushd` and `popd` around the loop, nested loops included, and judge each statement in every directory a pass can leave it in, so that command reports `/etc/f` and is denied. After the loop, a later write is judged in the directory before the loop and in every directory the body can end in, even for a loop that may never run (`while false; do cd /etc; done; echo > f`). A `cd` the analyzer cannot name (`cd "$d"`, `cd -`, bare `cd`, `popd`) makes the earlier write unresolved, and the command is denied. So does a relative `cd` that keeps moving the directory on every pass (`cd sub`), or a write that could land in more than 8 directories: the analyzers stop tracking there, so even many such loops in a row or nested are judged quickly and denied rather than timing out. A `cd` inside a `( … )` subshell stays inside it, and a loop with no directory change is judged as before. The same change clears the shellcheck hook lint failure (GH 2018).
