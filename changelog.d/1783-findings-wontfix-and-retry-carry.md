### Fixed
- **Review findings the Human accepts can be closed, and a retry keeps the open ones** (GH 1783): the findings ledger (GH 1737) had no way to record a finding the Human accepts, so it blocked the close gate forever, and `task_retry` started the new task with an empty ledger, dropping every open finding. `task_reopen` now takes an optional `wontfix: [{finding_id, reason}]`: each named open finding of the task becomes `wontfix`, gets a `review_finding_wontfix` audit row with the reason, and is no longer probed or shown in `task_brief.open_findings`; the call is refused whole when the caller is not bro, a finding is not an open finding of the task, a reason is under 10 characters or an id repeats. The result lists the ids in `wontfixed`. `task_retry` copies the failed task's open findings onto the new task as `F<new_task_id>-<n>` (attempt 0, so the retry's own reviews never replace them), records a `review_findings_carried` audit row and returns `carried_findings`. `validation_record` now declares `findings[].criterion_id` as string or null, matching what it already accepted.
