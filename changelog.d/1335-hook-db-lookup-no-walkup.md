### Security
- **Test runs can no longer reach the project's trajectory DB through a hook** (GH 1335): with `CLAUDE_PROJECT_DIR` unset, the hook DB resolver (`tmb_db_path` in `scripts/hooks/lib/query-task.sh`) walked up from the current directory, so L3 hook tests run from a checkout inside the project probed the live `.claude/tmb/trajectory.db`. Under `TMB_FORBID_LIVE_SYNC=1` or a set `TMB_TEST_RUN_ID` the resolver never walks: with neither `TRAJECTORY_DB_PATH` nor `CLAUDE_PROJECT_DIR` set the DB is unresolved and one stderr line names the flag. `scripts/scan.sh` uses the same rule (its exit 2 now also accepts `CLAUDE_PROJECT_DIR`) and, under either flag, never spawns the live `claude plugin list`. Every L3 hook test pins `CLAUDE_PROJECT_DIR` or `TRAJECTORY_DB_PATH` to its fixture, enforced by the new L1 lint `hook-tests-pin-project.sh` (with `--self-test`); the L3 hook and MCP runners put a `sqlite3` shim first on `PATH` that refuses and logs any argument under the real project's `.claude/tmb/` and fail the run on any refusal; `no-unpinned-scan-in-tests.sh` now requires an actual `pinScanEnv(` call or a `TRAJECTORY_DB_PATH` assignment outside comments, not a mention.
