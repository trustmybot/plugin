### Fixed
- **A python write function held in a variable or imported under another name is now denied** (GH 1687): an inline python program that stored a module-qualified writer as a value and called it later (`f = io.open`, `o = os.open`, `m = shutil.move`, `m = shutil.copy`, `import shutil as s; m = s.move`, `from shutil import move as mv; m = mv`, `from shutil import *; m = move`, `m = shutil . move`, `m = getattr(shutil, 'move')`, `[os.remove]`, `m = __import__('shutil').move`, `s = __import__('shutil'); m = s.move`) slipped past the containment guard, since only a held bare `open` was caught. Each is now denied as an aliased or stored write builtin, like `o = open`. Only a callable on an imported `os`, `io`, `shutil`, `pathlib.Path` or `zipfile` counts, so reading an attribute that shares a writer's name (`row.open`, `args.rm`, `df.open.mean()`) is still allowed. A writer called directly through an import alias (`import shutil as s; s.move('a', '/etc/x')`, `from os import remove; remove(p)`, `__import__('shutil').move('a', '/etc/x')`) is now judged on its path arguments, so a target outside the project is denied and one inside it is allowed; direct calls such as `shutil.move('a.txt', 'b.txt')` inside the worktree behave as before.
