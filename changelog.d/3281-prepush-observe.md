### Added
- **TMB's pre-push hook is installed, in observe mode** (GH 3281): at session start, on git 2.54 or newer, TMB adds a config-defined `pre-push` hook (`hook.tmb.*` in the repo's own config, script under `.git/tmb/`) to the project's repo and every registered repo, next to any hook you already run such as husky's, and marks the agent's shell. On each agent push the hook records what its net-diff judge would decide next to what the existing push guard decided, as one `prepush_observed` audit row; it never blocks a push, and a push from your own terminal skips it. Remove it from a repo with `cli.js prepush-uninstall [--repo <path>]`, or skip the install with `TMB_DISABLE_PREPUSH_INSTALL=1`.
- **An agent can't skip TMB's pre-push hook** (GH 3281): a new Bash guard denies an agent command that passes `--no-verify` to `git push`, sets a `hook.*` key through `-c`, `--config-env`, `GIT_CONFIG_*` or `git config`, sets `extensions.worktreeConfig`, writes or chmods `.git/tmb/` or the repo's git config file, or strips `TMB_AGENT_SHELL`. Where such a git argument comes from a variable or a `$( )` (`git push "$BR"`, `git config "$KEY" …`), the guard cannot tell what will run and denies it; write the argument literally. A `git config` read with a variable stays allowed when a literal `get`, `list`, `--get`, `--get-all`, `--get-regexp`, `-l` or `--list` makes it one, only literal, fully spelled options come before that word (a value option such as `-f`, `--file` or `--type` may take a double-quoted variable as its next word), and every expansion after it is double-quoted and is not `"$@"` or `"$*"` (`git config --get "$KEY"`, `git config -f "$F" --list`, `git config --list --file "$F"`). Abbreviated `git config` options such as `--com` are denied too. Each deny says the hook only observes in this release. Your own terminal is never gated.
- **An exempt repo stands the hook guard down** (GH 3281): in a repo whose stored mode is `exempt`, the installer adds no pre-push hook, the hook-skip guard admits, and the pre-push judge admits. It goes by the repo the command acts on, so `git -C <exempt>` from another repo stands down too. A DB that does not read keeps the denies on.
