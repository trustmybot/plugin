### Fixed
- **Squash-merged branches no longer show up as unmerged work, and post-merge cleanup now removes them** (GH 1674): `world_model_get` listed every squash-merged branch whose local ref was still around under `unmerged_work`, and the post-merge cleanup hook never deleted those branches, because both only checked whether the branch tip was an ancestor of the target. That is never true after a squash merge. Both now count a branch as merged when its tip is an ancestor of the target, when merging it into the target would change nothing, or when every one of its commits already has a matching patch in the target. The cleanup hook deletes such a branch with `git branch -D`, then runs a background `git fetch --prune`. It still never touches protected branches or worktrees with uncommitted changes. A branch with work the target doesn't have is still listed and kept.
