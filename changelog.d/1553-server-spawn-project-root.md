### Fixed
- **Server tools act on the project, not the folder Claude Code was launched from** (GH 1553): the trajectory server ran its scripts and CLIs in whatever directory the session started in, so in a nested or worktree session `cheatcode_install` could write the wrong project's `.claude/settings.json`. Each child process now runs in the project root found from the trajectory DB, with `TMB_PROJECT_ROOT` set; the cheatcode scripts look for their fixtures there and stop with a clear error when it is unset. `scan_run` with no `session_dir` scans the project root and passes the server's DB to `scan.sh`. `issue_snapshot_md` writes under `<project>/docs/trustmybot`, and relative paths in the containment checks resolve against the project root. The issue-sync backend probe runs in the issue's repo. `pr_monitor_comments_get` returns an error naming the repo when it can't resolve a GitHub/GitLab slug, instead of running `gh`/`glab` against the session folder. The post-close rescan and SessionStart prescan scripts take the project root from their argument or `CLAUDE_PROJECT_DIR`.
