### Fixed
- **Dashboard issue labels take their colors from the project's own label taxonomy** (GH 2600): label colors were tied to the built-in names (`Bug`, `Feature`, `Improvement`, `Docs`, `Priority: Urgent`, `Priority: High` and an `Area:` prefix), so a project with its own labels such as `kind/bug` or `prio/p1` saw them all gray. A label is now colored by its role and position in the effective taxonomy: the `issue_classification_labels` and `issue_priority_labels` config (else the issues tool's generic defaults) and `issue_area_labels`. With the generic defaults the colors are unchanged; an `Area:` label is colored only when it is listed in `issue_area_labels`. `/api/issues` now returns `{ issues, label_taxonomy }` instead of a bare array.
