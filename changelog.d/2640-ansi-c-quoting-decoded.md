### Fixed
- **Command guards decode `$'…'` words as bash does** (GH 2640): the analyzer only dropped the backslashes in ANSI-C quoting, so `git $'\x70ush' origin dev` read as `git x70ush` and passed git-push-guard. It now decodes every bash escape (`\n`, `\t`, `\\`, octal, `\x`, `\u`, `\U`, `\c`, …) first. An escape whose result is unknown (a NUL, a missing hex digit, a value above 0x7F, which bash writes as a raw byte or in the locale's encoding) or a control character other than tab and newline reads as computed text, so git-push-guard denies it as an unknown subcommand and the write-path check reports it unresolved.
