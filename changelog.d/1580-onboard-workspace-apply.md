### Fixed
- **`/onboard` keeps each repo's branching answers when it finishes** (GH 1580): the final workspace-level `onboard_apply` no longer requires `branching_model` on a remote project and no longer overwrites the branching model, PR target and protected branches each repo got in Round 2; it only seeds repos that have none yet (GitHub Flow and the repo's real default branch, or the values you pass). On a remote project `remote` may be omitted or empty: each repo's GitHub/GitLab remotes are read from its own git tree, and when no repo has one the apply succeeds with a warning instead of failing. The per-repo branching and PR target questions now run for local projects too, and a repo with a stored branching model but no PR target no longer offers to keep a PR target that does not exist.
