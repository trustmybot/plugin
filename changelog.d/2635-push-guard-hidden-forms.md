### Fixed
- **The push gate sees pushes the command hides** (GH 2635): `>out git push origin dev`, `2>&1 git push …`, `< /dev/null git push …`, `builtin eval 'git push …'`, `builtin command git push …` and `env -C . git push …` read as no git command, a `$( )` or backtick in a heredoc body (`cat <<EOF` or `<<-EOF`) went unread, and code a command keeps for later (`trap 'git push …' EXIT`, `alias p='git push …'`, `mapfile -C`, `readarray -C`, `compgen -C`, `complete -C`, and a `PS4` holding `$( )` or a backtick that `set -x` expands) was never looked at, so a push from `.claude/worktrees/` went through. The gate now reads all of these; a push in code that runs later is denied because the gate cannot tell which checkout it runs in. When a command names `push`, a `bash -c` string or `eval` argument built from an expansion (`bash -c "$(…)"`, `eval "$X push"`), a shell reading its code from stdin (`… | sh`, `bash <<<…`), a command word that is an expansion (`G=git; $G push`), a `PS4` the gate cannot read (`env PS4=… bash -x`, `PS4=$X`, `${PS4:=…}`, `printf -v PS4 …`, `read PS4`, anything but a literal `PS4=` assignment), or a variable name a builtin takes from an expansion (`declare "$X=…"`, `printf -v "$X"`, `read "$X"`), is denied as code the gate cannot read. `>out git status`, `trap 'rm -f t' EXIT`, `PS4='+ '; set -x; git status`, `bash -c 'git status'`, a heredoc with a quoted delimiter and `cat <<EOF` around `$(git status)` still pass.
