### Added
- **Task setup refuses a verification[] that names a test file that isn't there** (GH 2581): `task_provision`, `task_retry`, `task_reopen` and `task_update_spec` now check every test file a `verification[]` command hands a test runner (`*.test.*`, `*.spec.*`, `*.suite.ts`, `test_*.py` passed to `node`, `bun test`, vitest, jest, mocha or pytest, also inside `bash -c` and after a `cd`; a built `dist/**/*.js` one through its `src/**/*.ts` source). Words a command only greps for, tests for absence or passes to git are left alone. A path counts only when git shows it at the base (provision, retry) or the task branch tip (reopen, update_spec), or when `files[]` lists it because the task creates it. Anything else, or a git error, is refused with `verification_path_missing` (or `verification_path_unverified`) naming each path and the ref, and nothing is written, so a typo shows up at setup instead of at the close gate. Each of the four tools also returns `suggested_verification`: up to 20 existing tests that import a `files[]` module, read from the world model. They are suggestions only and are never added on their own.
