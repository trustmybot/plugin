### Fixed
- **`W=<path>; git -C $W …` keeps its directory when the git command carries a redirect** (GH 2404): adding `2>&1`, `2>/dev/null`, `>out.log` or `&>/dev/null` to a `git -C $W` command made git-guards and git-push-guard forget the path `W` was set to in the same command, so in a repo with linked worktrees they denied it with `ambiguous_git_target` ("comes through a variable"). A redirect to a plain word or an fd duplication cannot reassign the variable, so the guards now judge the command on that directory. A redirect target that can run code or reassign (`>$(…)`, `2>$((…))`, `>"$W"/log`) still fails closed.
