### Security
- **The TypeScript write-path analyzer fails closed where the bash one misses a write** (GH 1692): `mcp/trajectory-server/src/hooks/cmd-analysis/` now prints `UNRESOLVED:$(computed):<program or text>` (at most 80 characters) in these cases:
  - a program piped or redirected into an interpreter (`curl … | bash`, `python3 < x.py`). An info option such as `--version` exempts it only among the interpreter's own options, so `curl … | python3 - --version 1.8.0` and `… | sh -s -- -n` still fail closed. `perl -c` runs `BEGIN` blocks, so `cat x.pl | perl -c` fails closed too; `ruby -c` stays exempt;
  - a program held in a variable or in substitutions nested to any depth (`python3 -c "$PROG"`, `node -e "$(cat $(dirname $(which x))/b.js)"`), including one with a quoted paren inside (`python3 -c "$(cat ')')"`) and two substitutions with a blank between them (`python3 -c "$(cat a) $(cat b)"`);
  - a write call whose target is computed: string concatenation, f-strings, `%` / `.format`, `os.path.join` / `path.join` with a non-literal part, a variable, a loop over `os.listdir` / `glob` / `readdirSync`, or `sys.argv` / `process.argv` with no operand. The line is printed beside any literal paths the program also names, so `os.rename('a', b)` gives `/w/a` and the computed line. A python or node target name bound exactly once, first, at top level, to one plain string literal resolves to that literal, so `p='src/a.ts'; open(p,'w')` gives only `/w/src/a.ts`. In python, `Path('…')`, `pathlib.Path('…')` and `PurePath('…')` of one literal resolve the same way, so `p = Path('src/a.ts'); p.write_text('x')` gives only `/w/src/a.ts`. A name that is rebound, augmented, bound in a loop, a branch or a `with` / `for` header, bound to anything else, or never bound still fails closed, and so does every name after a python `from m import *`;
  - a program given operands (`python3 -c … foo`, `python3 - foo <<'EOF'`) whose write target is not a `sys.argv[n]` / `process.argv[n]` that an operand covers, such as `os.environ['T']`, or perl's `$ARGV[0]` and ruby's `ARGV[0]`, which the scanner does not read as argv. The operands print beside the computed line;
  - a shell body that `find -exec` / `fd -x` / `xargs` run on `"$0"`, `"$@"` or `for f;`;
  - `bash -c` / `eval` / heredoc programs nested deeper than 3 levels.
- **The analyzer also catches more writes:**
  - it judges a `bash -c` statement's own redirects and write commands before its body, so `bash -c 'ls' > /etc/out` reports `/etc/out`;
  - it looks through `timeout`, `stdbuf`, `nice` and `watch`, and through the Homebrew names `gtimeout`, `gstdbuf` and `gnice`, so `timeout 10 find . -delete` reports what `find` deletes;
  - a stdin program's operands resolve its `sys.argv[n]` / `process.argv[n]` targets, so `python3 - out.txt <<'EOF'` with a `sys.argv[1]` target reports `out.txt`. `process.argv[1]` under `node -` is `-`, so it still fails closed;
  - a process call's shell command (`subprocess.run(['bash','-c', …])`, `os.system`, `execSync`) that does not parse, or that fails closed, keeps its `UNRESOLVED:$(parse):` or `UNRESOLVED:$(computed):` line. Before, the TS stripped the prefix and judged the leftover text as a path, so a command that began with an in-root path was allowed.
- **Read-only programs still print nothing.** This includes `node --test`, `node --run`, `node --watch`, `python3 -mpytest` and `open(p, 'r')`.
- **This is a TS-only change.** `cmd-analysis.sh` is unchanged and still misses these shapes. Each of the 207 new cases either matches the bash output or is recorded in `tests/fixtures/cmd-analysis/divergences.jsonl` with the reason the TS is stricter. The corpus now holds 1605 commands, 225 of them recorded divergences.
