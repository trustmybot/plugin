### Added
- **The `/onboard` sandbox now allow-lists the hosts TMB's remote commands need** (GH 1252): answering **yes** to `sandbox_enforcement` also merges `sandbox.network.allowedDomains` (`github.com`, `api.github.com`, `*.githubusercontent.com`, `registry.npmjs.org` and the host of each HTTPS remote) into the project's `.claude/settings.local.json`, keeping every domain and `excludedCommands` entry you had, and never adding `excludedCommands`; **no** removes exactly the domains TMB added (`sandbox_settings.allowed_domains`). A new headless probe, `tests/l5-l6/probes/sandbox-network-probe.sh`, measures `gh`, `git ls-remote`, `git push --dry-run`, `npm view` and `bun add` with and without the allow-list. On Claude Code 2.1.303 the allow-list makes git over HTTPS work, but `gh` (TLS trust), `npm` (its `~/.npm` cache) and `bun add` (its temp dir) still fail inside the sandbox, so the default stays **no**. A fresh onboard recommends **yes** only once the probe passes every command and no remote is SSH, since git over SSH bypasses the sandbox proxy; a re-onboard defaults to keeping your stored answer. The table is in `docs/architecture/CONTAINMENT.md`.
