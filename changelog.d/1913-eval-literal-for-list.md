### Fixed
- **An eval over literal values is judged as the commands it runs** (GH 1913): the containment guard denied `for c in "bash a.sh" "bash b.sh"; do eval $c; done` and `c='ls -la'; eval "$c"` as unproven, though every value was a literal in the same command. When each variable an `eval` fills in holds only literals from a `for` list or a plain assignment, the guard now judges each expanded command (up to 16 combinations) as if typed directly, so read-only ones pass and writes are judged as writes. Any other `eval` of filled-in text is still denied, and the deny now suggests running each command directly instead of through eval.
