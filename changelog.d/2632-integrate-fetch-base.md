### Fixed
- **`cli.js integrate` rebases onto the remote base, and same-file renames no longer stop it** (GH 2632, GH 2356): when the local `dev` was behind `origin/dev`, `integrate <task> dev` compared against the stale local ref and reported nothing to rebase. integrate now fetches the base first: a local branch that tracks a remote resolves to its fetched upstream (`dev` → `origin/dev`), and an `origin/<x>` base fetches `<x>`. When the fetch fails (for example offline), integrate prints a warning and uses the local ref. The rebase also runs with rename detection off (`-c merge.renames=false`), so two sides renaming the same generated file differently no longer stop it on a rename/rename conflict; the patch-id check still judges the result.
