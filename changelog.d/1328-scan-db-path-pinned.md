### Security
- **Test runs can no longer reach the project's trajectory DB through `scan.sh`** (GH 1328): with `TRAJECTORY_DB_PATH` unset, `scripts/scan.sh` found its DB by walking up from the current directory, so unit tests forking it from a checkout inside the project opened the live `.claude/tmb/trajectory.db` (the Codex `project_scan` test also ran the real `claude plugin list` and wrote into it) and, with the real HOME, could record `~/.claude.json` MCP servers into it. Under `TMB_FORBID_LIVE_SYNC=1` or a set `TMB_TEST_RUN_ID`, scan.sh now exits 2 unless `TRAJECTORY_DB_PATH` names an existing file, and reads MCP servers from the `TMB_SCAN_MCP_JSON` fixture (an `mcpServers` object) instead of `~/.claude.json`; its JSON gains `mcp_inventory: {status, note}` (`home`, `fixture`, `unavailable` or `skipped`), which `scan_run` returns and, when unavailable, appends to the `deep_scan_completed` summary. Every scan-forking unit test pins its DB and the MCP fixture through `pinScanEnv` in `src/test/helpers.ts`; the L1 lint `no-unpinned-scan-in-tests.sh` (with `--self-test`) fails a test file that references `scan.sh`, `scan_run` or `project_scan` without the pin; the warn contract `no_fixture_rows_in_inventory` reports fixture-named plugin/MCP rows already in a DB, read-only.
