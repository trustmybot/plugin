### Fixed
- **`task_provision` accepts more input shapes the first time** (GH 1855): a base given as `origin/dev` now resolves the same as `dev` (it used to look up `origin/origin/dev` and refuse), in task_provision, task_retry and task_reopen alike; a local branch literally named `origin/<x>` still resolves as that branch. When `task.repo` is omitted the task goes to the issue's repo before the sole-repo fallback, so multi-repo workspaces no longer refuse it. The input schema now says `task.description` and `task.spec_body` are required and non-empty, so fewer calls are refused and retried.
