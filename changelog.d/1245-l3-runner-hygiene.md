### Fixed
- **Test runs name the failing file, deny on every failing verification, and stay inside `$TMPDIR` and an isolated HOME** (GH 1245, GH 1248, GH 1286): `tests/l3-integration/hooks/run.sh` ended with a bare failure count and `swe-verification-gate.sh` forwarded only the last 20 lines of a failing verification command, so an intermittent single-file failure could not be identified. The hooks runner now ends with every failing test file and its last 10 lines plus a `FAIL files:` line, `mcp/run.sh` does the same from node's failing-tests report, `-v` prints each file's duration, and the files measured at 30 s or more (`git-guards`, `swe-boundary`, `git-push-guard`, `roundtable-slash-detect`) get a 240 s timeout instead of 120 s. The gate's deny lists the output lines matching `FAIL|failed|Error|❌` (max 15) before the tail, and denies the same way when it verifies without its run lock (locks dir unavailable), whether the output has no matching line or thousands. Tests that relied on the runner unsetting `CLAUDE_PROJECT_DIR` (`swe-boundary`, `consultant-spawn-enforcement`, `roundtable-slash-detect`) pin it per fixture, and `hook-content-preservation` runs its hooks from a fixture project and masks path tokens, so its goldens no longer depend on the checkout. Both L3 runners point `TMPDIR` at a fresh dir under their throwaway HOME and fail when a test leaves a file in it or when `/tmp` gains an entry named with the run's id (`TMB_TEST_RUN_ID`, `tests/lib/tmp-footprint.sh`); other new `tmb*`/`claude*` entries, which can belong to a concurrent session, only print a warning, and Claude Code's `claude-*-cwd` and `claude-<uid>` are not counted (the L3 MCP harness gives each server its own `TMPDIR` and removes it on close). New L1 lint `no-tmp-writes.sh` fails on a write to a hard-coded `/tmp`, `/private/tmp` or `/var/tmp` path in `scripts/`, `skills/`, `agents/`, `commands/` or `mcp/trajectory-server/src/` (allowlist `no-tmp-writes.allowlist`; `--self-test` also fails when the L1 loop writes under an isolated HOME). `tests/run-all.sh` runs L1, L2 and L4 behind a `claude` stub and `gh`/`glab` stubs that record every call, a recorded call failing the step, so no step reaches the real `claude` or a forge CLI: L1 with `TMB_L1_OFFLINE=1` (which `labels-stable.sh` honours by skipping its live `gh` query), L2 and L4 with `TMB_FORBID_LIVE_SYNC=1`, so the server skips its `gh`/`glab auth status` probes. The L2 unit suite runs once, stubbed (the duplicate unstubbed run, which reached the real `claude` and its `~/.claude.json`, is gone); a failing L4 flow fails the run, and flow-02 closes its issue with `waive_review: true` and asserts the one bro-written `review_gate_waived` row the review gate on `issue_close` requires. bun's install and transpiler caches and mise's state and cache go to a run-scoped temp dir, and a run started with an empty HOME (`HOME=$(mktemp -d) bash tests/run-all.sh`) fails unless that HOME ends holding nothing but `.cache/huggingface`. `tests/README.md` names where `run-l6-chain.sh` writes its runs (`$L6C_RUNS_DIR`, default `~/.claude/tmb/l6-chain-runs`).
